## §7.1 实现形态：抽纯函数，而不是「在原地改 f-string」

判据 **P2** 要求「喂 `n_independent_pred_dates = 7` 的夹具，产物里的日数**随之变成 7**」。
⇒ 这要求那段散文**本身**是一个**可注入的纯函数**：

```python
def _cannot_prove_lines(kind: str, n_dates: int, n_rows: int) -> list[str]:
    …                                     # 返回那三句
```

调用点 `payload["what_this_cannot_prove"] = _cannot_prove_lines(
kind, primary["n_independent_pred_dates"], primary["n_rows_total"])`。

⚠️ **为什么必须抽函数，不能只把字面量改成 f-string**：
守卫若无法独立调用那段文案，P2 就退化成 P1（静态相等），
而 **P1 在修好之后恒真**（§3 已预注册这一点）。
⇒ 抽函数是 P2 可表达的**前提**，不是风格选择。

⚠️ K1/K2 各杀**两条**不是连坐 —— 那两条**真的都在守同一个槽位**。

**修正一：对照臂原本是个弱筛子。**
K4 造出来之后才发现它**杀不掉** `changes`：`.mut` 只能改一行，
而那一行还留着 `{n_dates}` ⇒ `7 日` vs `9 日` 仍不同 ⇒ `a != b` 仍成立。
⇒ 根因是 `assert a != b` 只要求「整体变了」，
而 K2 证明「整体变了但**一半槽位已死**」也能满足它。
⇒ 已改成**逐槽位**比对（`every_measured_slot`），
它被 K1/K2 各杀一次 ⇒ 现在**有**自己的变异证据。
（第 112 层：弱筛子与恒真一样有害 —— 它会让人以为对照臂在工作。）

**修正二（未覆盖，如实登记）：`P1`（`not_a_hardcoded_literal`）至今没被红过。**
`.mut` 的单行锚点**造不出**能让它变红的变异体 ——
把整个 payload 项改成字面量列表需要**跨行**改写，
而多行锚点会因 `dedent` 错位（第 171 层）。
⚠️ 它**不是**完全没有作用：`P4` 的 `assert calls` 蕴含了它
（若该项变回字面量列表，就不存在调用，`P4` 先红），
但「蕴含」不等于「验证过」⇒ **本节不把 P1 记成有判别力的守卫**。
