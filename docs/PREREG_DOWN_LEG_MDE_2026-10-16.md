- 第 160 层：把「测不到」写成**没有**（乐观 ⇒ 误导人放弃唯一能解锁的路）
- 本层：把「测不出」写成**兑现了**（同样乐观 ⇒ 误导人以为产品承诺已被验证）

🚨 **两者方向相同（都是乐观），但载体不同**：一个写在 `CLAUDE.md` 里，
一个写在**每次判决都返回的 `note` 字符串**里。
后者更危险 —— 它跟着每个 HTTP 响应发出去。

**附带一个已定位但本轮不改的洞**：`aplus/verify.py::rolling_stats`
在 `history` 为空或缺 `direction` 列时回落到 `zero = {…全部 0.0…}`，
而 `live_down_leg` 的入选条件 `isinstance(..., (int, float))` 对 `0.0` **为真**
⇒ 「没测过」会被读成「测到了 0」。
⚠️ 该路在赛马路径上**不可达**（`aplus/backtest.py::RESULT_COLUMNS` 含 `direction`
⇒ `evaluate_weights` 的结果恒有该列）⇒ **潜伏，不是活 bug**。
修法须与本文件一起预注册（候选：`zero` 用 `None`，或消费侧加 `judged > 0`）。
**本轮不改**，理由：生成器字节在赛马跑完前冻结（第 125 层）。

## §2 判决改成三态（**对称，不偏向任何一侧**）

设 `c = avg_down_return`（日均绝对收益，跌腿**不扣成本**），
`M = MDE`（§4）。

| 态 | 条件 | 允许的陈述 | 禁止的陈述 |
|---|---|---|---|
| `DOWN_LEG_NEGATIVE_MEASURED` | `c + M < 0` | 「这篮子确实会跌，超出测量下限」 | 任何关于**幅度**的陈述 |
| `DOWN_LEG_NOT_MEASURED` | `|c| ≤ M` | 「**测不出**，不等于跌也不等于不跌」 | 「兑现了」/「未兑现」 |
| `DOWN_LEG_NOT_NEGATIVE` | `c − M > 0` | 「这篮子确实在涨，承诺未兑现」 | — |

⚠️ **中间态必须存在且必须能在真实产物上可达。**
若某次改动让 `|c| ≤ M` 永不可达（等价于门槛被挪到极端），
中间态就是**死代码** ⇒ 前端会滑向两端之一（`[[120]]`）。

**不设四态**：不区分「测不出是因为 sd 大」与「测不出是因为 n 小」——
那两个量在同一个 MDE 里已经合成为一句话，而它们导向**同一个动作**
（加样本 / 压波动），拆开只会多一个**没人读**的字段。

## §3 分母用哪个 `n`（**这是本节最贵的一处**）

跌腿的 `actual_pct` 是**逐条预测**的持有期收益。
多条预测**共用同一段行情**（`rolling_stats` 自己也写着
`n_up`/`n_down` 是**条目数**，并另给 `n_independent_windows` 作为
「独立成交窗口数」）。

| 候选 | 含义 | 后果 |
|---|---|---|
| `n_predictions` | 条目数 | ❌ **MDE 被低估 √(倍数)** ⇒ 测不出被读成测得出 |
| `n_independent_windows` | 独立成交窗口数 | ✅ 诚实的分母 |

⇒ **判决一律用 `n_independent_windows`。**
⚠️ 它是**全表**的独立窗口数，而跌腿预测只落在其中一部分窗口上 ⇒
**严格讲它偏大 ⇒ MDE 偏保守**。这是**可接受的方向**
（测不出被判成测不出，而不是反过来），但必须在 `note` 里写明
「分母是全表窗口数，对跌腿偏保守」——不许让它读成精确。

⇒ 若要精确到「含至少一条跌腿预测的窗口数」，需在 `rolling_stats` 里
新增一个字段 ⇒ **那是另一项改动，本文件不预注册它**（§6）。

## §4 MDE 公式与外部锚（**不查表，全部外部**）

> 🚨 **2026-10-16 修正（本文件写下后、看到本轮数据前）**：
> 原式把**逐条** sd 与**窗口**数配对，**分子分母不同观测单位**。
> 详见下面「⚠️ 口径同源」一节。

```
# ① 先把逐条预测聚合成「每个成交窗口一个数」
daily_down[窗口] = mean(该窗口内跌腿 actual_pct)      # 与 avg_down 同一口径
n   = len(daily_down)                                  # §3 那个量
c   = mean(daily_down)                                 # ⚠️ 须与 avg_down 逐位一致（见下）
sd  = std(daily_down, ddof=1)
se  = sd / sqrt(n)
M   = t_power × se
```

### ⚠️ 口径同源：为什么不能拿**逐条** `actual_pct` 的 sd

`rolling_stats` 现在报的 `avg_down` 是**逐条** `down["actual_pct"].mean()`
（分母 `n_down` = **条目数**）。而 §3 定的 `n` 是 `n_independent_windows`
（**成交窗口数**）。

**同一天点名的 10 只跌腿高度共动**（它们来自同一次排序、同一个行情段）
⇒ 逐条 sd 被篮子内共动撑大，而分母被压缩到窗口数
⇒ `M = t_power × sd_逐条 / √n_窗口` **系统性高估**。

🚨 高估 MDE 的方向是「更多落入 `NOT_MEASURED`」＝**保守**，
但它仍然是错的：它会把**本该判「确实在涨」**的情形吞进中间态
⇒ §2 明写「中间态必须可达**且有意义**」，而系统性高估让它的边界失真。

⇒ **判据：`c` 与 `sd` 与 `n` 三者必须落在同一个观测单位上。**
⇒ **守卫 G8**（新增，见 §5）：喂两组「条目数相同但窗口数不同」的夹具
⇒ 逐条 sd 的实现**必须给出相同的 MDE**（它对窗口数失明），
而窗口聚合的实现**必须给出不同的 MDE**。
⚠️ 这条守卫的判别力**只来自「两种构造成员不同、条目数相同」**；
若两组用同一批条目重排，它会恒绿（`[[164]]` 的累加器同族：**对称的探针测不出缺陷**）。

### ⚠️ `c` 必须与 `avg_down` 逐位一致（**不许重算均值**）

`c` 取 **`avg_down`（产物里已有的那个数）**，不另算一遍 `mean(daily_down)`。
理由：若另算，两者在「某窗口无有效条目」时可能不同步
⇒ **判决的 `c` 与产品页展示的 `avg_down` 会分叉**。
⇒ 守卫 G9：`c` 必须**逐位等于** `test_stats.avg_down_return`
（若因聚合口径差异而不相等，**必须报错**，不许各自为准）。

| 常数 | 值 | 出处（**外部**，不来自本仓实现） |
|---|---|---|
| `t_power` | **2.80** | `1.96 + 0.84`：5% 双尾临界 + 正态分布两者之间的面积（80% 检出力） |
| `t_crit` | **1.96** | 5% 双尾。与 `scripts/factor_attribution.py::power_floor` 同一组，`T_CRIT_5PCT` / `T_POWER_TARGET` |
| 年化因子 | **不年化** | 本判决报**日均**；真要年化则**均值 ×T、sd ×√T、SE ×T**（`[[93]]`，三者乘数不同） |
| 交易日/年 | **244** | `aplus.hurdle` 是唯一真相源（仓内另有 250 / 252，**不是同一个量**，`[[177]]`） |

⇒ **单一真相源**：MDE 原语从 `scripts/factor_attribution.py::power_floor`
**提取**到 `aplus/`（与 `CALIBER_PCT_SCALE` / `required_excess()` 同一手法）。
🚨 **不许在 `champion_health.py` 里重写一遍**（两份副本之间没有守卫 = `[[182]]`）。
