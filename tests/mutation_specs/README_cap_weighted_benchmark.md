## 为什么先钉这三条

`decide()` 是**预注册判决函数**：三个分支在跑数据之前就写死了，
而报告里引用的是这三个字符串。⇒ 它一旦被改，**是结论层面的改动**，
而本仓的教训是「守卫全绿」与「判决已经翻面」可以同时成立。

⚠️ 本文件用 `.mut` 平台（`scripts/mutation_harness.py`），**只改源码、不改产物**，
与 `scripts/mutation_check.py` 里那套内建变异体是两套独立机制，互为交叉验证。

## 三条各钉一个东西

| 变异 | 钉住的东西 |
|---|---|
| C1 | 「压根没算出数」必须**拒绝判决**，不许滑进某一支 |
| C2 | 分支边界 `≤ 0` 里的**等号**（毛超额恰好为 0 时该落在哪一支） |
| C3 | 边界 `t ≥ t_crit` 里的**等号**（t 恰好等于临界值时算不算显著） |

C2 / C3 是**预注册文本的逐字落地**：那两条 `≤ 0` 与 `≥ t_crit`
是 `docs/TODO_cap_weighted_benchmark_2026-10-15.md` §2 表格里的原话，
改一个等号就是改判据。

C1 不在预注册三支之内 —— 它是 2026-10-15 **事后补**的第 0 支
（`CAP_UNMEASURABLE`），见 `docs/MISTAKE_LOG_2026-10-14.md` 第 120 层
「同型第二次」。补的方向是**朝不让自己通过**的：它把一类原本会出判决的入参
改成**拒绝判决**，所以它不会为了让报告好看而放松任何东西。
