> **状态**：🔴 **未修**（登记于发现当晚；当时晚间链在跑 ⇒ 不热改）
> **影响面**：D1 的**独立成交窗口计数（W）** ⇒ ⇒ **D1 验收的样本口径存疑**
> **判决标签没变**（仍是 `NOT_PASSED_POWERLESS` / `publish_allowed=false`）⇒ **不紧急，但必须查清**

## §1 现象

底稿 `data/reports/verification.parquet` 今天新增了 `signal_id` 列 ⇒
归属基准从 `weights_hash` 切到 `signal_id`
⇒ 作用域从 `{10-14, 10-15, 10-16}` 变成 `{10-10, 10-19}`
⇒ 样本从 **60 行 / 3 窗口**缩到 **40 行 / 2 窗口** ⇒ **W 由 3 变 2**。

⚠️ **但 10-10 那 20 行是可疑的**：

- 那 20 行是 **2026-10-21 20:16 重判**时进底稿的
  （原判 10-14，因缺 `exit_date` 被重开）；
- 重判时它们被打上了**当前**的 `signal_id = 0df5828c`；
- 而实测：**10-10 那份名单是按 2026-10-14 翻转前的旧权重排出来的**
  - ρ(落盘 score, 按**旧**权重重算的秩相关) = **+0.99**
  - ρ(落盘 score, 按**当前**权重重算的秩相关) = **−0.87**
  - 对照：10-19 才是当前权重（ρ = +0.59 / +0.91）

⇒ ⇒ **`signal_id` 是在重判时补上的标签，不是「这份名单由该信号产生」的证据**
⇒ ⇒ **新作用域里有一半样本（20/40 行）可能属于另一个信号**。

## §2 为什么这是「一个真缺陷」而不是「一条读数」

`signal_id` 存在的**全部意义**是「**这行的名单是用哪套信号排出来的**」
⇒ 它是**归属基准** ⇒ ⇒ **归属基准错了 ⇒ 独立窗口数就是错的**
⇒ ⇒ 而 W 是 D1 验收的**唯一门槛**（≥ 10）⇒ ⇒ ⇒ **它错了，门槛的达成进度就错了。**

⚠️ **但今晚不能据此翻任何判决**：
- 判决标签（`NOT_PASSED_POWERLESS` / `publish_allowed=false`）**未变**；
- W=2 与 W=3 **都远小于门槛 10** ⇒ 结论方向不变；
- ⇒ **正确的处置**：这批产物的引用**限定为「诊断读数」**，D1 验收以 W=2 的
  `NOT_PASSED_POWERLESS` 为准，**并把根因查清**。

### §5.1 一句话根因

**重判路径把「当前信号 id」当成了「这份名单由哪套信号排出来的」写进底稿，
而重判那批行来自一份 `save_predictions` 写 `signal_id` **之前**落盘的预测文件
⇒ 该文件根本没有这一列 ⇒ `verify_predictions` 用入参补上 ⇒
补上的值是**重判当天**的信号 id，不是**出单那天**的。**

⇒ 缺陷**不在** `save_predictions`（它写对了：10-21 那份文件里的 `0df5828c` 与
`current_signal_id()` 逐位相同），**在** `aplus/verify.py::verify_predictions` 的
`signal_id` **入参** + `scripts/run_daily.py` 重判路径的**调用方式**。

⇒ 附带的第二个根因（更靠前、且决定了第一个）：**重判不是「追加新行」，
是「覆盖旧行」**（`aplus/reports.py::append_verification` 的
`drop_duplicates(subset=["pred_date","code"], keep="last")`）
⇒ 所以「追加式纪律：既有行不许回填」在重判路径上**根本不成立** ——
它不是在旧行旁边加一行标签，它是**把旧行整行换掉**，换成了带标签的新行。

### §5.3 「那份名单是旧权重排出来的」—— 独立证据（不依赖 §5.2 的标签）

**证据一：权重翻转的 commit 时间 vs 名单落盘时间**（git 硬证据）

| 事实 | 值 | 出处 |
|---|---|---|
| 10-10 预测文件落盘 | **2026-10-10 19:31:04** | `stat` on `pred_2026-10-10.parquet` |
| 权重符号翻转 commit | **2026-10-14 13:19:59**（`d9b0dc9`） | `git show -s d9b0dc9` |
| 翻转**前**的 `DEFAULT_WEIGHTS` | `{mom20:+1.0, rev5:+0.3, vol20:+0.5, vsur:+0.5}` | `git show d9b0dc9^:aplus/factor.py:14` |
| 翻转**后**（= 当前） | `{mom20:-1.0, rev5:+0.3, vol20:-0.5, vsur:-0.5}` | `git show d9b0dc9:aplus/factor.py:54` |

⇒ 10-10 那份名单**只可能**是翻转前的权重排出来的（它在翻转前 4 天就落盘了）。

**证据二：涨腿 `mom20` 的极性**（**不依赖 `robust_z`、不依赖任何近似**）

`mom20` 的权重从 `+1.0` 翻成 `-1.0` ⇒ 「高动量」在涨榜里的地位从**加分**变成**减分**
⇒ 涨榜 top-10 的 `mom20` 极性必然随之翻转。实测（原始值，小数）：

| 预测日 | 涨腿 top-10 的 `mom20` | 极性 | 与哪套权重一致 |
|---|---|---|---|
| **2026-10-10** | `+9.0372, +8.3955, +7.4563, +8.3105, +2.7688, +0.2972, +1.4189, +1.6476, +0.0848, +1.2506` | **全正**（中位 **+2.2082 = +220.8%**） | **旧权重**（`mom20=+1.0`） |
| 2026-10-19 | `-0.4557, -0.3546, -0.3099, -0.2977, -0.4677, -0.438, -0.482, -0.4106, -0.3556, -0.3476` | **全负**（中位 −0.3831） | 当前权重（`mom20=-1.0`） |

### §5.5 为什么 `scope_ledger` 的四态判据没抓到它

`aplus/signal_scope.py` 的四态是**「有没有一份能对上的标签」**，**不是**「这份标签是不是真的」：

| 态 | 判据（`signal_scope.py:17-19`） | 标签写错时会怎样 |
|---|---|---|
| `OK` | 有 `signal_id` 列 **且** 至少一行等于当前 id | 🚨 **写错的标签照样进这一档**（实测：现状 `status=OK`） |
| `ATTRIBUTED_BY_WEIGHTS_HASH` | 无 `signal_id` 列、但有 `weights_hash` ⇒ 逐行判 | — |
| `NO_MATCHING_SIGNAL` | 有 `signal_id` 列、无一行等于当前 id | — |
| `MISSING_SIGNAL_ID_COLUMN` | 两列都没有 | — |

⇒ **四态判的是「证据在不在」，不是「证据真不真」** ⇒ 一个**被写错的**标签会得到
**最强的一档**（`OK`）⇒ `scope_ledger` 在这里**结构上不可能**抓到它。

实测（探针 `/tmp/aplus_resignal_probe/scope.py`）：

```
A. 现状（底稿真样）
  status=OK  basis=signal_id  usable=True
  rows_in_scope=40  pred_dates_in_scope=2  entry_dates_in_scope(W)=2
  ledger_total=180 rows_unattributed=140 rows_other_signals=0
  W (独立成交窗口) = 2

B. 反事实1：若重判**没有**盖标签（追加式纪律本来的样子）
  status=NO_MATCHING_SIGNAL  basis=signal_id  usable=False
  rows_in_scope=0  W=0

C. 反事实2：若 10-10 那 20 行带的是**它自己**的 id（da18a166 = 翻转前权重）
  status=OK  basis=signal_id  usable=True
  rows_in_scope=20  pred_dates_in_scope=1  W=1
  rows_unattributed=140  rows_other_signals=20
```

⇒ **W=2 里有一半（1 个独立成交窗口、20/40 行）来自另一个信号。**
⇒ 且**没有任何机制**会在这批行上标出「它们其实属于 `da18a166`」——
底稿里那一列**只有** `0df5828c` 一个取值（实测 §5.2-§7）。
