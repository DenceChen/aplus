## §1 要回答的问题

`portfolio_nav.json` 测的是**组合的净值**。它有一条 `测量假设` 写着
「**每天的名单全部执行**」，而**没有**任何一条提到**钱够不够**。

⇒ 本产物只回答一件事：**那个组合，在 ¥50,000 下能不能真的开出来。**

它**不重跑回测**、**不重算任何收益**（收益口径归 `portfolio_nav.json`）——
它只在既有组合上加一层**资金约束**。

## §2 口径（七条，逐字写死）

| # | 口径 | 出处 / 理由 |
|---|---|---|
| E1 | **本金 `CAPITAL = 50_000.0`** | 与 `lot_affordability.py:43` **同一个字面量** |
| E2 | **整手 `LOT = 100` 股** | 同上 `lot_affordability.py:44`；A 股最小买入单位 |
| E3 | **价格用不复权 `close`** | `lot_affordability.py` docstring 逐字：判「能不能买」必须用真实成交价；收益口径才用后复权 |
| E4 | **成交窗口的进场日**取 `entry_date`，**不是** `pred_date` | 实测周末出单时三者落到同一窗口（`run_daily.py:290-293` 逐字记载） |
| E5 | **每份金额** = `CAPITAL / 该窗口的成分行数`（**行数**，不是去重 code 数） | 与 `daily_portfolio_returns` 的 `by_day.mean()` **同一个分母**（`verify.py:390-393`）—— 否则两个量（第 7 层） |
| E6 | **取不到 `entry_date` 行情的票**不静默当成 0 元 ⇒ 计入 `price_missing` 并**从买得起判定中剔除、但计入分母** | 缺失 ≠ 买得起（第 153 层：查不到 ≠ 没有） |
| E7 | **禁止在产物里出现「达标 / 未达标 / 能做到」** | 这套判据下它是**不可判定的量**（第 124 层：判据不可问就等于没有守卫） |

### E5 的一个反直觉后果，必须写明

同一只票被两个 `pred_date` 选中时，它在**行**口径下拿**两份**金额、
**两份**整手 —— 而不是一份。因为「每天全仓执行」假设下，
两笔在同一天同一价成交（实测 `300019.SZ 硅宝科技`：两行 `actual_pct` 逐位相同）。

⚠️ 「29 行 vs 28 只去重」是**两个量**。产物**两个都报**，
不许只报一个（第 7 层）。

## §3 两种处置口径（**都算，都落盘**）

买不到 1 手之后，钱怎么办？两种**都说得通**且给出**不同组合、不同净值**：

| 口径 | 含义 | 实现 |
|---|---|---|
| **A `hold_cash`** | 仓位就是 0，钱闲置 | 每份金额**固定** = E5 的值；买不到的份额变成现金 |
| **B `reallocate`** | 钱分给买得起的那些 | 迭代：剔除买不够的 → 剩余等分 → 再检查，直到**不动点** |

⇒ **B 是不动点求解**：剔除一轮后每份金额上升，可能又买得起新的 ⇒ 重复直到无新增。
⇒ 必须**迭代到收敛**并把**轮数**落盘，否则读者无法判断它是否真的收敛过。

⚠️ **A 与 B 不可比较**：它们是**不同的组合**，不是同一组合的两种估计。
产物必须**并排**，且各自带自己的成分数与投入率。

## §4 判决规则（五条）

- **X1**：每个成交窗口必须给出 `名义行数` / `去重code数` / `实际投入` /
  `闲置现金` / `投入率` 五个字段，**一个都不许省**。
- **X2**：**闲置现金比例必须落盘**——它是可执行性的**核心量**。
  「组合能开出来」和「组合值得开出来」是两个问题（后者要靠闲置率说话）。
- **X3**：`verdict_about_exec` **只允许**三种措辞：
  `可开（闲置 < 20%）` / `部分开不出（闲置 ≥ 20%）` / `判不出（无行情）`。
  阈值 `IDLE_CASH_LIMIT = 0.20` 在**看任何数字之前**定死。
- **X4**：**不许**把 `portfolio_nav.json` 的 `verdict_about_20pct` 复制过来当结论
  —— 两个产物回答**两个问题**（净值 vs 能不能开），混起来是第 7 层。
- **X5**：产物必须带 provenance 章，`extra` 里必须有
  `source_parquet_sha256`（**当前字节** sha256，不是 mtime）。

⚠️ **X3 的阈值是我拍的，不是推出来的**：20% 对应「闲置 2 万还能接受」。
拍阈值这件事必须写在**看数字之前**，所以它是本文件里唯一一条
「无外部依据」的判据 —— 显式承认它可以被后来的证据推翻（第 91 层）。

## §5 上游一致性：靠 **sha256 相等**，不靠计数相等

本产物与 `portfolio_nav.json` 读的是**同一张 `verification.parquet`**
⇒ 两边的 `source_parquet_sha256` **必须相等**。

⚠️ 复用 `portfolio_nav.json` 的 §7 / V6' 教训：**这两个数本来就不该用计数相等来对**，
`n_days` 是「成交窗口桶数」、`trading_days_measured` 是「出名单的天数」。
⇒ 本条**不比较任何计数**，只比 sha256。

## §6 已看过的数（🚨 因此本文件不是预注册）

2026-10-16 一次性探针（**无出处、未落盘，禁引用**）在 `2026-10-13` 窗口上量到：

- 每份 `50000 / 29 = 1724.14` 元
- 买得起 1 手 = **16 / 28 只**；买不够 = **12 只**
- 最贵一只 `688137.SH` 一手 `14697` 元（占本金 29%）
- 口径 A 留现金：投入率 **35.40%**、闲置 **64.60%**
- 该窗口 名义等权 `−0.603456%` vs 口径 A `+0.161812%`，**符号相反**

⚠️ **符号相反这件事不构成任何结论**：那是**单窗口 3 天样本**，
连 `n_days=3` 都不足以给方向（`portfolio_nav.json` 的 V7）。
它唯一的作用是**说明资金约束会显著改变读数，且方向不定**
⇒ 所以 §3 必须两个口径都算。

⚠️ **闲置 64.60% 是本产物真正要回答的量**，它与方向无关：
不管符号往哪边，**只投得起 35% 的钱**就足以否掉「年化 20%」。
