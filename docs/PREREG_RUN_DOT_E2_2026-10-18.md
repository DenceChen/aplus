## §1 被改的那条判据（改前 / 改后）

守卫：`tests/test_data_caliber_consistency.py::test_e2_the_real_run_status_on_disk_agrees_with_what_the_dot_would_render`

**改前**（两条互斥分支，按 `s.date == 今天` 二分）：

| 条件 | 断言 |
|---|---|
| `s.date == today` | **必**出现「今日已跑」 |
| `s.date != today` | 不许出现「今日已跑」 |

**改后**（两条独立不变式，各自可空）：

| 不变式 | 条件 | 断言 |
|---|---|---|
| ① 陈旧方向 | `s.date != today` | 不许出现「今日已跑」 |
| ② **没跑成方向** | `s.status != "ok"` | **不许**出现「今日已跑」，且不许配绿点 |

★ **② 是新增的** ⇒ 本次改动**不是放松**：删掉的那条断言要求生产**说谎**，
换上的这条断言是生产真正实现的那半（第 112 层：过严的守卫与恒真的同样有害）。

## §2 为什么删的是它而不是改生产

生产 `aplus/web/index.html::loadRunDot` 的真实条件（实读源码，非推断）：

```javascript
if (s.status === 'ok' && age === 0) { /* 「今日已跑」+ 绿点 */ }
```

⇒ 「今日已跑」⟸ `status === 'ok' ∧ age === 0`。**`date == 今天` 不是充分条件。**

三条独立依据：

1. **生产自己的注释逐字记录了设计意图**：
   「`status` 只说『这一次跑成没跑成』，**从不说『跑的是哪天』**」
   ＋「判不出来（date 缺失/格式非法）时**也不许**落进『今日』分支」。
2. **正向对照臂本来就存在且写对了**：
   `test_e2_the_run_dot_says_today_only_when_the_run_date_really_is_today` 用的是
   `_ok_run(_TODAY_A)` —— **`status="ok"` + 今天**。⇒ 被删的那条是一条**重复且写错**的对照臂。
3. **盘上状态是合法的 pipeline 跳过**：周六 `run_day_gate = WEEKEND` ⇒ 什么都没预测
   ⇒ 说「今日已跑」+ 绿点是**撒谎**（页面当天确实没有新名单）。

⇒ **生产一个字都不改。**

## §3 变异台（必做，见 `guards-only-count-after-mutation`）

变异体：把 `s.status === 'ok' && ` 从 `loadRunDot` 的第一条判定里摘掉（退化成只按 `age` 分支）。

- 期望：**`rc == 1`**（只有 rc==1 算被杀，rc∈{2,3,4,5} 记「不可验证」）
- 落地核验：**文件 sha256 变了** ＋ **标记串恰好出现 1 次**（不用子串：子串恒真，第 14 层）
- 还原核验：**sha256 逐位相等**（不认「替换执行了」）
- 前置：**变异前基线必须 rc=0**

⚠️ 被这条变异杀死的**只有 ②** ⇒ 若 ② 是恒真的，变异会存活并被读成「守卫有洞」。
⇒ 变异跑完必须**先问「我改的是哪一行」**（第 122 层），再读台子输出。

## §6 变异台结果：⭕ **存活**，以及它暴露的东西

> 🚨 **本节是补记**（§3 是事前写死的规格，本节是它跑完之后的结果）。
> 🚨 **§5 末句那句「不再依赖日历」当场被证伪**，本节就是那份证伪。

执行 §3 规格（变异体 = 摘掉 `s.status === 'ok' && `），结果 **`rc = 0` ⇒ 存活**。

### 逐项取证（三项都是程序打的布尔，不是人眼比 hex）

| 落地核验 | 值 | 读法 |
|---|---|---|
| 文件 sha256 变了 | `True` | 变异确实写进了文件 |
| 标记串恰好出现 1 次 | `True` | 且只有一处（不是子串恒真） |
| 旧串已消失 | `True` | 旧判定确已摘除 |
| 还原后 sha256 逐位相等 | `True` | 还原是真的还原 |
| **变异下 rc** | **`0`** | **存活** |

⇒ 变异**确实生效**（第 14 层的四种入口全排除：匹配 0 处 / 语法炸弹 / 收集期崩 / 同长度）
⇒ 所以「存活」的成因**不在变异侧**。

### 成因：`date == 今天 ∧ status ≠ ok` 这一格此前**零覆盖**

1. 全部兄弟守卫的载荷都由 `_ok_run(...)` 造，`status` **恒为 `"ok"`**；
   `never_run` 那条**没有 `date`** ⇒ 被改的那半个合取项从来没被单独验过。
2. 真实数据守卫**本该**杀掉它 —— 但它读盘上载荷，而盘上
   `date = 2026-10-17`、今天 `2026-10-18` ⇒ **`age == 1`**
   ⇒ 被改的 `age === 0` 分支**根本没进**。

⇒ ★ **真实数据守卫只覆盖「盘上状态恰好落在哪一格」。**
当初（10-17）`date == today` 时它能杀掉这条变异；**日子一翻过去就不能了。**
⇒ 这正是 §5 末句写过的那句「它仍然是时间局部的」，当天兑现。

### 处置：补一条**确定性**的合成对照臂

`tests/test_data_caliber_consistency.py::test_e2_a_skipped_run_never_says_it_ran_today`
—— 日期**同样是今天**，唯一差别是 `status="skipped"` / `steps.run_day_gate="WEEKEND"`，
与已有的正控臂（`_ok_run(_TODAY_A)`）严格配对。

⇒ 两条并排读：「今日已跑」由 `status === 'ok'` **和** `age === 0` **两个条件合取**撑起，
缺任何一个都不许亮；其中**每一个**都有自己独立的一天**不依赖盘上状态**的守卫。

🚨 按 `guards-only-count-after-mutation`：**没被变异杀掉的守卫一条都不算数。**
⇒ 在本节记下结论之前，② 对「`status` 那半个合取项」而言**零证据**；
补完合成臂并重跑变异台拿到 `rc = 1` 之后，它才开始算数。

也没有改动 §1 判据、不改 §2 依据、不改任何数字。
