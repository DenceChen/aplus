# 2026-10-11 操作事故：我自己犯的错

> `INCIDENTS_2026-10-11.md` 记的是**平台**的缺陷。这份记的是**我**的——
> 诊断脚本出错、还原失败、测试本身失效、验证脚本写错。
>
> 分开记的理由：平台缺陷可以靠代码审查和测试发现，
> 而操作事故的特征是「**每一步都照常输出**」。
> 它们不会失败，它们只是安静地给出错误答案。

## A. 诊断脚本：三次事故，全部照常打印

1. **结论写死**。`_diag_limitup.py` 里写死「一字板收益更高」，
   实测更低。脚本正常跑完、正常出图、结论是反的。
2. **`np.arange(n)//0`**。除零让 63 万行归成一组，输出 −80% / +161%
   两行数字并正常退出。一个除零让分布统计变成两个点。
3. **把 100% 换手当成每个调仓点都发生**。日频年成本虚报成 24.51%
   （真实 16.91%）。

**共同点**：都打印了看起来很像样的数字。**有输出的荒谬数字，比没有输出更危险。**

## B. 取名字取错一位

4. **`rsi_series` 播种修正写成 `(W_seed[t] − E[t]) × 衰减`**。

   写成那样等于把未来信息混进了递推。
5. **`ivol` 的市场序列用不复权价算**（因子表未 attach 就求）。

   mkt 按日期索引 → 300 行全 NaN。**且不报错**，只是一个干净的空表。
7. **`keep = [c for c in PRED_COLUMNS if c in df.columns]` 把 `direction` 过滤掉了**
   （它在 up/down 上后设）。

## I. 验证脚本写错（19:13）

17. `_verify_reversal.py` 写 `if "date" in pred.columns else pred`，
    而 `evaluate_weights` 返回的列是 **`pred_date`**。

## 三条从上面长出来的规则

1. **安静的错误输出 > 崩溃。** 每加一处兜底分支（`if x in cols else y`、
   `try/except`、`except → return []`），都要问：这一支会把错误变成什么形状的输出？
2. **变异体全绿先怀疑变异体。** 测试全绿先怀疑测试。
3. **验证脚本必须先验证自己。** 打印第一个数字之前，
   先断言「训练段与测试段不同」「列名是我以为的那个」。

# 第二轮（20:40 ~ 21:20）：复合候选与分块 t 检验

## E'. 测试本身失效：新增 6 次（同一形状，第三次犯）

13. **手算的期望值算错**。`test_block_mean_equals_hand_computed_value`
    断言 `[0.10, 0.40]`，实际 `(0.30+0.40+0.60)/3 = 0.4333`。
    写断言时没把三个数加起来。
14. **构造了一个不体现待证现象的用例**。
    `test_autocorrelated_series_has_far_fewer_independent_observations`
    断言「逐日 t > 分块 t × 3」，实测比值 **1.04**。
    原因是我的「块内噪声」幅度（`var=7.5e-4`）远大于「块间漂移」
    （`var=1.67e-4`），块内噪声**帮忙**把逐日 t 抬高了。
    **先写好「现象应该长什么样」，再构造数据——顺序反了就是给自己写一个假命题。**
15. **等号用在了不等的地方**。断言虚高倍数 `== √6`，实测 **2.769**：
    逐日用 23 个自由度、分块只有 3 个自由度，样本越少单个观测的误差棒越宽。
    改成区间断言 `[√6, 1.2√6]` 并写清为什么略高于 √K。
16. **fixture 不满足被测代码的前提**。`oos_decision` 读 `table[0]` 当最优，
    前提是 `race()` 已排序——我的 `_dec_table` 没排序，
    等于拿一个**不可能由 `race()` 产出的形状**去测裁决。测的是我的假设，不是代码。
17. **fixture 用假日期**。`_xs(n)` 拼出 `2024-01-400`。
    能跑，但读代码的人会以为索引没对齐——**假数据比没有数据更费时间**。
18. **断言了「不像某句话」而不是「是某个数」**。
    变异体「现任只按权重认」**存活**：认错时 champ 变成月频行（0.90），
    增益算成 0.90−0.90 = 0；认对时是 0.90−0.50 = **0.40**。
    我原来只断言「理由里不含某句话」，两种情况都满足。
    改成断言 `train_gain == 0.40` 才真正区分得开。

## F'. 变异体工具本身的一个盲区：1 次

19. **变异体「文本变了、效果是 no-op」，工具却判它有效**。
    变异体写成 `candidate.get("buffer_multiple", 3.0)`，
    而 fixture 总是**显式带这个键且值为 `None`**，
    于是 `get(key, default)` 照样返回 `None`——**源码文本确实变了，行为完全没变**。

    `scripts/mutation_check.py` 的 no-op 检查只比对**源码文本**
    （`changed == original`），查不出**语义上的** no-op。
    真正的判据是**目标测试有没有反应**，而那正是「存活」的定义——
    工具没法靠这个自证，只能靠人问一句「这个变异体真的会改变行为吗」。

    补法：加一条测试覆盖「键根本被省略」的形状
    （`test_omitted_buffer_key_also_means_no_buffer`）。

## G'. 三处多余/错误的代码

20. **写了 `pd_std()` 辅助函数然后立刻删掉**——
    `numpy.ndarray` 与 `pandas.Series` 都原生支持 `.std(ddof=1)`。
21. 前端 `cadence()` 里留了 `${b != null ? '' : ''}`——
    恒为空串的模板片段。改完顺手删掉。
22. 判决板表格**没有「调仓」列**。候选池升到 84 组之后，
    同一组权重的 6 个格子（K=1/5/21/63）看起来像同一个候选重复了 6 遍，
    而**276 个百分点的差距全在被隐藏的那一列里**。
    补列时才意识到：这不是「加个显示」，这是**藏了一个决定性变量**。

## H'. 两条「靠运气」的测试（第 23、24 起）

23. **测试功效只有一半**。变异体「Bonferroni 只按 1 组算」第一次跑就**存活**——
    我的测试用 `t ~ N(0, 1.5)` 造 7 个随机候选，指望至少一个落进
    (1.96, bonferroni_t(8)=2.75) 窗口。算了一下概率：
    单个 9.5%，7 个全落空的概率 **50%**。
    **一条一半概率才杀得掉变异的测试，等于没有。**
    改成全部 `t = 2.2` 的确定性构造。
    补充判据：以后报变异体结果时**连存活率一起报**，别只报「全杀」——
    样本量小的「全杀」里可能藏着 50% 的运气成分。
24. **同一个文件里定义了两遍同名测试函数**。第二份把第一份**整个覆盖**，
    pytest 照样收集 7 个测试、照样全绿——
    而跑的是**旧的那份**（随机版）。
    改用 `edit` 追加函数时没检查旧名是否已存在。
    **同名覆盖在 Python 里不报错，只是悄悄换掉实现**，
    这一点和 `const fmtNum` / `function fmtNum` 重名导致整脚本挂掉是同一族问题，
    但方向相反：那一次是崩了，这一次是安静地跑错了版本。

## I'. 三处「顺手就错」（第 25 ~ 27 起）

25. **module docstring 忘了闭合引号**。后面 17 个测试函数全被吞进字符串里，
    报错是 `SyntaxError: invalid character '。'`——
    指向一个**完全无辜**的汉字，而真正的错在 30 行之前。
    用 `cat >>` 往文件尾部追加时最容易出这种错。
26. **导入了 `advance` 却没在调它之前把计数交出去**——
    自己先写了 `days_since = prev + 1`，再 `advance()` 又加一次，
    月频会**每两天算成三天**。写了才发现多算了。
    判据：**每个 import 都要能被 grep 到一次真正的调用**，否则删掉。
27. **`bool` 穿透了 `isinstance(x, int)`**。Python 里 `bool` 是 `int` 的子类，
    `load_state` 把 `days_since_rebalance: true` 当成 1 天。
    同一个项目在 `save_state` 和 `ledger._validate` 里都写了 `isinstance(x, bool)`
    排除，**唯独新写的 `load_state` 漏了**——
    三处写法不一致，第三处是最后写的。
    是新加的「非法计数」测试把它逼出来的。

## J'. 一个真·冗余护栏引出的僵尸变异体（第 28 起）

28. 变异体「删掉 `is_due` 里的 `if every <= 1: return True`」**存活**。
    按规矩先怀疑变异体——逐个枚举状态后发现：
    通式 `days_since + 1 >= every` 在 `every=1` 时本来就恒真，
    **那道短路是真冗余，删掉行为不变**。
    这是**僵尸变异体**：源码文本变了，效果是 no-op，
    而 `mutation_check.py` 的 no-op 检查只比对文本，查不出语义上的。

    处置：换成一个真会改变行为的变异（通式差一），
    并在脚本里写明**为什么这一处不用短路变异**。
    **变异体存活有两种原因——测试弱，或变异体无效——必须逐个分清**，
    否则「存活率」这个指标本身就没意义。

## K'. 真实浏览器抓到的三件 pytest 抓不到的事（第 29 ~ 31 起）

29. **同一屏上两处对同一组权重给出相反结论**。21:42 的判决板截图：
    - 上方红字：「现任健康度：**已被证伪**」
    - 下方：「未经赛马验收的默认值（**尚未被证伪**，也尚未被证实）」

    两句话在描述**同一组** `{'mom20':1.0,'rev5':0.3,'vol20':0.5,'vsur':0.5}`。
    下方那句是**硬编码文案**，它从没问过健康度那一栏。
    修法：让它去问 `evoSummary.champion_falsified`。
    **教训：一块屏幕上描述同一对象的结论，必须来自同一处判定。**
    「硬编码的措辞」是静默矛盾的温床——它永远不会被后端的改动通知到。
30. **A 股配色是反的**：`--up: #F04A4F`（**红**）、`--down: #1FB981`（**绿**）。
    我按英文直觉把「已被证伪」写成 `pct-down`，真浏览器里量出来是
    `rgb(31,185,129)`——**绿的**。证伪是元判断（策略无效），比亏钱更严重，
    必须是红色，也就是这个项目里的 `--up`。
    **教训：颜色/符号这类约定要去量，不能按名字推断。**
31. **`textContent = '<b>…</b>'` 会把标签原样打印出来**。
    第一次修完自相矛盾，浏览器里显示的是字面的
    `<b class="pct-down">已被证伪</b>`。
    要渲染标记就用 `innerHTML`（并对插值做转义）。

## L'. 三起「一直在跑，但跑的不是我以为在跑的东西」（第 32 ~ 34 起）

32. **跑了七场赛马，从来没量过一次因子 IC**。

    而候选池里**没有**符号正确的那个组合。再赛一百场也不会发现。
    **教训：当所有实验都在同一个维度上增加样本时，

    正确顺序是「先量因子 → 再赛权重」，我把它整个跳过了。
33. **候选池的符号结构从来没被打印过**。

    **教训：生成搜索空间之后，第一件事是看它的分布，不是看它的排名。**
    搜索空间的形状决定你能找到什么，排名只决定你找到的先后。
34. **改掉前视口径之后，没量过「虚高了多少」**。

## M'. 三起「测试通过了，但它没测到它声称在测的东西」（第 35 ~ 37 起）

35. **推理链在最顺的那一环断了**。
    `mom20` 的 IC 显著为负（t=−9.40）→ 书 3.1.2 要求构造因子所用收益
    做 ±10% 复牌压缩 → 代码里 `mom20`/`rev5` 直接用原始价比值、
    确实绕过了压缩 → 「所以 IC 为负是复牌极值造成的」。
    前三箭头都对，**第四箭头是我编的**。
    实测 400 只 / 720,587 行：复牌日且 |收益|>10% 只有 **90 行（0.0125%）**，
    修复前后 mom20 绝对值之比中位数 **1.000**。
    结论：**负 IC 是真实的短期反转效应，不是数据缺陷。**
    **教训：「找到一个能解释现象的缺陷」≠「它就是这个现象的原因」。
    两者之间必须有一步实测，否则链条会断在听起来最顺的那一环——
    而那一环恰恰是最少被人验证的。**
36. **第一版修复压得太宽，被既有测试拦下**。
    我写的是全局 `clip(±10%)`，`test_factor_layer_still_keeps_legitimate_limit_up_moves`
    当场打红：创业板 ±20% 涨停是真实、可交易、有信息的事件，
    全局压缩会**系统性削平所有信号**。

## O'. 两个「等结果的循环」永远等不到结果（第 39 起）

39. **`pgrep -f X` 会匹配到包含 X 的那条命令行本身**。
    我写了三条等待赛马的循环，其中两条是：

        while pgrep -f ic_guided_race >/dev/null; do sleep 120; done

    而**这条 `bash -c` 自己的命令行里就有 `ic_guided_race`** ——
    `pgrep -f` 按完整命令行匹配，于是它永远匹配到自己，永远不退出。
    赛马 23:26 就跑完了，这两个循环活到 23:49 还在空转。

    正确写法是 `ps aux | grep -q "[i]c_guided_race"`（方括号让 grep 不匹配自己），
    第三条我确实是这么写的，它正常退出了——**同一个坑在同一条消息里踩了两次**。

    **教训：等待逻辑本身也会挂，而且挂得毫无症状**——
    没有报错、没有输出、没有 CPU 占用，只是一直不结束。
    「等不到结果」有两种可能：结果没来，或者等待器坏了。
    区分它们的方法只有一个：**先确认等待条件本身是否可能为真**。

## P'. 探针量错了对象，差点写出一条假结论（第 40 起）

40. **「`turn` 历史数据缺失」是我探针写错造出来的假结论**。
