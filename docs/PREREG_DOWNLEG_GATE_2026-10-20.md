## 0. 为什么跌腿需要自己的闸门

D1 交付物是两半：每天 **10 只会涨** + **10 只会跌**。

- **涨腿**有上线闸门：`scripts/score_ranking_power.py`（`GATE_ARM = "up"`），
  判据 **G4 = 「`score` 四分位命中率单调」**，三态判决
  `PASS` / `NOT_PASSED_POWERLESS` / `NOT_PASSED_MEASURED`。
- **跌腿**此前**只出单、没有被判**：`data/reports/downleg_ranking.json` 自己写着
  `role: "⚠️ 对照臂 / 诊断，不是判决臂。"`，
  `verdict_about_downleg: "样本不足（5 个成交窗口 < 6），不给方向；还差 1 个成交窗口才开判。"`

⇒ 本文件预注册的是**跌腿自己的三态闸门**，产物
`data/reports/downleg_gate.json`（**新文件**，不覆盖对照臂那份）。

🚨 **不许改 `scripts/score_ranking_power.py` 的判据臂一个字。**
本轮**只读复用**它的统计实现（§4），不复制、不重写、不调它的常量。

## 1. 判决臂与口径（预注册）

| 项 | 值 | 理由 |
|---|---|---|

## 2. ★ 方向镜像规则（本文件最承重的一条）

### 2.1 规则

> **跌腿的命中率必须随 `score` 升高而下降**（`monotone_direction = "decreasing"`）。
> 判据写在 **score 升序**的命中率序列上：**非递增**（分段单调即可，非严格）。
>
> 用代码里的分位标签写：四分位 **Q1 = 组内最高分，Q4 = 组内最低分**，
> 于是同一条规则在 Q 标签上是
>
> ```
> hit_rate(Q1) <= hit_rate(Q2) <= hit_rate(Q3) <= hit_rate(Q4)
> ```
>
> ⚠️ **补记（2026-10-20 实现时更正，见 §9 第 7 条）**：本节初稿把这条写成
> `>=`，那是**Q 标签转写**写反了。**规则本身（score 空间）一个字未改**
> ——「命中率随 score 升高而下降」是 §2.2 从生产代码推出的，与命中率数字无关。

### 2.2 这条方向**只**由生产代码推出，与任何命中率数字无关

三处生产代码（**行号级**）：

| 事实 | 出处 |
|---|---|
| 打分器「**分越高越看涨**」 | `aplus/predict.py:271` `ranked = df.sort_values("score", ascending=False).reset_index(drop=True)` |
| 跌腿取的是**分数最低**的 `bottom_n` 只 | `aplus/predict.py:276` `up_src, down_src = ranked.head(top_n), ranked.tail(bottom_n)` |
| 跌腿的 `hit` 意思是「**它真的跌了**」 | `aplus/verify.py:94-95` `is_up_prediction = prediction["direction"] == "up"` / `return "hit" if (actual_pct > 0) == is_up_prediction else "miss"` |

⇒ 跌腿的 `hit` = 真的跌 ⇒ 生产发的是**最低分**的那 10 只
⇒ 期望：**分越低 ⇒ 越容易真的跌** ⇒ **命中率随分数升高而下降**。

⇒ **即使把命中率换成随机数，方向规则也不变** —— 它由「发哪一端」与
「`hit` 是什么意思」两件事定死，不由数据定。
（守卫 `tests/test_downleg_gate.py` 里的方向对子**不依赖任何真实产物**。）

### 2.3 与涨腿臂的关系：**镜像，不是照抄**

| | 涨腿（`score_ranking_power.py`） | 跌腿（本产物） |
|---|---|---|
| `hit` 的含义 | 真的**涨**了 | 真的**跌**了 |
| 生产发的哪一端 | `ranked.head(top_n)` = **最高分** | `ranked.tail(bottom_n)` = **最低分** |
| 期望（**score 空间**） | 分越高 ⇒ 越容易涨 ⇒ 命中率**随 score 升高而上升** | 分越低 ⇒ 越容易跌 ⇒ 命中率**随 score 升高而下降** |
| 期望的 ρ 符号 | **正** | **负** |
| 分位标签 | Q1 = 最高分 | Q1 = 最高分（**同源**） |
| **Q 标签上的判据写法** | `hit(Q1) <= hit(Q2) <= hit(Q3) <= hit(Q4)` | `hit(Q1) <= hit(Q2) <= hit(Q3) <= hit(Q4)` |

⇒ 🚨 **两边的代数形式逐字相同、含义完全相反**：
在 Q 标签（Q1=最高分）上，`<=` 在**涨腿**那边读作「**分越低命中率越高**」
（⇒ 与涨腿的期望相反，见 §2.4），在**跌腿**这边读作「**分越高命中率越低**」
（⇒ 正是跌腿的期望 ✓）。

⇒ **这正是「方向必须显式写进产物」的理由**：
两个脚本里长得**一模一样**的那一行，含义是**相反**的
⇒ 读者若靠「代码长得像」去推断方向，**一定会读反**。
⇒ 产物因此必须同时写 `monotone_direction` / `monotone_direction_means` /
`quartile_label_convention` / `monotone_test` / `expected_rho_sign`
（§5），而**不许**让读者从代码形状去猜。

### 2.4 🚨 观察到的方向不一致（本轮发现，**不改涨腿臂**）

读 `scripts/score_ranking_power.py` 时发现一处**方向口径**问题，本轮**只记录、不修改**
（不许改判据臂）：

- 涨腿臂的代码判定是 `all(seq[i] <= seq[i+1])`，`seq` 按 **Q1(最高分) → Q4(最低分)** 排
  ⇒ 它判的是「**分数越低命中率越高**」；
- 而 §2.2 的推导（`predict.py` 分高=看涨 + `verify.py` up 的 `hit`=真涨）给出
  涨腿的期望是「**分数越高命中率越高**」；
- ⇒ **两者方向相反。** 预注册 `docs/TODO_reverse_scoring_2026-10-15.md` §2.1 S3 原文
  「`score 四分位 → 命中率单调递增`」按统计学的常规定义（Q1 = 25 分位 = **最低分**）
  读，指向的是「分数越高命中率越高」⇒ 与**代码**的方向不一致。

⚠️ **今天没有数字被翻转**：涨腿臂当前的四分位序列在**两个方向下都不单调**
⇒ 判决 `NOT_PASSED_POWERLESS` 在两个口径下**相同**
（产物 `up_arm_cross_reference` 的两个单调标志会把这件事**算出来**，不是断言）。
🚨 但这是**运气**，不是保险：若将来涨腿臂的四分位变成「只在一个方向下单调」，
那枚 PASS 就会是**反向的绿灯**。⇒ 登记为**欠账**（§9），本轮不动它。

## 3. 三态判决（同名同义）

| 判决 | 触发条件 | 含义 | 该做什么 |
|---|---|---|---|
| `PASS` | 四分位命中率随分数升高而**下降**（§2.1 判据成立） | 跌腿**有**排序力 | 进入发布评估（**还要过 §7 的其余条件**） |
| `NOT_PASSED_POWERLESS` | 不满足判据 **且** `\|ρ\| < 检出力下限` | 这份样本**分不出**任何效应 | **不许当回避清单发布**；先攒前瞻期 |
| `NOT_PASSED_MEASURED` | 不满足判据 **且** `\|ρ\| >= 检出力下限` | 检出力**足够**却仍不满足 ⇒ 分数没有排序力 | 要换结构 |

⇒ 两支 `NOT_PASSED_*` **都**不许发布，区别只在**下一步动作相反**
（与涨腿臂完全一致：`docs/TODO_reverse_scoring_2026-10-15.md` §7 的三态表）。

🚨 **`NOT_PASSED_POWERLESS` 绝不许读成「跌腿没有预测力」**（第 16 种形状）。
它是「**测不到**」，不是「**没有**」。

## 4. 检出力下限的算法（**不许手打**）

- 统计量：**点二列相关** `ρ(score, hit_indicator)`（与涨腿臂同款）。
- 零分布：**组内置换**（组 = `pred_date`），打乱「分数 ↔ 命中」的配对，
  保留日期结构与方向结构；`B = 20000`，`seed = 42`。
- **检出力下限 = 零分布的 95 分位** `q95 = quantile(|ρ_null|, 0.95)`。
  含义：**这份样本连 `|ρ|` 小于它的关联都分不出来。**
- `detectable_at_alpha05 = (|ρ_obs| >= q95)`。
- p 值用 **Phipson–Smyth `(b+1)/(B+1)`**，不是 `b/B`（后者在零假设下会报 `p = 0`，
  而 `p = 0` 不是概率）。

⇒ **外部锚**：这个下限**不是**手打的字面量，它是**这份样本自己的零分布**。
石川与 Chan **都没有**给「命中率门槛」（见 `docs/TODO_reverse_scoring_2026-10-15.md` §1 末），
所以**不许**从书里编一个数来。

⇒ **同源才有可比性**：以上四项**直接 import** `scripts/score_ranking_power.py` 的
`_permutation_p` / `_point_biserial` / `_within_group_quartile` / `_groups_by`
（**只读，不改它一字**）。守卫会断言「本脚本用的就是它那个对象」
（防「复制一份，两份悄悄漂移」）。

## 6. `what_this_cannot_prove`（**四条，逐字写进产物**）

1. 样本薄时「**测不到**」≠「**没有**预测力」。
2. **条目数不是独立观测数** —— 独立单元是**成交窗口**（`entry_date`），
   而 `pred_date` 是**出单日**（周末/节假日出单 ⇒ 多张名单押同一个成交窗口）。
3. 跌腿**不可直接做空** ⇒ 其价值必须由**信息价值**证明（外部锚：
   石川 `data/books/cn_factor_lines.txt:768`「不合理考虑做空限制，也会高估因子的收益。」）。
4. 本产物**不是**涨腿的判据臂（涨腿的闸门是 `scripts/score_ranking_power.py`）。

⚠️ 这四条里的**数必须算出来**（`n_pred_dates` / `n_entry_dates` / `n_rows`），
不许写死（第 73 层：同一事实被复制到多处 ⇒ 写死的那处必然漂移）。
