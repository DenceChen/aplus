## §1 这个问题是什么

屏幕上的 D2 读数 `data/reports/basket_nav_01_2026-10-16.json` 测的是**满仓 10 只 +
8 因子逐年 IC 定权**的组合，判决档 `cagr = +10.5563%`、年化 MDE `±22.6738%`。

但**平台真正会执行的账户**不是它：

| 维度 | 屏幕读数（`basket_nav_01`） | 平台实盘 |
|---|---|---|
| 权益敞口 | 1.0（满仓） | **0.5**（5 只 × 10%） |
| 持仓数 | 10 | **5** |
| 信号 | 8 因子**逐年 IC 定权**（`R⁻¹Σ_f`） | **4 因子 `DEFAULT_WEIGHTS`**（`weights.json` 不存在 ⇒ `evolve.load_weights` 走 fallback，`caveat_kind="unraced"`） |
| 整手 | **无**（小数股） | A 股 1 手 100 股；**科创板 688/689 = 200 股** |
| 每笔成本 | `cost_drag = 换手 × 费率`（**无 ¥5 固定额**） | `aplus/costs.py::FeeSchedule`（**有 ¥5 最低佣金**） |

⇒ **三层口径错位**（敞口 / 持仓数 / 信号），另加两层执行层错位（整手 / 成本模型）。

**本文要回答的问题（唯一）**：
**按平台「真正会执行的那个账户」的配置，5 万本金的年化是多少、离 20% 差多少、能不能定符号。**

**本文不回答**：
① 因子有没有效；② 20% 到底能不能达到（那需要先知道信号本身）；
③ 怎样改进策略。**只做一次测量，并把测不出的部分照实写成「测不出」。**

### §3.2 臂组 2 — 可买性（本轮最重要的新东西）

**先说清它不是什么**：
`aplus/predict.py::filter_universe` 现在把「买不进（一字板/涨停收盘/停牌）」**两边都剔**，
理由是「塞进跌篮子等于把一个缺失当成一个看空信号」。
🚨 **那是「没有价格发现」，不是「贵」。**
⇒ **整手买不起 ≠ 买不进**：688498 天天正常交易，只是 1 手要 20 万。
对**涨腿**它不可执行 ⇒ 剔掉；对**跌腿**它恰恰是最该提醒「你手上这只该跑」的名字。

⇒ **本组三个臂只改涨腿。跌腿的原样结果必须同时报出**（作为对照），
并写明「可买性过滤不改跌腿」这条口径。

**可买性判据**（每个信号日 D、每只候选票）：

```
lot(code)  = 200 if code[:3] in ("688","689") else 100      # 科创板 200 股，其余 100 股
px(code,D) = 该票**自己的时间轴**上第一根 > D 的 bar 的**不复权 close**
cost_1_lot = px(code,D) × lot(code)
可买 ⇔ cost_1_lot ≤ 每份预算
```

🚨 **价格用 D 日自己时间轴上的第一根 > D 的 bar**（不是日历日 D+1）：
停牌票的下一根 bar 可能远在数日之后，而 `_next_bars` 用的就是**它自己的时间轴**
⇒ 判可买性必须与成交窗口用**同一条时间轴**，否则「买得起」与「买得进」不是同一个量。

🚨 **科创板 200 股是交易所规则，不是本仓数据里的数**：
`aplus/panel.py::price_limit` 认得 688/689（`LIMIT_GROWTH=0.20`）⇒ 板块归属可信；
但「起买 200 股」这条**本仓没有数据源**，它写成**代码里的显式常量**并在本产物里
自报「外部规则，非实测」。

**三个臂**（都在同一候选池上做，差别只在**什么时候**看可买性）：

| 臂 | 规则 | 涨腿结果 | 跌腿 |
|---|---|---|---|
| `ARM_A`（无约束） | 候选池 = 全部可打分股票；按分数取 top-N | top-N（**可能全是买不起的**） | **原样** |
| `ARM_B`（硬过滤） | 候选池**剔掉**「1 手金额 > 每份预算」的票；再取 top-N | 买得起的里分数最高的 N 只（**池子不足 N ⇒ 就取剩下的那些**） | **原样** |
| `ARM_C`（过滤 + 降深度） | 同 ARM_B 的过滤，但**凑不满 N 时向排名更深处取**（先取全部买得起的，不足部分用分数最高的买不起的补位） | 恒为 N 只（池子用尽则用尽数） | **原样** |

⚠️ **ARM_B 与 ARM_C 的唯一区别是「可买候选不足 N 只时怎么办」**。
⚠️ **过滤同时作用于池子与名次**：ARM_B/ARM_C 的名次是**在过滤后的池子里重排**的
（不是「取原 top-N 再删」）—— 否则它们与 ARM_A 只差一个「剔掉几只」，
量不到「可买性过滤把选股口径改了没有」。

**每个臂 × 每个预算档出**：
命中率 / 毛超额 / sd / 年化 MDE / 分块 t / 判决 **+**
**整手可投入率 / 买得起 1 手的票数 / 连 1 手都买不起的票数**。

**整手可投入率** = `Σ(实投金额) / (N × 每份预算)`（真实整手取整后的钱 / 名义权益）。
**买得起 1 手的票数 / 连 1 手都买不起的票数** = 逐调仓日的**篮子层面**计数（汇总后报均值与总数）。

🚨 **过滤引入的暴露变化必须同时报**（不许只报「过滤后更好」）：
① 组合的**流通市值中位数 ÷ 候选池的流通市值中位数**（用 `aplus/capweight.py`；
`implied_cap = close × a_shares`，`a_shares = volume × 100 / turn`）；
② 与已有 8 个因子的**共线性**：用 `scripts/factor_attribution.py` 的口径
（`gross_excess ~ 1 + Σβ_i·expo_i`，野自助 B=2000、种子 20261015），
报 `expo_logcap` 的 β 与 t。⚠️ **`expo_logcap` 不进 `FACTOR_COLS`**（那 8 列是
`factor_attribution` 自己预注册过的判决口径，往里加 = 换判据后重跑）。
**只作测量，不进判决。**

### §3.3 臂组 3 — 实盘账户（判决腿）

**一个账户引擎**（`simulate_account`），四档并排：

| 档 | 名称 | 权益 | 持仓数 | 每份 | 信号 | 可买性臂 | 角色 |
|---|---|---|---|---|---|---|---|
| `T1` | 满仓 10 只 + IC 定权（**日再平衡**） | 1.0 | 10 | ¥5,000 | `BACKTEST_IC` | 无 | **对照 = 现有判决**（必须复现 `+10.5563%`） |
| `T1h` | 满仓 10 只 + IC 定权（**持有到期**） | 1.0 | 10 | ¥5,000 | `BACKTEST_IC` | 无 | 与 T1 的差 = 「日内再平衡 vs 持有」的差 |
| `T2` | **半仓 5 只 + 实盘信号** | **0.5** | 5 | **¥5,000** | `LIVE_DEFAULT` | 无 | **🚨 实盘真相（判决腿）** |
| `T2b` | 满仓 5 只 + 实盘信号 | 1.0 | 5 | ¥10,000 | `LIVE_DEFAULT` | 无 | 「5 万 / 5 只」满仓读法（敏感性） |
| `T3` | 满仓 10 只 + 实盘信号 + 可买性 | 1.0 | 10 | ¥5,000 | `LIVE_DEFAULT` | `ARM_C`@`P5` | 「若执行层修好后能达到什么」 |

**T2 的每份金额是 ¥5,000 而不是 ¥10,000** —— 这是**代码事实**：
`aplus/alloc.py::build_allocation` 的 `amount = round(capital * per_stock_cap, 2)`
= `50000 × 0.10` = **¥5,000**；`scripts/run_daily.py:786` 调它时**没传**
`max_positions` / `per_stock_cap` ⇒ 用默认 `5` / `0.10` ⇒ **5 只 × ¥5,000 = ¥25,000 权益 + ¥25,000 现金**。
⇒ **T2 = 50% 敞口**；`T2b`（¥10,000/份、满仓）是**另一种读法**，只作敏感性。
⚠️ 「5 万 / 5 只 = 每份 ¥10,000」与「实盘每份 ¥5,000」**是两个不同的东西**，
本文两个都报并标明。

**账户引擎的口径**（`simulate_account`）：

1. **买入**：调仓日 D 的成交日 e(D) = 该票自己时间轴上第一根 > D 的 bar；
   `shares = floor(每份预算 ÷ (px × lot)) × lot`；`实投 = shares × px`；
   `shares = 0` ⇒ 该票**买不进**（钱留现金）。
2. **持有**：逐日 `value_i ← value_i × (1 + r_i(t))`，`r_i(t)` = 回测产出的该票该日
   `actual_pct`（后复权口径的日收益）。
3. **卖出 + 换仓**：下一个调仓日 D' 的 e(D') 收盘全部卖出（付卖出侧成本），
   再按新名单买入（付买入侧成本）。**换仓日当天的收益只归新篮子**
   （旧篮子在 e(D') 收盘已变现）。
4. **现金**：收益 **0**（主口径）；另报 **1.5%/年**（`0.015/244` 每日）的敏感性。
5. **成本**：`aplus/costs.py::FeeSchedule` **逐笔**算（`buy` / `sell`），
   ⇒ 与 §3.1 的 `backtest_tier_*` 是**两个模型**，分别标注。

**每档出**：`cagr`（几何）、`arith_ann`、`verdict_mde_annual`（`aplus/hurdle.py::DAYS_PER_YEAR=244`）、
`verdict_upper_one_sided_95`、`target=0.20`、`measured_sign_determinable`、`gap_to_target_pp`、
`整手导致的实际投入率`、闲置现金比例、逐日 NAV 序列的落盘字段。

🚨 **公式不许重写**：`judge()` / `account_nav()` / `excess_contribution()` /
`required_excess()` / `tier()` **一律从 `scripts/measure_basket_nav_01.py` import**。
本脚本只**调用**，不复制、不改写。

🚨 **`R` 只有一个**：`aplus.hurdle.DAYS_PER_YEAR = 244`。
`aplus/verify.py::TRADING_DAYS_PER_YEAR = 378` 是**另一个量**，本产物**不引用**。

## §4 判决规则（事前写死，四条穷举）

**判决链一律用 `measure_basket_nav_01.py::judge()`**，判据文本一字不改：

```
U = c + M（M = 年化 MDE）
1. |c| < M            ⇒ 🚨 连符号都定不了
2. U < T(=20%)        ⇒ 「在 95% 置信下 20% 不可达」
3. c < T ≤ U          ⇒ 🚨「测不出」：既不许说「达不到」，也不许说「接近」
4. c ≥ T              ⇒ 不许写「能做到」⇒ 转 §3.3 的账户净值
```

- `M` = 年化 MDE = `1.96 × sd(log1p r) / √n × 244`（`tier()::mde_as_annual_pct`）。
- `measured_sign_determinable` = `|c| ≥ M`。
- `gap_to_target_pp` = `(0.20 − c) × 100`（**带符号**；⚠️ 当 `|c| < M` 时
  **它不是点估计**，只作形状陈述，产物里必须同时带 `measured_sign_determinable`）。
- **超额腿的判决**用 `excess_contribution()` + `required_excess()`（比值口径，
  `(1+c_bk)/(1+c_mkt) − 1`），⚠️ `yrs` **不进公式**（两个入参都已是年率）。
- 「实测/需要」= 两个**不可定符号**的量相除 ⇒ **只作形状陈述**。

**判决腿 = `T2`（实盘真相）**。T1 / T1h / T2b / T3 / 敞口阶梯 = **并排对照**。

**「还差多少」按基准分臂**（`VERDICT_BENCH_ARM="equal_weight"` 判决臂 +
`cap_weight` 敏感性臂），**基准臂的选取是预注册的，不许因为读数难看就换**。

## §5 失败怎么办（事前写死）

| 失败 | 处置 |
|---|---|
| 面板为空 / 判决年缺失 | 拒绝落盘（rc=2），打印原因。**绝不回落成「没有超额」** |
| 某臂跑不出来（空序列） | 该臂在产物里写 `null` + `reason`，**不许**用 0 顶，**不许**跳过不提 |
| 某个臂的 MDE 算不出（n ≤ 1） | 同上，`null` |
| 某档 `|c| < M` | 照实写「**测不出**」。**不许**写「接近」，**不许**写「达不到」 |
| 成本被扣两次（`毛 − 净 ≠ 实测成本`） | 拒绝落盘（会计恒等式，只靠减法） |
| T1 复现不出 `+10.5563%` | 拒绝落盘并打印两个数 ⇒ 说明本脚本与既有判决链分叉了 |
| 跑不完（时间/内存） | 产物**不落盘**（不落半份）；已算完的臂写进 `data/reports/_deployed_d2_arms/*.json` 缓存，重跑时复用 |

## §14 补记 B：**§5 的「成本被重复扣减 ⇒ 拒绝落盘」是一条恒真的守卫**（2026-10-21）

> ⚠️ **本节是补记，不是事前预注册**，且**不含任何读数** ——
> 它记录的是**实现层的一个设计缺陷**，与数据无关。

§5 写的是「成本被重复扣减（`毛 − 净 ≠ 实测成本`）⇒ 拒绝落盘（会计恒等式，只靠减法）」。
实现时去读了被调用的那个函数
（`scripts/backtest_walk_forward_weights.py::realized_cost_and_net`）：

```python
gross_annual    = mean(gross_daily) * 244
with_cost_annual= mean(daily_with_cost) * 244
realized        = gross_annual - with_cost_annual
return realized, with_cost_annual, gross_annual - with_cost_annual - realized
```

⇒ **第三个数（drift）按定义恒等于 0**（它就是 `a − b − (a − b)`）。
⇒ 「`abs(drift) > 1e-12` ⇒ 拒绝落盘」这条守卫**永远不会触发** ——
它是**恒真的装饰**（第 112 层：过严的守卫与恒真的守卫同害，而恒真的更贵，
因为它让人以为「这一层有人守」）。

⇒ **处置**：
1. **不**把它做成「拒绝落盘」的写盘闸（那是一条永不触发的装饰）；
   改成**把 drift 逐档记进产物**（读者看得见它是 0，也看得见它**按定义**是 0）。
2. **真正的「成本只扣一次」证据在别处**：
   **账户引擎的逐笔恒等式** —— 守卫
   `tests/test_deployed_d2_verdict.py::test_the_account_engine_deducts_costs_exactly_once`

3. ⚠️ 顺带记录：**既有脚本 `backtest_walk_forward_weights.py::main` 里那条

### §16.1 K 的语义（不许写成「降低了推荐频率」）

`rebalance_every = K` 交易日换一次仓；**非调仓日沿用上期持仓**
（`aplus/backtest.py::_held_predictions` 就是这个语义）
⇒ **「每天出单」与「每 K 日交易」是两件事**（`aplus/live_rebalance.py` 的设计）
⇒ **K 不改变 D1 的承诺**。

### §16.2 网格定义：K × 权益 × 过滤 × 信号

| 轴 | 取值 |
|---|---|
| K | **5 / 10 / 21 / 42 / 63**（交易日） |
| 权益 | **50% / 100%** |
| 过滤 | **ARM_A（无过滤）/ ARM_C @¥5,000** |
| 信号 | **LIVE_DEFAULT / BACKTEST_IC** |
| 仓数 | **固定 10 只**（交付形态） |

⇒ **20 个 arm 配置**（4 组基础配置 × 5 个 K），其中 **K=21 的 4 个复用既有 config_id**（不重跑）
⇒ **账户层 40 格**（20 配置 × 2 个权益档）。

**每份金额**：50% ⇒ ¥2,500/份；100% ⇒ ¥5,000/份（= 本金 × 敞口 ÷ 仓数）。
⚠️ **过滤阈值固定 ¥5,000**（任务书指定）⇒ **权益 50% 档「过滤比账户松」**
⇒ 该档仍会有买不起的票（**投入率会显示它**）——这不是 bug，是口径，必须标出来。

### §16.3 三条必须一起报的

1. 🚨 **K 变大 ⇒ 账户的「日度」性质下降**：K=63 时持有 3 个月，
   而 D1 的榜单**每天**都换 ⇒ **榜单与账户持仓脱节**，榜单的边际价值随 K 递减。
   ⇒ 每格给**实测的持仓换手率**（口径与 `aplus/backtest.py::cost_drag` 相同：
   `(n_in + n_out) / (2·max(top_n, |cur|, |prev|))`，逐调仓日取均值，年化 × 244/K）。
2. 🚨 **K 的净效应 = 毛超额的变化 + 摩擦的变化**，**两项方向可能不同**
   ⇒ 每格**分列** `gross_excess_annual_pct` 与 `friction_annual_pct`（= 账户逐笔成本 / 本金 / 年数），
   **不许只报净值**。
3. ⚠️ **K=63 的前瞻证据需要 189 个交易日**（batch 5 的 C2）⇒ 前瞻轨要半年 ⇒
   **即使回测说它好，也不许跳过这半年**（写进产物的 `forward_evidence_note`）。

### §16.4 「榜单命中率与账户收益的关系」怎么报

⚠️ **D1 榜单的命中率与 K 无关**（榜单每天出，K 只改**交易**频率）
⇒ 变的是**账户对榜单的暴露**：K 越大，账户实际持有的那一篮子越旧。
⇒ 报法：**逐 K 给「持有篮子的逐笔命中率」+「实测持仓换手率」+「账户 CAGR」三列并排**，
让读者自己看「榜单的边际价值随 K 递减」这个形状，**不许**写成「K 越大越差/越好」的定论
（各档 `measured_sign_determinable` 均为 False ⇒ 只作形状陈述）。

## §17 补记 E：**两个被实测抓到的缺陷**（2026-10-21，K 轴落地时）

> ⚠️ **本节是补记，不是事前预注册**，且**不含任何读数** ——
> 它记录的是**实现层的两个缺陷与它们的处置**，不是结论。
> 🚨 **两个缺陷都产出了「看起来很正常」的数**，而其中一组已被下游读到并引用过。

### §17.1 缺陷一：**价格表只覆盖 K=21 的调仓日** ⇒ K=5 / K=10 两组臂的读数是坏的

**机制**：`price_map` 原先按 **K=21 的逐年日历**构造
（`rebalance_days = {d : is_rebalance_day(by_year[y], d, 21)}`）。
K=42 / K=63 的调仓日历**恰好是 K=21 的子集**（42 = 2×21、63 = 3×21）⇒ **没露馅**；
而 **K=5 / K=10 的调仓日不在表里** ⇒ 那些臂的绝大多数选择 `px = None`
⇒ `affordable_at(None, …)` 判 False（信号缺失不放行）⇒ **被判成「买不起」**。

**实测证据**（K=5 臂的缓存）：`selections=2777`、**`px_is_None=2608`**（93.8%）、
`n_cannot_afford_1_lot@¥5,000 = 2632` ⇒ 那组臂的「买得起率」是**伪像**。

⇒ **处置**：价格表与池子中位数**覆盖所有 K 的调仓日**（`K_VALUES ∪ {args.rebalance_every}`），
并把那 8 个坏缓存**删掉重跑**。
⚠️ **下游已经读到过这组数**（K=5 毛超额 +4.82%、净 −18.65% 等）⇒ **那些数一律作废**。

### §17.2 缺陷二（**已撤回**：它其实不是缺陷）

~~**换手率按 `(code, px)` 元组比** ⇒ 年化换手 4268%（无意义）~~

🚨 **这条我写错了，撤回**：把 `(code, px)` 元组当集合元素，**只有在 px 每天都在变
且同一天内每只票的 px 唯一时**才会「每只都算新股」。而 §17.1 的缺陷
让 K=5/K=10 的 **px 大量为 `None`** ⇒ 元组 `(code, None)` **跨天稳定**
⇒ 换手率**本来就是按 code 算的** ⇒ **4268% 不是 bug**。

⇒ **4268% 是真的**：K=5 ⇒ 每年 48.8 次调仓、每次换掉 85.5% 的名字
⇒ **年化 4175%（= 41.75 倍）** —— **K=5 就是「每 5 个交易日全换一次」**
⇒ 这个数与「持有 5 天」自洽。⚠️ 我差点把它当成缺陷去「修」。

✅ **但代码仍改成比 code**（`{c for c, _p in baskets[day]}`）——
不是修 bug，是**去掉一个「px 恰好稳定时才正确」的隐含前提**
（价格缺失时元组会退化成 `(code, None)`，两天的元组相等 ⇒ 换手率被**低估**）。

⇒ **留下的纪律**（比原条更强）：
**任何新出的量都要先看一眼量级 + 问「它有没有物理上界」** ——
换手率 ≤ 100%/次调仓、年化 ≤ (244/K)×100% ⇒ **K=5 的 4175% 落在界内**
⇒ 反而是**界内**才让我没去「修」它。
⇒ **「离谱」与「错」不是同一件事**：离谱的数要先问「它的上界是多少」。

### §17.3 两条纪律（留给下一轮）

1. **任何跨参数轴的新增维度，都必须重新检查「这个量的输入表覆盖了它吗」** ——
   §17.1 的根因不是算错，是**K=42/63 恰好落在 K=21 的子集里**（看起来没事）。
2. **量级自检**：换手率、投入率、买得起率这三个量，**各自都有一个「物理上界」**
   （换手率 ≤ 100%/年 × 常数、投入率 ≤ 1、买得起率 ≤ 1）⇒ 出了界就是**读法错了**，不是**世界变了**。
