## §1 口径（预注册 · 定义层 · 外部锚）

| 量 | 定义 | 外部锚 / 理由 |
|---|---|---|
| **本金** | `capital = 50_000` 元 | 用户原话「我有5万块钱」 |
| **满仓** | `equity_weight = 1.0` | `aplus/backtest.py` 的生产实测口径 |
| **涨腿名数** | `n_positions = 10` | D1 交付契约（「各10个」） |
| **目标** | `net_target = 0.20` | 用户原话「年化收益20%」 |
| **年摩擦** | `aplus.costs.annual_friction(...)`，**返回**占**本金**的比例 | ⚠️ 它算的是**占本金**，不是占权益 ⇒ 不得与「占权益」口径并列 |
| **所需毛超额** | `aplus.costs.gross_needed_for_net(...)`，返回占**权益**的比例 | ⚠️ 与上一行**不是同一个分母**（[[a-ratio-whose-two-halves-count-different-things]]） |
| **年化常数** | `aplus.hurdle.DAYS_PER_YEAR`（实测 **244**） | 🚨 仓里另有 **250**（`costs.TRADING_DAYS_PER_YEAR`）与 **252**（`PREREG_PORTFOLIO_NAV`），**三个不是同一个量** ⇒ 本文件只用 `hurdle` 的那个 |
| **费率** | `aplus.costs.FeeSchedule()` 的默认常量 | 万三佣金 / ¥5 最低 / 印花税 0.05% 单边 / 过户费 0.001% 双边 / 价差 0.15% 单边 |

⇒ **本文件不许重写成本公式。** 全部数字由**调用** `aplus.costs` 得到
（照 `measure_basket_nav_01.py` 的做法：只调用 + 落盘 + 盖章）。

### §1.1 机制（为什么这个数字这么大）

单笔名义额 `= 50_000 × 1.0 / 10 = ¥5,000`
< `COMMISSION_MIN_BINDS_BELOW = 5.0 / 0.0003 = ¥16,666.67`
⇒ **每笔佣金吃满 ¥5 固定额** ⇒ 实际费率 `5/5000 = 0.1000%`，
是名义费率 `0.030%` 的 **3.33 倍**。

⇒ **这是「5 万本金 + 10 只 + 日频」三者的联合后果，不是费率表的问题。**
把名数降到 3（每笔 ¥16,667）才会脱离最低佣金，摩擦从 134.69% 降到 100.53%
——**仍然 > 100%**，因为**每天换仓本身**就不可行。

## §2 换手测量口径（预注册 · 定义层）

### §2.1 为什么必须测换手，而不是假设 100%

`FeeSchedule.rebalance()` 的语义是「**10 只全部换手**」。
若实测名单大面积重叠，真实换手远小于 10 只全换 ⇒
**直接引用 `annual_friction(..., rebalances_per_year=244)` 会高估摩擦。**
⇒ 必须先测。

### §2.2 🚨 观测单位 = `entry_date`，**不是** `pred_date`

**这是本文件最贵的一处口径，必须单独写死。**

实测 `verification.parquet`：6 个 `pred_date` 只对应 **4** 个 `entry_date`
—— 10-09 / 10-10 / 10-11 三天的单**全部 entry 到 `2026-10-12`**，
持有的是**同一批 bar**。

⇒ **按 `pred_date` 相邻对算换手会把不存在的成交算进去。**
（本文件作者第一版正是这么算的，得 82.0%；按 `entry_date` 重算是 **73.33%**。）

⇒ **实测规则**（写进守卫）：
1. 只取 `direction == 'up'` 的行（跌腿不可执行，`news_overlay` 只接 `up.head(10)`）；
2. 每个 `entry_date` 取该日**最新的 `pred_date`** 那一份名单 = 真正被撮合的；
3. 换手按**相邻 `entry_date`** 之间算：`τ = |新名单 − 旧名单| / 10`；
4. **首个 `entry_date` 不参与**（无前仓可换）。

⚠️ 该规则**结构性地**漏掉「同一 `entry_date` 内换了几次单」——
但那几次**没有产生额外成交**（同一批 bar、同一批可成交量），
所以漏掉它们是**对的**，不是缺陷。

### §2.3 🚨 合成口径：单边换手只乘**一次**

`FeeSchedule.round_trip(notional)` = `buy + sell`，**已含双边**。

而 §2.2 测出的 τ 是**单边**换手（新买占比），每个换掉的名字付**一个** `round_trip`
（卖旧 + 买新在同一轮里）。

⇒ 成本对 τ 的依赖：每轮 `= τ × Σ_names round_trip(per)`，
其中 `per = 50_000/10 = ¥5,000` 对**每个名字相同**
⇒ **这个和式对 τ 严格线性**（最低佣金的非线性已在 `commission()` 里按笔吃掉，
不会在聚合时翻回来）。

⇒ 等价于 `rebalances_per_year → 244 × τ`。
🚨 **不是** `244 × 2τ` —— 乘 2 是**重复计一次双边**（[[k-is-not-a-window-rate]] 的族：
合成两个口径时每一项都要问「这一项量的是哪一边」）。

## §3 判决规则（🚨 **补记** · 门槛由 §1 外部锚推导，不写字面量）

### D1 🚨 本判决**不需要 MDE**

理由由**规则的代数形式**唯一决定，不由数据决定：

> 摩擦是**已公布费率**的确定性算术（万三 / ¥5 / 0.05% / 0.001% / 0.15%），
> 换手是从**底稿**数出来的计数。两者都不含随机成分
> ⇒ **没有「样本量不足」这一格**，也就没有 MDE。
>
> 这与 `basket_nav_01` 的 `|c| < M ⇒ 连符号都定不了` 是**相反**的情形：
> 那里的读数是**随机变量**的估计，这里的读数是**确定性函数**的值。
>
> ⚠️ **不许把「确定性」读成「可靠」** —— 它的失效模式是
> **费率表错了**或**换手测错了**，而这两者都由守卫钉，不靠样本量兜底。

### D2 三档判决（**顺序即判据**，按严厉程度降序）

| 档 | 条件 | 含义 |
|---|---|---|
| `SINGLE_SIDED_UNREACHABLE` | 交付形态年摩擦 **≥** 目标 | 🚨 **单边不可达**（D1 ⇒ 无需 MDE） |
| `OVER_TARGET_BUT_NOT_SEALED` | 摩擦 **<** 目标但 > 0 | 未封口，仍需毛超额 ≥ `gross_needed_for_net` |
| `NOT_SEALED` | 摩擦 ≤ 0 | 结构异常（摩擦恒 > 0，见 [[a-plus-friction-has-positive-floor]]） |

### D3 🚨 判决必须挂在**实测换手的整个区间**上，不是点估计

τ 只有 **3** 次调仓的样本 ⇒ `τ = 0.7333` 是**点估计**，按
[[unmeasurable-point-estimate-only-supports-shape-claims]] 不可引用。

⇒ 产物必须**并排**给出：
- τ 的点估计（标 `role = 点估计`，**不进判决**）
- τ 的**实测最小值**与**最大值**（**判决只用这个区间**）
- 区间两端的摩擦，以及**反解出的「要让摩擦 ≤ 目标所需的 τ」**

⚠️ **判决条件是 `区间下端的摩擦 ≥ 目标`** —— 即「**即便取实测最省的那一档**，
摩擦仍然 ≥ 目标」。这是**最弱**的要求，因而最稳。

## §5 守卫清单（🚨 **补记**，不冒充预注册）

| # | 守卫 | 钉住哪一层 |
|---|---|---|
| G1 | 摩擦对 τ **严格线性**（`f(0.5τ) == 0.5·f(τ)`，相对差 ≤1e-12） | §2.3 的合成口径 |
| G2 | 换手观测单位**必须**是 `entry_date`；按 `pred_date` 算必须给出**不同**的数 | §2.2 |
| G3 | 单边换手只乘**一次**（`f(τ) < f(1.0)` 且 `f(τ) == f(244τ/244)`） | §2.3 的「不乘 2」 |
| G4 | 判决**必须**取区间下端（`min` 档），不是点估计 | D3 |
| G5 | 产物**必须**同时含点估计与区间，且点估计**不得**进判决字段 | D3 |
| G6 | 年化常数**必须**取自 `aplus.hurdle`，不许字面量 `244` | §1 |
| G7 | 缺上游键必须 `KeyError`，不许 `.get(默认值)` | 分支 D_NO_DATA |
| G8 | 「每笔实际费率 = 名义费率」在 `per < 阈值` 时**必须**不成立 | §1.1 的机制 |

⚠️ **G8 是唯一一条能在「费率表被改成正确」时变红的守卫** ——
若有人把 `COMMISSION_RATE` 调到让 ¥5,000 落在比例段，摩擦会掉到 ~40%，
判决档**从 `SINGLE_SIDED_UNREACHABLE` 变成 `OVER_TARGET_BUT_NOT_SEALED`**。
⇒ **那不是守卫坏了，是费率表真的变了**，而那必须是一次显式的口径决策
（§1 的锚会失效）。守卫的作用是**让那次变更响**，不是**禁止它发生**。
