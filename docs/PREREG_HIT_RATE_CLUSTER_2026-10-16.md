## §1 缺陷陈述（不是猜测）

`hit_rate_diagnosis.json` 的每一个推断量（`ci95` / `z` / `p_two_sided`）
都是把**交易行**当独立观测算的。实测：

- up 腿 45 行 → 只有 **3 个**独立成交窗口；
- 29 行同窗（`run_daily.py:290-293`：周五/六/日三次出名单落到同一个成交窗口）。

⇒ 行与行之间**不独立**（同一窗口内的行共享同一次开平仓的价格路径），
把它们当 45 次独立抽样 ⇒ **标准误被低估 ⇒ 区间被压窄**
⇒ 把「测不出方向」显示成「边缘显著」。

## §2 独立样本单位

> 🚨 **独立样本单位是「成交窗口」，不是「交易行」。**
> 一行 = 一只票的一次判定；一个窗口 = 一次开仓→平仓的价格路径。
> 同一个窗口里的行共享同一段行情，因此它们之间**不是独立重抽样**。

## §3 判据（改法在看新数之前定死）

### C1 聚类键 = `exit_date`，不是 `pred_date`

| | |
|---|---|
| **为什么是 `exit_date`** | 它是**收益真正实现的那一天**，与 `aplus/verify.py::daily_portfolio_returns`（`day_col` 那段）**同口径** ⇒ 两个产物不会各算各的 |
| **为什么不用 `pred_date`** | `pred_date` 是**出名单**的那一天。实测周五/六/日三次出单落到同一个 10-12→10-13 成交窗口 ⇒ 按 `pred_date` 分组会把**同一天的三个篮子**当成三天独立观测 |
| **缺 `exit_date` 的历史行** | 退回 `pred_date`，并加 `legacy:` 前缀**单独成组** ⇒ 绝不与真窗口混组，也绝不整段丢掉（那等于抹掉上线以来攒下的全部证据） |

### C2 聚类口径的区间怎么算

- **点估计不变**：`rate = Σhits / Σn`（行级合并，**不是**窗口率的简单平均）。
  ⚠️ 每窗口 n 不等 ⇒ 简单平均与合并率**不是同一个量**，
  产物必须把简单平均**单列**并标注「**这不是整体命中率**」，且它**不进判决**。
- **独立观测数由行数换成窗口数**：`se = sqrt(p(1−p)/W)`，`W` = 窗口数。
- **这是对现有公式的唯一改动**：分子分母、`p`、临界值全部不变，
  只有 `n → W` ⇒ 两个口径的差**全部**归因于聚类这一个变量，可逐位对账。
- **W < 2 ⇒ 拒绝出区间**（`ci95 = null`）。一个窗口估不出窗口间方差，
  返回 `[0,1]` 或 `[p,p]` 都是「看起来有结论」的假象（第 0 层的 0/0 教训）。
- ⚠️ 这个区间是**保守方向**（偏宽）：它把整窗当成一次抽样，
  **完全丢掉**窗内 29 条的信息。方向写在这里，是因为
  「过严的守卫/尺子会把人推向去改本来正确的代码」（第 112 层）。

### C3 🚨 行级 CI 必须**并排保留**，不许删

- 产物里每一个块的 `ci95`（聚类口径）与 `ci95_row_level`（行级口径）**必须同时存在**。
- 行级那一个必须带标注：**「被窗口叠加虚增」**，
  并落盘 `inflation_factor`（两个半宽之比）供逐位对账。
- **不许删掉**：读者需要看见两个口径差多少；只留聚类口径会让后人对
  历史文档里的 14.6% 无从对照，反而制造第二个「找不到出处」的数。

### C4 🚨 MDE 必须与点估计**并排印出**

- `mde_rate_points = (z₀.₉₇₅ + z₀.₈₀) · se_clustered`，与 `rate` 同块落盘。
- 同时落盘 `abs_gap_to_50pct` 与 `gap_over_mde = |rate − 0.5| / MDE`。
- **`gap_over_mde < 1` 时必须携带**「连符号都定不了，只支持『测不到』这类形状陈述」
  这句标注；缺了它就是把「测不出」说成「没有」（第 16 / 160 层）。
- 🚨 **任何「不显著」不许单独出现**（本仓铁律）。

### C5 措辞

- 禁「达标 / 未达标 / 过关 / 及格」一类**交付式**措辞；
- 禁把「不显著」写成「没有 alpha / 没有超额 / 已证伪」；
- 证据强度必须分级：窗口数 < 2 写「不可估」，< 10 写「薄」。

### C6 判据不许随数改

- 窗口键、SE 公式、MDE 的临界值、措辞表，**全部在 `diagnose_hit_rate.py` 里写成常量**，
  不许由数据反推（`docs/TODO_factor_width_2026-10-15.md` 第 145 层的教训：

第一版 G6（产物层）有三条守卫，全部读 `half_width`：

| 洞 | 形态 | 为什么第一版抓不到 |
|---|---|---|
| **A** | 把 `ci95` 换成行级那一个、`half_width` 留在聚类值上 | 读 `half_width` 的守卫全绿，而**读者读的是 `ci95`** ⇒「两个字段都在」≠「它们说的是同一件事」 |

⇒ 三条**正交**的补丁（G7/G8/G9，2026-10-16 落盘）：

- **G7** `ci95` ↔ `half_width` **互为对账**：`ci95 == clip(rate ± half_width)`，

  ⇒ 堵 A。**半宽必须单列成一个字段**正是因为截断把 105% 变成 100%，
  `ci95` 反推不出真半宽。
- **G8** 半宽比恒等式 `hw聚类 / hw行级 == sqrt(N / W)` 在**落盘产物**上重跑一次。
  ⇒ 堵 B 的前半（口径整体回退）。
- **G9** 🚨 **对账守卫**：从 `verification.parquet` **重数一遍**成交窗口，
  与产物的 `n_windows` 比对。⇒ 堵 B/C 的后半：判「这个数是量出来的」，
  而不是判「产物自己跟自己对不对得上」（第 118 层）。
  ⚠️ parquet **不入库** ⇒ 缺它时 `pytest.skip` 并写明理由；
  **skip 与「通过」在门禁输出里长得一样**，所以理由必须落在代码里。
