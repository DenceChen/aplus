# 预注册：安慰剂对照 —— 「t=2.44」是因子，还是一个差基准？

**状态**：预注册已写死，**安慰剂尚未运行**。
**写入时间**：2026-10-15，在看到任何安慰剂数字之前。
**触发原因**：榜宽实验主档 N=200 给出分块 t = 2.44（> t_crit 1.96）。

---

## 1. 为什么要立刻做这件事（不是「以后有空再说」）

榜宽实验（`docs/TODO_basket_width_2026-10-15.md`）在 N=200 给出：

```
毛超额 9.46%/年 ｜ 分块 t = 2.44 ｜ 独立观测 66 ｜ σ实测/σ理论 2.99x
```

这是**全项目第一次出现统计显著的涨腿超额**。也正因为是第一次，
它最可能不是第一次。

### ★ 一个不需要任何 bug 就能产生 t=2.44 的解释

`N=200` 是全池（约 4000 只可交易）里的 **5%**。基准是**等权全市场**。

> **H_benchmark**：等权 A 股池是个**结构性偏差**的基准 ——
> 大量小市值、低流动性、长期停牌附近的票把它往下拖。
> 于是「持有任意 200 只 + 按 score 排序」都能显著跑赢它，
> **与 score 是否有信息量无关**。

**H_benchmark 不需要任何 bug，只需要「等权池 ≠ 有效市值加权池」这一个事实。**
而这个事实在中国市场是众所周知的。

⇒ **在这个替代假设被排除之前，「因子有效」这句话一个字都不能写。**

## 2. 安慰剂臂（三个，都必须跑，全部报告）

| 臂 | 做法 | 检验什么 |
|---|---|---|
| **P0 观测** | 原样，N=200，按 composite_score 排序 | 已知：t=2.44 |
| **P1 打乱 score** | 在**每个横截面内**对 composite_score 做**随机置换**，再取 top 200 | 若 t(P1) 仍高 ⇒ **H_benchmark** |
| **P2 打乱名单** | 不排序，直接在当日可交易池里**随机抽 200 只** | 最粗的对照：连排序都去掉 |

### ★ 为什么 P1 必须是「横截面内置换」而不是「整体打乱」

- 横截面内置换保留了**每日池子的成分构成**、停牌分布、流动性分布、
  以及 score 与这些的相关性结构；它只摧毁「score 把好票排在前面」这件事。
- 整体打乱会把日期结构也毁掉，测的就不是同一个东西了。
- **置换必须在每个日期独立做**，用固定种子（`PLACEBO_SEED`），
  否则不可复现，而不可复现的阴性结果等于没跑。

### 随机基线不是可选的

`scripts/evolution_race` 的历史注释里已经记过一次教训：
「**30 组随机权重里也有 1 组能过闸**」。⇒ 单个随机臂不够，
**必须报告随机臂的分布**，否则「1 个 placebo 恰好也很高」和「placebo 系统性偏高」分不开。

| 项 | 值 |
|---|---|
| `PLACEBO_SEED` | 20261015 |
| `N_PLACEBO_REPS` | **20** |
| 每个 rep 独立种子 | `PLACEBO_SEED + rep` |
| 必须报告 | 20 个 t 的 **min / 中位数 / max**，以及 **≥ P0 的个数** |

## 3. 判决分支（**看到任何安慰剂数字之前**写死）

**主档仍是 N=200、K=21、窗口 2021-01-01 起**（全部沿用榜宽实验的预注册，一字不改）。

| 分支 | 条件 | 含义 |
|---|---|---|
| **`PLACEBO_PASSES`** | `t(P0)=2.44` > P1 的 **max** | 因子确实排序。**这是唯一允许写「因子有效」的分支** |
| **`PLACEBO_BENCHMARK`** | P1 的中位数 ≥ **1.96** | 🚨 **测的是差基准，不是因子。** 榜宽实验的「显著性」全部作废，必须换基准重测 |
| **`PLACEBO_MIXED`** | P1 中位数 < 1.96 但 ≥ 1 个 P1 ≥ 2.44 | 边缘。**不许报喜**，只记录，且需要更多 rep 才谈得上判断 |
| **`PLACEBO_NULL`** | P1 全部 < 1.96 且 max < 2.44 | 干净的阴性对照。此时 P0 的 2.44 才可信 |

#### 🚨 修订 1（2026-10-15，落地时发现，**补录而非改判据**）

上表有**两个**自身缺陷，都在写完预注册、被实现第一次读出来时才暴露。
两条都**只改「怎么读表」，不改任何阈值**——阈值是判据，动它就是作弊。

#### (a) ★ 四条条件**不互斥**，而「谁压过谁」从来没被声明过

第一版修订只发现了一条不互斥（`NULL ⊆ PASSES`），**不完整**。
穷举 40000 组 P1 分布（`t(P0) ∈ [−1,5]`、20 个 rep）实测**恰好两组同时成立**：

| 同时成立 | 次数 | 谁能压谁才对 | 为什么 |
|---|---|---|---|
| `NULL` ∧ `PASSES` | 557 | `NULL` 在前 | `NULL ⊆ PASSES`，`PASSES` 是更弱的话（只说 P0 比随机高，没说随机自己就不显著） |
| **`BENCHMARK` ∧ `PASSES`** | **284** | 🚨 **`BENCHMARK` 必须在 `PASSES` 之前** | 见下 |

🚨 **第二条是第一版修订漏掉的，而它比第一条严重得多。**
`PLACEBO_BENCHMARK` 的含义是「**测的是差基准，不是因子；榜宽实验的显著性全部作废**」——
它是最响的警报。`PLACEBO_PASSES` 是**唯一允许写「因子有效」的分支**。
⇒ 两者同时成立时若让 `PASSES` 赢，**284 例「安慰剂中位数已经 ≥ 1.96」会被判成「因子有效」**。

⇒ **失败模式是不对称的**：让好消息压过坏消息，代价是不对称的 ——
压对了只是多花一次重测，压错了整轮结论作废而没人知道。

**修订（最终版）**：
1. 四条分支的条件**各自独立求值一次**，四个布尔值**同时写进产物**
   （读者能看到「哪几条同时成立」，不会只拿到一个标签而丢掉信息）。
2. **求值顺序按结论的严厉程度降序**，明确写死为：
   `BENCHMARK`（全盘作废）→ `MIXED`（边缘，禁报喜）→ `NULL`（干净对照）→ `PASSES`（最好听）。
3. 🚨 **预注册的表格行序不得被实现继承成优先级。**
   表格是给人读的，行序没有语义；本文件的第一版实现正是默认继承了行序，
   于是 284 例警报被静默吃掉。**顺序必须单独声明，并在守卫里钉死**
   （`test_the_branch_order_is_the_conservative_one`）。

⇒ 这与第 88 层（判决分支不可达）同族，但更靠前一层：
**不是某个分支进不去，是分支之间的优先级根本没被当成判据写下来。**

#### (b) `2.44` 钉在一个会被删掉的产物的字段上。
2.44 来自**旧的** `factor_width_mde.json`，而那个产物已在 P0 修复时删除重跑
（它的 `annual_sd_pct` 带着 `×T` 的错，旧档位整份作废）。
`t_blocked` 本身**不受那两个修复影响**（它直接由日频序列算出，不经过 `annual_sd_pct`，
也不经过成本链 —— 宽榜实验的 `series` 是**毛**超额序列），
所以 2.44 这个数本身站得住；但**「它被写死在一个已被删除的产物里」这件事站不住**。

**修订**：判决阈值 `t(P0)` 由本脚本的 **P0 臂实测**（同一条代码路径），
产物与报告**必须打印这个实测值并与 2.44 并排**；
榜宽产物只作**可选交叉核对**，缺档即 `null`，**绝不允许猜一个数填上**。
🚨 若实测 `t(P0)` 与 2.44 不一致 ⇒ 停下报告，**不许**为了让分支好看而改阈值。

### ★ 三条不得逾越的规则（与第 91 层同一份纪律）

1. **不得在看到 P1 之后再改 P0 的档位或窗口。** 榜宽实验已把主档钉死为 200。
2. **不得只报对自己有利的那一臂。** 20 个 rep 的分布全部写进产物。
3. **不得把 `PLACEBO_BENCHMARK` 解释成「因子也许还有一点」。**
   若基准有问题，**正确动作是换基准（等权 → 流通市值加权）后整轮重测**，
   而不是拿现有数字减去一点。

## 4. 口径纪律（与前几轮同一份）

- 安慰剂臂必须走**与 P0 完全相同**的代码路径：
  同一个 `run_year`、同一个 `evaluate_weights`、同一个成本链、同一份 `MIN_BASKET`
- **禁止**为安慰剂另写一条更快的路径 —— 那样测的是另一个东西
- 置换在 `build_predictions` 之前作用于 `score` 列，
  **不得**改动 `composite_score` 的实现（那是共享代码，改了就污染 P0）
- 若实现上必须新增一个 `score_override` 参数，
  必须有守卫钉住「`score_override is None` 时逐位等于原行为」

### ★ P1 与 P2 的**池子不同** —— 两条差不是同一个量

落地时才发现预注册没写死的一点：

| 臂 | 置换作用在哪个池子上 |
|---|---|
| **P1** | 与 P0 **同一个池**：因子完整的那些票，NaN **原地不动**，只换顺序 |
| **P2** | **全可交易池**：包含因子不完整的那些票 |

⇒ **`P1 − P0` 与 `P2 − P0` 量的不是同一件事**，不许并排相减、
更不许取平均。产物与报告必须把两者的**池子规模**一并打印
（`n_pool_p0` / `n_pool_p2`），否则两个差值会被读成可比的重复测量。

### ★ P0 与 P1 的 NaN 语义

P1 置换时 NaN **必须留在原地**（不能整列一起搬走）。
理由：搬走了池子就变大变小，`P1 − P0` 立刻变成两个不同池子的差 ——
和上面 P1/P2 的问题是同一族。守卫 `test_placebo_control.py`
用「多重集不变 + 池子不变」两条钉死，不靠子串。

## 5. 这个实验**不能**证明什么

- 不能证明前瞻有效（全样本内）
- 不能证明 20%/年的目标可达 —— P0 的 9.46%/年 离门槛 26.39%/年 差得远，
  **且 200 只 × 250 元/只的形态 5 万本金也无法交付**
- `PLACEBO_PASSES` 只说明「横截面排序有信息量」，
  **不说明这个信息量在扣成本后还剩多少** —— 后者是 K 扫描的事，两者不合并
