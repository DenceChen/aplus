# 2026-10-11 数据事故链：从 +903% 到 +9.84%，再到 +0.27% 和一个 500，一条链上的 13 个缺陷

> 这份文档记录的不是「修好了什么」，而是**一条失效链**：
> 每一个缺陷单独看都不致命，串起来就足以让平台在一天之内
> 既把错误标的送进用户的 5 万块建仓清单，又报出一个 `t = 7.75` 的假 alpha。
>
> 记录它的目的不是留档好看，而是给未来的自己留一条**检查清单**：
> 任何一个新数据源、新因子、新指标进来时，按这张表逐条问一遍。

---

## 0. 一句话结论

那一天平台做的每一件事都是「照着代码写的」，但代码里的每一个口径都各自成立，
合起来却不成立。**没有一条单一的质量指标发现得了它们。**

## 1. 失效链（按发现顺序）

### ① 成交收益用**不复权**价 → 除权日记下从未发生的亏损

`verify_predictions` 一直按 `close / prev_close - 1` 算实际涨跌，而 `close` 是
不复权收盘价。A 股除权除息当天不复权价会**直接跳空**。

全库实测（5447 只，610 万个相邻交易日对）：

- **2623 只**出现 `|不复权比值 − 交易所 pctChg| > 2%` 的日对
- 受影响日对 **11762** 个（占全部 0.193%）
- 最极端：`002594.SZ` 2025-07-29，不复权比值 **−66.94%**，交易所口径 **+0.37%**
  —— 一根 K 线凭空造出 **67 个百分点**的亏损

`data/reports/evolution_race.json` 里那两个 **−27.8% / −20.6%** 的「日超额」
就是这么来的——那不是策略，那是除权。

**修复**：`aplus/adjust.py: hfq_close()`，`aplus/backtest.py: _next_bars` 与
`aplus/verify.py: last_two_bars` 都改用后复权价，**回测与实盘同口径**。
测试 `tests/test_exrights_return.py`（含真实案例回归 + 变异验证）。

> **教训**：主键 `close` 是「看起来最不可能错」的那个字段。
> 「市场实际怎么走」这个语义，必须用**经过公司行动调整**的价格才能表达。

### ② 复权基准未知的时期被**填成 1.0** → 001914.SZ 的 +491% 假收益

`attach_factor` 用 `merge_asof(backward)` 贴因子事件，首事件之前按 **1.0** 填充。
当首事件因子本来就 >1（重组/借壳/缩股之后基准才重新起算），这个 1.0 是一段
**尺度未知**的历史。

`001914.SZ`（招商积余）实测：

```
日线首根 2019-01-02   close 10.80   因子填充 1.0000
首事件   2019-06-06   close  9.96   因子     6.4111
→ 该日复权收益 = +491.25%
```

该表**单调、无 NaN、无非正值、文件完整**——所有旧判据全部放行。
`scripts/repair_factors.py` 重取后事件数仍是 11 条不变：源站确实只给这些，
早期基准**无法恢复**，只能作废。

**修复**：`adjust.UNKNOWN_SCALE_MIN_FACTOR` + `adjust.is_scale_neutralized`。
基准未知的时期标 NaN（该股自然退出横截面），而不是填一个编造值。
测试 `tests/test_unknown_scale.py`。

> **教训**：旧代码里有一条测试 `test_attach_factor_before_first_event_still_defaults_to_one`，
> 它的夹具**正是**这个残缺形状，还断言「填 1.0 是正确的」。
> 同一份代码里，另一条测试把它认定为「残缺」。两条测试互相矛盾，
> 而被当作规范的是**错的那条**。→ 测试也会固化 bug。

### ③ ST 过滤**对 88.2% 的股票失效** → 用户名单里出现 `*ST岭南`

用户当日推荐名单里出现了 `*ST岭南`（002717.SZ）和 `*ST住亭`（301030.SZ）。
`filter_universe` 的过滤条件是 `isST == 0`，按设计它们本该被剔除。

逐层挖下去：

| 数据状态 | 股票数 | 占全池 |
|---|---|---|
| `isST` 列**不存在**（腾讯备源写入的文件） | 1693 | 31.1% |
| `isST` 列存在但最新值是 **NaN**（`_upsert` 把有列与无列的源 concat 出来） | 3112 | 57.1% |
| `isST` 最新值可用 | 642 | 11.8% |

**合计 4805 只（88.2%）的 ST 状态不可判定。** 而 `panel.cross_section` 把 NaN
一律当 0 ——「不知道」被当成「不是 ST」。

拿独立来源交叉验证（`data/names.json` 的官方简称）：

- 名称含 `ST`/`*ST` 的股票共 **310** 只
- 其中 **178** 只 `isST` 不可判定 → 正在被当作普通股票推荐
- 另有 **45** 只 `isST` 列写着 0 但名称是 ST ——**列本身也是错的**

**修复**：`aplus/predict.py: is_st_name()`，ST 用**两个独立信号取「或」**
（`isST == 1` 或名称前缀 `^(S\*?)?\*?ST`）。绝不能要求两者都说是才剔，
也绝不能要求 `isST == 0` 才保留（那会砍掉 88% 的正常股票）。
测试 `tests/test_st_filter.py`（22 例）。

> **教训**：`isST` 这一列看起来是权威的**布尔字段**。
> 但「缺失」和「否」在这个系统里被同一个 `== 0` 判定吞掉了。

### ④ 因子表体检是**事后告警** → 用坏数据发名单，事后再体检

`data/run_daily.log` 留着这一行：

```
601607.SH 上海医药 score=22.53 mom20=903.72%
002261.SZ 拓维信息 score=21.45 mom20=839.55%
000626.SZ 远大控股 score=18.60 mom20=745.63%
```

20 个交易日涨 **903%** 在真实市场不存在。逐只复算证实：这三只当时因子表是坏的。

同一批坏数据在 **09:07** 的体检里被抓到，**09:08–09:41** 全量修复。修复之后
逐只复算，mom20 最大值回落到 152.8%，>200% 的股票 0 只——**数据本身没问题，
是输入有问题**。

而当时的流水线顺序是：

```
update → verify → predict → alloc → stats → factor_audit   ← 体检在最后
```

`step_factor_audit` 的 docstring 里明确写着「体检**不阻断**主流程（因子坏了也要出预测）」。

**修复**：`scripts/run_daily.py` 把体检提到 `predict` **之前**，
并改成阻断式闸门（`factor_gate_blocks`）。测试 `tests/test_factor_gate.py`。

> **教训**：**后发现的体检挡不住已发出的名单。**
> 而「可用性的正确含义」是「服务能响应」，不是「服务能在输入损坏时编一个答案出来」。

### ⑤ 闸门上线的第一天就被**误报**顶住 → 天天出不了名单

闸门按「1 只即停」上线后立刻失效：`001872.SZ`（招商港口）、`600018.SH`（上港集团）
被判为损坏。它们首事件因子本就 >1（借壳/重组上市，基准在上市日已累积），
但首事件在日线起点**之前**，全程被正确前向填充覆盖，**根本没有 1.0 填充段**。

结果：损坏率 3/5447 = **0.06%**，闸门每天阻断。

**修复**：判据从「因子值是否等于 1.0」改成「**首事件日期是否晚于日线首根**」——
真正要抓的破坏是「`attach_factor` 在早期填了 1.0」，它成立的前提就是
首事件落在日线起点之后。测试 `tests/test_factor_false_positive.py`。

顺带纠正了旧文档的一处**错误判断**：它把 `001914.SZ` 也列为「已知误报」，
实测证明那是真损坏（见 ②）。

闸门最终口径：单只损坏已被两层数据闸中和（② 与 ⑥），≤5 只不拦；
超过 5 只即判定为系统性故障，停机。

> **教训**：一个天天误报的闸门等于没有闸门——它只会被绕过或忽略。
> 而**收紧**判据比放宽更危险：它制造的是「持续拒绝服务」。

### ⑥ ±40% 之外的收益被当成真实成交 → 173 只股票可伪造 alpha

全库扫描复权日收益，**173 只（3.2%）存在 |单日收益| > 25%**，最大 −96.4%：

```
600766.SH  2024-06-05  close 9.84 → 0.35   pctChg -96.4431
600608.SH  2026-06-08  close 2.07 → 0.20   pctChg -90.3382
300029.SZ  2026-06-18  close 3.46 → 0.20
002898.SZ  2026-06-26  close 8.74 → 0.35
```

形态一致：停牌若干日（`tradestatus=0`、`volume=0`、close 冻结）→ 复牌当日
价格掉到零头。前后两根的复权因子**完全相同**（3.7392 → 3.7392），
所以**不是**复权因子没记录，而是源站把一次缩股记成了价格跳空，
连它自己的 `pctChg` 也是按同一对 close 算出来的，不构成独立证据。

**修复**：`aplus/panel.py: MAX_PLAUSIBLE_RETURN = 0.40`，
在**因子层**与**成交层**（`aplus/backtest.py`）同时作废——不是钳制。
钳制会把 −96% 变成 −40%，照样污染均值，并把「数据有问题」永久掩盖。
测试 `tests/test_implausible_return.py`。

> **教训**：A 股真实涨跌停是 ±10% / ±20% / ±30%（北交所）。
> 任何超出这个范围的单日收益都不是「行情」，是「数据」。
> 但**实盘横截面此前一道闸门都没有**——回测有，实盘没有。

### ⑦ 面板把 `last_date` **伪造成预测日** → 退市股进入回测股票池

样本外赛马跑出「惊人」数字：某些候选的多空价差 **+9.84%，t = 7.75**
（日频 9.84% 相当于年化数百倍，且 t 值比任何真 alpha 都显著）。

顺着挖：某日跌篮子 10 只成分里 **9 只早已退市**：

| 代码 | 末根 K 线 | 该日有 bar 吗 |
|---|---|---|
| 301139.SZ | 2026-10-09 | 有 |
| 300799.SZ | **2024-07-26** | 无 |
| 002336.SZ | **2025-07-03** | 无 |
| 300742.SZ | **2024-07-19** | 无 |
| 000622.SZ | **2025-07-15** | 无 |
| 300297.SZ | **2023-07-28** | 无 |
| 002781.SZ | **2023-07-04** | 无 |
| 300089.SZ | **2023-07-12** | 无 |
| 300208.SZ | **2025-07-18** | 无 |

三个环节串起来：

1. `FactorPanel.cross_section` 把 `last_date` 写死成 **预测日本身**
   → `filter_universe` 专门为退市股写的 `max_stale_days=30`
   **完全是空操作**
2. 退市股照常被选中，但没有次日 bar → `actual_pct` 全是 NaN
3. `groupby().mean()` **默认跳过 NaN** → 「篮子平均收益」实际是
   **剩下那一只**股票的收益，再被日度汇总平均

**修复**：
- `panel.cross_section` 返回该股**真实**的末根 K 线日期
- `verify.MIN_BASKET = 3`：`rolling_stats` 报出有效成分数，
  t 检验逐日聚合时丢弃成分不足的日子

测试 `tests/test_stale_universe.py`。

> **教训**：pandas 的 `mean()` / `groupby().mean()` **静默跳过 NaN**。
> 分母会随日子变化，而调用方完全看不出来。
> 一个被自己文档里的过滤器保护不了的过滤器，等于没有过滤器。

### ⑧ 一字涨停**买不进**的交易被记成了收益 → 52% 的超额是假的

这一条不是数据脏，是**回测口径缺了一层现实**。全平台没有任何一处代码判断「这一笔能不能成交」。

发现在真实浏览器里：2026-10-11 的实盘名单，「看涨首选」是
`600825.SH 新华传媒`，二十日动量 **+141.9%**，综合分 7.56。
翻它的日线，2026-09-21 起连续 **9 天一字板**（`open=high=low=close`），
5.84 → 12.53；09-07~09-18 是停牌段（`tradestatus=0`）。
`605303.SH 园林股份` 同样一字板连板。`mom20 = 12.53/5.18 − 1 = +141.9%` **算术无误**——
数据没坏，行情是真的。

但一字板收盘价就是涨停价，全天没打开，**收盘排单进不去**。

窗口 2026-04-09 ~ 2026-10-09，涨篮子 = mom20 排序 top-10，1010 个样本：

| 口径 | 涨篮子日均超额 |
|---|---|
| 全部计入 | **+0.2655%** |
| 剔除「信号日一字涨停」 | **+0.1283%** |

一字板在全市场只占 0.337%，在涨篮子里占 **4.06%**——因子越偏好动量，
越集中地挑中买不进的票。那 41 个一字板样本次日收益 **+3.4058%**，
其余 969 个 **−0.0146%**。

**动量因子的表观超额里约 52% 来自无法执行的交易。**
卖端同理：D+2 若是一字跌停，你也卖不掉。

### ⑨ 停牌股进了涨篮子，且 `tradestatus` 在最新一根 K 线根本不可用

`688146.SH` 收盘价冻结在 389.99 连续多日、`mom20` 算出 **+190%**，
它在停牌；`605577.SH` 冻结在 18.67；`603221.SH` 在 6 个月窗口里
**10 次**进入涨篮子。这些票根本不可买。

停牌日 `volume == 0` 且 `amount == 0`（4 只样本 **100%** 命中），
这是不依赖任何元数据列的可靠判据。**但不能用 `tradestatus == 0`**：

抽样 283 只，看**每只的最后一根 K 线**：

| 字段 | 末根 NaN 比例 |
|---|---|
| `turn` | **69.6%** |
| `isST` | **66.1%** |
| `tradestatus` | **66.1%** |

**三分之二股票的最新一根 K 线元数据是空的**，用 `tradestatus` 判停牌会整批漏掉。

### ⑩ 一次降级写入，在同一时刻污染了 2/3 的股票 → 换手率因子长期只覆盖 40%

按倒数位置统计缺失率（130 只样本）：

| 位置 | close | volume | amount | turn | isST | tradestatus |
|---|---|---|---|---|---|---|
| 倒数第 1 根 | **0%** | **0%** | 66.9% | **70.0%** | 66.9% | 66.9% |
| 倒数第 2 根 | 0% | 0% | 0% | 2.3% | 0% | 0% |
| 倒数第 6 根 | 0% | 0% | 0% | 2.3% | 0% | 0% |

**只有最后一根坏，且 OHLCV 完整、元数据全缺**——这正是腾讯源 7 列输出的形状
（`tencent_frame_to_unified` 只产出 `date/code/OHLC/volume`）。

文件 mtime 取证：`末根 turn 缺失` 的 305 只里 **288 只**、
`无 turn 列`的 60 只里 **59 只**，都写在 **2026-10-10 21 点同一波**。
那是 `bootstrap_history.py` 的运行窗口——baostock 被限流，
`pipeline.py` 的降级分支把腾讯的 7 列数据当正常数据写进了主库（见缺陷 ⑧ 的同源根因），
而 `LocalStore._upsert` 的 `drop_duplicates(keep="last")`
让这些窄行**覆盖掉**已有的 12 列完整行。

后果：`turn20` / `turnratio` 候选只能打 4037–4990 只，
而其他因子能打 4990 只——**不同候选根本不在同一批标的上比较**。

**补数能修数据，修不了这个机制**：`scripts/backfill_gaps.py` 只是绕开 `pipeline.py`，
任何人再跑一次 `bootstrap_history.py`，同样的缺口立刻回来。

### ⑪ 交叉校验用**相对**容差判**绝对量化误差** → 主源的好数据被备源否决，13 只股票从池中消失

`aplus/crosscheck.py` 的容差是 `tol_rel = 1e-4`（**相对** 0.01%），
docstring 写着「跨源实测成交量/成交额 100% 一致 → 严格比对」。

**那条依据只在大成交量上成立。** 腾讯 kline 的成交量按 **100 股（1 手）取整**，
baostock 给精确股数，取整误差上界 ±50 股，于是相对误差随成交量下降而放大：

| 成交量 | 相对误差上界 | vs `1e-4` |
|---|---|---|
| 8,397,166 股 | 6.0e-6 | 通过 |
| 300,000 股 | **1.7e-4** | **不通过** |

全量补数实测：**513 个失配行，最大相对误差 0.0864%，100% 都能被 ±100 股吸收**，
失配行成交量中位数 300,300 股。

后果不是「多隔离几只」：**23 只被隔离，其中 13 只的 master 文件根本不存在**——
它们的数据只在隔离区，等于**从股票池里被静默删除**，任何统计都看不到它们消失了。

修法不是放宽相对容差（那会让真正的价格错配蒙混过关，而那正是这道闸门的本职），
而是给**按手取整的字段**单独加绝对容差：`bound = |a|·tol_rel + abs_tol + 1e-9`。
**价格字段不加**——它们没有量化问题，加了就是纯粹的放松。

### ⑫ 一张图里 4% 的坏点让整页不可用：`NaN` 不是合法 JSON

用户在看板点「回测」，页面全白，`/api/backtest` 返回 **500**：

```
ValueError: Out of range float values are not JSON compliant: nan
```

`daily_series` 里 **485 行有 20 行**的 `down_excess`/`breadth` 是 NaN，
Starlette 的 `JSONResponse` 用 `json.dumps(..., allow_nan=False)`，遇到一个就抛。

函数里明明写了 `if len(down) else None`，看着处理过了。漏的是另一条路径：
**`down` 有行、而 `actual_pct` 全是 NaN 时，`.mean()` 返回的是 NaN 而不是 None。**
判空判的是**行数**，坏点在**值**上。

这也是结构性的、不是数据事故——任何一次「跌腿样本全部无次日 bar」都会触发。
所以防线落在函数自身：算完之后统一 `_finite_or_none`。
顺带钉死语义：**`0.0` 是「恰好持平」，`None` 是「算不出来」，两者不能混。**

### ⑬ 缩尾制造并列 → 排名对极值极端敏感（本轮仍未解决）

`winsorize(WINSOR_Q=0.01)` 每天把约 49 只（4935 × 1%）压到**同一个 99% 分位值**，
形成大量并列，并列后的名次由代码序决定。剔除极端尾部会改变分位点与并列集合
→ 榜单大面积重排：可交易性过滤前后，1200 个涨篮子样本**只重叠 218 个**（换手 82%）。

**任何跨日期、跨候选的排名对比都受此影响**，`evolve_race` 的晋级裁决同理。
修法（用连续分位插值代替硬截断，或在排名里显式打破并列）会改变全部历史结论，
必须重跑，暂未动手。

| ST 状态不可判定 | 88.2%，且当「非 ST」 | 双信号判定，覆盖 100% |
| 复权口径 | 不复权 | 后复权，回测与实盘一致 |
| 退市股进入回测池 | 是（过滤器空操作） | 否 |
| `ivol` 是否用未来数据 | **是（全时间轴）** | 否（逐日序列） |
| 涨篮子日均超额 | +0.1965% | **−0.0067%** |
| 赛马裁决 | — | 31 组候选，晋级 **0** 组 |

**没有一组权重被晋级。** `data/reports/weights.json` 不存在——这是正确的结果。

### 超额从 +0.1965% 变成 −0.0067%：为什么这是进步

那天最刺眼的数字不是 `t = 7.75` 的假 alpha，而是这个：

可交易性过滤上线后，涨篮子的日均超额从 **+0.1965% 掉到 −0.0067%**。
查下来 **52% 的超额来自根本买不进的交易**——一字涨停、停牌。
收盘价就是涨停价，排单进不去；回测却把它当成一笔已成交的盈利。

一个只记录「提升」的台账会把这一天记成灾难。
它不是灾难，是**账本第一次跟现实对上了**。

> 同类问题还有：缩尾硬 clip 让 Top10 内部并列 9 个（排序退化成按股票代码取前十），
> 交叉校验容差让 13 只股票从池子里静默消失，`/api/backtest` 直接 500。
> 修复它们的共同点是——**数字都会变差**，但坏数字正在消失。

### 第 14 号缺陷：`ivol` 的全时间轴前视泄露（性质最严重）

```python
# aplus/panel.py  _factor_series 末尾，原文
out["ivol"] = ivol_series(r, m).iloc[-1] if len(m) else np.nan
```

`r` / `m` 是**全历史**序列，`ivol_series` 返回**全历史**序列。
`.iloc[-1]` 取的是**数据末端（2026-10-09）的 ivol**，
再由 pandas 按索引把标量广播给窗口内**每一天**。

**等于说：回测里 2024-10-01 那天的 ivol，用的是 2026-10-09 的数据算出来的。**

它比这一天其他所有缺陷都严重，原因有三：

1. **不崩、不报 nan、不产生 inf**。每一列都有数、都有区分度、横截面看起来完全正常。
2. **其他 7 个因子都通过了泄露测试**，只有 `ivol` 这一个是逐点序列，
   而它是唯一被 `.iloc[-1]` 处理过的——所以「7/8 通过」并不能说明平台无泄露。
3. **它污染了当天的核心结论**：2 年终裁第一名 `{ivol: -1.0}`（t=+0.91）
   与频率赛马 t=2.32 的 `{ivol: -0.3}` **全部作废**。

抓到它的测试形状只有一个：**把 D 之后的数据改成天荒地老，看 D 的因子变不变**
（`tests/test_backtest.py::test_panel_respects_as_of_no_future_leak`）。

而且那条测试一开始也**没抓到 ivol**，因为它跑在 `_populate` 造的
「每日恰好 +1.2%」的确定性单调序列上——波动率恒为 0，
vol20/ivol 全是 1e-17 量级的浮点尘埃，「变了」和「没变」在数值上无法区分。
**泄露测试跑在退化数据上，等于没跑。**
（`tests/test_ivol_no_leak.py` 因此自带 `_fixture_is_non_degenerate` 前置断言。）

### 第 15 号缺陷：退化序列报出 `t = 3.1e16`，且**显著性硬闸拦不住**

```python
# aplus/evolve_race.py::_tstat，原文
sd = float(daily.std(ddof=1))
if not math.isfinite(sd) or sd <= 0:      # ← 这一支从未成立过
    return None, n
return float(daily.mean() / (sd / math.sqrt(n))), n
```

意图在，`breadth_tstat` 的注释早就写明「标准差为 0 时必须返回 None……
那正是当初『30 组随机权重里也有 1 组能过闸』的同类陷阱」。

**但护栏从未落地**：pandas 的 `std(ddof=1)` 对常数序列返回的是
**3.5e-18 而不是 0**（浮点累加误差），于是 `sd <= 0` 永远不成立。

实测：`pd.Series([0.02]*30).std(ddof=1) = 3.51e-18`，
`t = 0.02 / (3.51e-18/√30) = 3.10e16`。

一个**完全测不出差别**的序列，凭空报出一个能闯过 Bonferroni 显著性硬闸的巨大 t。
760 个测试全绿，没有任何一条测到这个形状。

修法：判据从 `sd == 0` 换成**变异系数**——
`sd <= |mean| * 1e-12` 一律判「无法测量」返回 `None`。
（`DEGENERATE_CV`，回归测试 `test_constant_series_returns_none_not_a_huge_t`。）

**教训**：注释里写了意图 ≠ 代码实现了意图。
`sd <= 0` 这种判据在任何浮点统计量上都要先问一句「它真的会触发吗」。

### 第 16 号缺陷：低频候选的 t 值按**假样本量**算

2019-01 ~ 2023-12 独立验证（962 个交易日）的频率对比表，
毛超额几乎不动、t 却一路涨：

| 纯反转 `{mom20:-1.0}` | 年成本 | 年毛超额 | 逐日 t |
|---|---|---|---|
| 日频 K=1 | 246.3% | +77.4% | 6.32 |
| 周频 K=5 | 98.2% | +92.8% | 8.01 |
| 月频 K=21 | 35.8% | +113.4% | 9.19 |
| 季频 K=63 | 12.2% | +117.9% | **11.17** |

K 日调仓时，一天里「选了谁」在 K 天内**不变**。
把 K×n 个交易日当成 K×n 个**独立观测**，等于把同一个决策数了 K 遍。

修法：`excess_tstat` / `breadth_tstat` 收到 `rebalance_every`，
把逐日序列切成**互不重叠的 K 日整块**、块内取均值、对块均值做 t 检验。
尾部不足一整块的零头丢掉（不满的块均值方差更大）。
`block=1` 逐位等于老行为，历史结论不受影响，有测试钉死。

**实测虚高倍数（`data/reports/frequency_block_t_2019_2023.json`）**：

| 候选 | K | 独立观测（块） | t_daily | t_block | 倍数 |
|---|---|---|---|---|---|
| 纯反转 | 1 | 1154 | 6.32 | 6.32 | 1.00 |
| 纯反转 | 21 | 53 | 9.19 | 6.81 | 1.35 |
| 纯反转 | 63 | **18** | 11.17 | **6.76** | 1.65 |
| 反转+风控 | 63 | **18** | 13.12 | **6.46** | 2.03 |

**理论上界是 √K（K=63 → 7.9 倍），实测只有 1.0–2.0 倍。**
差在哪儿：逐日序列里还留着个股噪声，块内平均把它抹掉了一部分，
所以没有顶到最坏情况。**我事先担心的虚高被数据推翻了一半**——
缺陷是真的，但危害比我预估的小，**照实记下来**。

结论「反转 + 低频显著为正」**扛住了修正**（t 仍 6.76 > Bonferroni 临界）。

顺带撞见一条更硬的东西：**现任 K=63 的 t_block = +4.03 是正的，
广度 t = −2.10 是负的**。涨腿超额为正而多空价差为负，
说明那个超额是**大盘 beta 而不是排序能力**——
正是 `breadth_tstat` 当初被造出来要抓的东西。

### 第 17 号缺陷：候选池里没有「执行方式」这一维，现任只按权重认

独立验证给出同一组权重 `{mom20:-1.0}` 的实测：

    日频净 −168.9%   周频 −5.3%   月频 +77.6%   季频 +105.7%

**276 个百分点全部来自 `rebalance_every` 这一个参数。**

而 `candidate_weights` 只产出权重、`oos_decision` 只看得懂权重。于是：

- 赛马永远在「已知不可行的执行方式」（日频）下比较信号强弱
- **日频下任何权重都是负的**（现任净 −478.8%），比较本身没有区分度
- 「先修权重还是先调频率」这个真正的问题，**根本没被问出来**
- 实盘 `run_daily.py` 也没有频率概念，每天从零选 Top10 全换

**测得再准也落不了地。**

同时 `oos_decision` 用 `r["weights"] == champion_weights` 认现任：
候选池一加入频率，同权重的月频行就会**冒名顶替**日频现任，
在裁决里坐现任的席位。

修法：候选升格为三元组 `{weights, rebalance_every, buffer_multiple}`
（`aplus/evolve.split_weights` / `candidate_key` / `dedupe_candidates`），
现任按**三元组**认，去重也看三个字段。
带频率的候选遇到 5 参 evaluate **当场报错**——
静默忽略等于把月频候选当天频跑，数字与实盘不符且看不出来。

候选池从 14 组涨到 **84 组**（14 权重 × K∈{1,5,21,63} × 缓冲）。
缓冲只在 K∈{1,5} 上跑变体：实测 K=21 成本 35.8%→35.4%、K=63 12.2%→12.1%，
**跑那两格不是省算力，是跑实测已知的无效格子**。

### 第 18 号缺陷：独立验证表里有 **8 行建立在空股票池上**

`data/reports/reversal_freq_2019_2023.json` 的 `反转+低异常换手`
（`{"mom20": -0.5, "turnratio": -0.5}`）8 行，`n_ranked = 0`。

`turnratio` 这一列在 2019-2023 **根本不存在**，那 8 行——包括当时
被当成「净收益最高 +114.5%」的那一行——建立在一个**空股票池**上。

它之所以能被当成结论，是因为这张表只打印了 `cost / 超额 / 净 / t`，
`n_ranked` 那一列排在最后，没人会先看它。
新的 `_verify_freq_block_t.py` 已把它从候选池剔除，并在输出里保留
`n_ranked` 以便再次核对。

**教训**：一张表里最该先看的列，往往是排在最后的那列。

### 第 19 号缺陷：门槛按 84 组校正，被检验的却只有第 1 名

```python
best = table[0]                                   # 只看训练段第一名
...
n_cmp = int(significance_lookup) if significance_lookup else len(table)   # 按全部 84 组
```

复合赛马（84 组）跑完后的实际数字：

| K | 训练毛超额 | 训练命中率 | 训练目标分 | 有效观测 |
|---|---|---|---|---|
| 63 | 0.19% | 50.4% | **0.691** ← 第 1 名 | 3 |
| 1 | 0.15% | 52.5% | 0.672 | 194 |
| 5 | 0.08% | 52.1% | 0.606 | 38 |

**毛超额几乎一样**（0.19% / 0.15% / 0.08%），排名差距几乎全部来自命中率。
而命中率在 K=1 与 K=63 之间**根本不是同一个量**：
`objective = 100×毛超额 + 命中率`，K=1 的命中率问「明天涨没涨」，
K=63 问「这 63 天涨没涨」。**第一名是被一个跨频率不可比的量选出来的。**

更根本的问题是自相矛盾：**Bonferroni 门槛按 84 组算，
而被检验的只有 1 组**——被校正的比较里有 83 次根本没发生。
这不是「保守」，是门槛与被检验对象不一致。

修法：按训练目标分顺序**逐个**过闸，命中第一个全过的即晋级；
门槛一个字没改，只是让被检验的对象与被校正的对象一致。
结果里新增 `examined` 字段，如实报告检查了几组。

**这不是放宽挑选**：Bonferroni 的作用本来就是让「84 组里扫一遍挑最好的」
有可控的假阳性率（本次 84 组 → 临界 3.16）。
2026-10-11 21:15 的 2 年窗口上，**扫描前后都是 0 晋级**，
可见这一修正在那个窗口里不改变结论，只在其他窗口里不让好候选被漏掉。

## 3. 给下一个人的检查清单

新增数据源 / 因子 / 指标时，逐条问：

1. **这个字段在「缺失」和「为否」时，返回的是同一个值吗？**
   （`isST` 的教训：88.2% 的缺失被当成「不是 ST」）
2. **公司行动（分红、送股、缩股）在这条路径上会发生什么？**
   （不复权价的跳空是 +67 个百分点的假亏损）
3. **填充值是「无信息」还是「编造」？**
   （`attach_factor` 的 1.0 填充造出了 +491%）
4. **静默默认值是什么？它偏向乐观还是悲观？**
   （交易成本默认 0 会让任何漏传 cost 的调用方拿到「策略有 alpha」）
5. **`.mean()` / `groupby().mean()` 的分母是多少？会随时间变吗？**
   （9/10 成分缺失时的「篮子均值」）
6. **这个判据的**误报率**是多少？每天会误报几只？**
   （0.16% 的借壳股误报，在只统计不阻断时无害，在闸门上致命）
7. **体检在流程的哪一步？发现问题时，产物发出去了吗？**
   （08:53 发名单、09:07 才体检）
8. **这个指标的量纲是什么？多离谱的数会被当成「好结果」？**
   （+9.84% 的日频价差，t = 7.75）
9. **做变异测试**：故意把修复改坏，确认测试会红。
10. **随机对照**：任何「正的超额」都要问一句——随机权重能不能得到同样的数？
11. **这一笔交易在现实中成交得了吗？**
    （一字板收盘买不进；停牌股不在池子里；卖端一字跌停同样卖不掉）
12. **我依赖的那个字段，在最新一根 K 线上真的存在吗？**
    （`tradestatus` 在 2/3 股票的最新一根上是 NaN——凡是以它为判据的过滤，
    都在最新的、也就是最关键的那一天上静默失效）
13. **不同候选池打的是同一批股票吗？**
    （`turn` 缺失让含换手率的候选只覆盖 4037 只，其他覆盖 4990 只，
    排名因此不可比——而这个警告写在日志里，不在判决条件里）
14. **算出来的聚合量可能是 NaN，而 NaN 不是合法 JSON。**
    （485 行里 20 行坏点 → 整个回测页 500。判空要判**值**，不能只判**行数**）
15. **相对容差能不能表达绝对量化误差？**
    （`tol_rel=1e-4` 判不出腾讯按 100 股取整的成交量，
     23 只被隔离、13 只直接从股票池消失）
16. **诊断脚本的结论是算出来的，还是我写死的？**
    （我自己连续两版诊断脚本：写死「一字板收益更高」而实测更低；
    又因 `np.arange(n)//0` 除零把 63 万行归成一组，输出 −80% / +161% 仍照常打印。
    **有输出的荒谬数字，比没有输出更危险。**)
17. **这一列是逐点算出来的，还是全序列算一个值再广播？**
    （`ivol_series(r, m).iloc[-1]` 把数据末端的 ivol 广播给每一天。
    看代码的**形状**——`.iloc[-1]` / `.mean()` / `.max()` 收尾的赋值，
    在因子里出现一次就是一次前视。**它不崩、不报 nan，只是静悄悄地作弊。**）
18. **泄露测试用的数据，本身有区分度吗？**
    （确定性单调序列的波动率恒为 0，vol20/ivol 全是 1e-17 浮点尘埃，
    「变了」与「没变」在数值上无法区分——**泄露测试跑在退化数据上，等于没跑**。
    前置断言：先证明 fixture 能产生非退化的因子值，再谈测没测出来。）
19. **这个指标的「好」是哪一边？**
    （成本、并列数、错误码下降都是**改善**。
    台账若一律按「数字变大=变好」推导方向，会把 11 条里的 6 条判反——
    包括「年成本 16.91%→0.57%」「HTTP 500→200」。
    **把改善标成退步的台账，比没有台账更有害。**）
20. **测试的 fixture 退化了吗？变异体真的被杀了吗？**
    （本轮两次变异体**存活**：`live_validated` 不看 `source` 存活，因为
    测试没覆盖「weights.json 存在但 source=default」这一档——
    而那恰好就是线上真实情况。写完变异体若全绿，先怀疑测试。）
21. **前端改完在真实浏览器里打开过吗？**
    （新加的 `function fmtNum` 与已有的 `const fmtNum` 重名，
    整个脚本抛 `Identifier already been declared`，页面永远停在「加载…」——
    而 **pytest 全绿**。JS 只有真实浏览器能验。）
22. **你确认的是磁盘上的代码，还是**运行中**的代码？**
    （2026-10-11 19:03。变异测试用 `cp` 改文件又改回来，mtime 与 size 撞上旧
    `__pycache__`，`inspect.signature` 读到 `max_universe_gap=10.0`，
    而 `grep` 读到的文件里明明是 `0.02`。**源码对、运行值错**——
    静态检查（读文件、grep、git diff）全部看不出问题，只有跑起来才暴露。
    症状是「新加的测试莫名其妙失败，而代码看起来完全正确」。
    处置：清 `__pycache__`；并让**默认值本身**被一条测试钉住
    （`test_default_threshold_blocks_real_observed_gap` 正是为此写的，
    别的测试都显式传了自己的阈值，默认值根本没被测到）。
23. **报告里自己写的警告，进裁决逻辑了吗？**
    （2 年终裁报告末尾白纸黑字写着「各候选的可打分股票数不一致（4021/4177/4183/4185），
    **这些候选不在同一批标的上比较**，排名只能作参考」——
    而 `oos_decision` **完全没看它**。会自我警告但照样参与排名的报告，等于没有警告。
    少掉的 164 只恰恰是**换手率数据缺失的那批**（当日末根 turn 缺 62.0%），
    不是随机缺失，是系统性缺失。现已加为第六道闸。）
24. **统计量的判据，真的会触发吗？**
    （缺陷 15：`if sd <= 0` 写了、注释还专门解释了为什么必须这么写，
    但 pandas 的 `std(ddof=1)` 对常数序列返回 `3.5e-18` 而非 0，
    这一支**从未成立过**。注释里写了意图 ≠ 代码实现了意图。
    任何 `== 0` / `<= 0` 的浮点判据都要配一条「构造退化输入，验证它真的返回 None」。
    `scripts/mutation_check.py` 就是干这个的。）
25. **序列的观测单位，是它声称的那个吗？**
    （缺陷 16：K 日调仓把逐日序列当成 K×n 个独立观测。
    问法固定：**「这条序列里，几天是同一个决策？」**
    独立观测数 = 交易日数 / K，不是交易日数。
    `excess_days` 这个字段名从此报的是**块数**。）
26. **候选的身份由哪些字段决定？去重和「谁是谁」用的是同一套吗？**
    （缺陷 17：加入 `rebalance_every` 之后，`r["weights"] == champion_weights`
    会让同权重的月频行**冒名顶替**日频现任。
    去重也只看权重，于是日频与月频被当成同一组——
    同一组权重净值差 **276 个百分点**。
    身份字段变了，去重、认现任、显示**三处**必须同时改。）
27. **新加的参数，老函数会怎么处理它？**
    （静默忽略 = 把月频候选当天频跑，数字与实盘不符却看不出来。
    能力探测后**显式报错**，比「兼容处理」正确。）
28. **这张表里哪一列最该先看？它排在第几位？**
    （缺陷 18：独立验证表最漂亮的结论「净 +114.5%」来自 `n_ranked = 0` 的空股票池，
    而 `n_ranked` 是最后一列。**排最后的列往往正是能不能信的那一列。**）
29. **前端显示的每一列，都是候选身份的一部分吗？**
    （候选池升到 84 组后，判决板表格里同一组权重出现 6 次而看不出区别——
    决定性变量被藏起来了。加那一列时才发现它在藏。）
30. **「按 N 校正」和「检验了 N 个」是同一个 N 吗？**
    （缺陷 19：门槛按 84 组 Bonferroni 校正，被检验的却只有 `table[0]`。
    问法固定：**「我声称校正了多少次比较？我真的做了那么多次吗？」**
    两个数对不上，就说明有一部分比较是纸面上的。）
31. **统计功效是设计出来的，不是许愿来的。**
    （变异测试里「Bonferroni 只按 1 组算」这个变异体**第一次跑就存活**——
    因为那条测试用 `t ~ N(0, 1.5)` 造了 7 个随机候选，
    单个落进 (1.96, 2.75) 窗口的概率只有 9.5%，7 个都没落的概率 **50%**。
    **一半概率才杀得掉的变异体，等于没测。**
    改成全部 `t = 2.2` 的确定性构造后必然区分得开。
    判据：**报变异体存活率**，不要只报「变异体全杀」。）
32. **回测里有的东西，实盘里有没有？**
    （`aplus/rebalance.py` 有频率与缓冲区，`evaluate_weights` 支持这两个参数，
    而 `run_daily.py` 每天 `build_predictions` 从零选——
    **回测能执行任何配置，实盘只能执行一种**。
    问法固定：**「这个参数，实盘路径收到它之后会做什么？」
    答不上来就是执行不了。**）
33. **实测过的最优配置，实盘执行得了吗？**
    （独立验证给的最优是「月频」。日频下它净 −168.9%、月频 +77.6%，方向都反了。

    `live_execution_status` 就是为了让这个不匹配**出现在用户眼前**。）
34. **三处相同的校验，写法一致吗？**
    （`bool` 是 `int` 的子类，`isinstance(True, int)` 为真。
    `save_state`、`ledger._validate` 都写了 `isinstance(x, bool)` 排除，
    新写的 `load_state` 漏了。**最后写的那一处最容易漏**——
    因为写的时候眼睛里只有那个文件。）
35. **僵尸变异体：源码文本变了，效果是 no-op。**
    （变异体「删掉 `is_due` 里的 `if every <= 1` 短路」存活。

    `mutation_check.py` 的 no-op 检查只比对文本，查不出语义上的。
    **变异体存活有两种原因：测试弱，或变异体无效。必须逐个分清**，
    否则「存活率」这个指标本身就没有意义。）
36. **同一屏上，描述同一对象的结论来自同一处判定吗？**

    从没问过健康度那一栏，后端改了它也不会变。
    **硬编码的措辞是静默矛盾的温床。**）
37. **颜色与符号，去量，别按名字推断。**

38. **闸门的输入，是单点还是分布？**

## 3.5 第 20 号缺陷：`n_ranked` 只看窗口第一天（22:15）

```python
result.attrs["n_ranked"] = scoreable_count(cross_sections[use_dates[0]], weights)
```

`n_ranked` 是**第六道闸（股票池可比）的输入**。跑全历史赛马时窗口从
`2019-01-02` 开始——那是数据集的第一天，那天没有任何股票有可计算的
`mom20`（20 日窗口需要 20 个交易日的历史），于是现任权重训练段报 `n_ranked = 0`。

这次**没有造成误判**：闸门读的是测试段的 `n_ranked` = 4805。
但它证明了一件事：**闸门可以拿到一个退化样本，而闸门不会知道**——
它只会安静地拿 0 去和 4805 比，然后报「股票池空了」。

修法：跨 5 个等距日期取**中位数**（`sampled_ranked_count`）。
取中位数而不是平均：平均会被大量不可算的日子系统性拉低，
而中位数仍反映典型的那几天。

**这与第 18 号缺陷同族**：`n_ranked` 都是「能不能排名」的度量，
也都都被放在了没人先看的位置。

### 第 21 号缺陷：「现任只按权重认」的**第三个副本**（22:30）

同一个错误在一天里被犯了三次，每次都在我没看的地方：

| 位置 | 症状 |
|---|---|
| `oos_decision` 认现任 | 月频行冒名顶替日频现任（21:15 已修） |
| `dedupe_candidates` 去重 | 日频与月频被当成同一组，抹掉 276 个百分点（21:40 已修） |
| **`webapp._live_oos`** | **判决板拿 K=63 的成绩去描述日频策略**（22:30） |

第三个副本是**真浏览器截图**抓到的：把 84 组复合赛马报告拷进 `reports/` 后，
绿色框从「样本外显著为负 −0.598%/日 · t −2.83」变成
「样本外**无法区分于 0** · t=—」。

原因是现任权重在 84 组候选里出现 **6 次**（K=1/5/21/63 × 有无缓冲），
`_live_oos` 只按权重匹配，返回表里第一个匹配行——恰好是 K=63 那行。

### 第 22 号缺陷：赛马报告有**两种行布局**，`_live_oos` 只认一种（22:35）

修好频率匹配后，`t` 变成了 `None`：

| 写入方 | 行布局 |
|---|---|
| `evolve_race_fast.py` | `row["test"]["stats"]` |
| `evolve_race_composite.py` | `row["test_stats"]`（顶层扁平） |

`_live_oos` 只读前者，于是对 84 组复合报告**一直返回 t=None**——
那批报告里现任的日频行 t=−7.56。

与 `champion_health.collect_windows` 里记录的「两个报告族用不同键名表示同一个量」
完全同族，只是这里多了一种**布局**而非键名。

**教训**：加了新的报告写入方，就必须让**所有**读报告的地方认得它的形状。
写完新写入方之后要做的第一件事，是**把所有读方跑一遍**——
本项目的读方已经有三个（`champion_health.collect_windows`、`_live_oos`、
以及 `evolve_weekly.build_log_record`），而我只检查了其中一个。

## 3.6 第 22 号缺陷：现任权重的**符号**是反的（2026-10-12 21:45）

### 一句话

平台跑了三周的「现任」`{mom20:1.0, rev5:0.3, vol20:0.5, vsur:0.5}`，
其中 **三个因子的权重符号与它们在 A 股的真实预测方向相反**。
它每天稳定亏 0.54%~0.85%，**不是运气不好，是结构性地买在预测收益最差的一端**。

### 怎么发现的

不是再跑一场赛马。是加了 `aplus/factor_ic.py`——
逐因子信息系数（Spearman），1821 个交易日、8 个因子、4 个前瞻窗口，
跑完 816 秒。它回答的是一个赛马**结构上答不了**的问题：
「这个因子到底有没有预测力」。

意思是**这些因子的极值端是反向的**——买进去就是接盘。

1. **现任没有自动改**。理由：翻转符号就是在同一段数据上做的决定，
   那是数据挖掘。正确路径是 `scripts/ic_guided_race.py`——
   **符号只在训练段定，测试段一根都不碰**，再过七道闸。
2. **前瞻台账里冻结的 6 组候选**，其中 4 组本来就是负 mom20
   （`{mom20:-1.0}` K=1 / K=5缓冲3.0、`{mom20:-0.5, turnratio:-0.5}` K=21 / K=5），
   方向与 IC 结论一致。它们等的是 2026-10-13 起算的前瞻窗口。
3. **日常推荐继续出**，但判决板必须说明原因——
   现在它能说清「为什么这份名单来自一组已知方向反了的权重」，
   而不只是「某组旧权重历史上表现不好」。

- **39.** 任何因子在**建仓之前**先问「它的 IC 是正还是负」。

  「知道旧的错了」和「知道错了 68%」是两个完全不同的知识量。

## 3.7 第 23 号缺陷：前瞻验证**接上定时任务的第一天就崩**（2026-10-12 22:00）

### 一句话

`forward_validate.py` 从未被任何定时任务调用过。接上之后第一次跑就抛异常——
因为第一批候选就是今天注册的，而 `build_cross_sections` 的区间是半开的。

### 崩溃点

    ValueError: build_panel 的窗口是半开区间 [start, end)，
    要求 start < end，收到 start='2026-10-12' end='2026-10-12'

面板起点取的是注册日，而注册当天 `latest` 就等于注册日 → `start == end` → 空区间。

### 为什么它比崩溃本身更值得记

崩溃是**好事**——至少它吵。但它的危险在于**时机**：

    窗口攒够之前，每天崩一次 → 没人盯 stderr
    某天窗口够了，突然开始工作 → 没人知道之前空转了多久

窗口从 2026-10-13 起算，K=63 要 189 个交易日才够判决力。
也就是说**这个缺陷会安静地存在整整 9 个月**，
而它挡住的正是目前唯一干净的晋级路径。

而且 `--status-only` 完全正常（0.9 秒返回）。
**一个只在真实路径上出现的 bug，被一个恰好覆盖了另一条路径的测试放过了。**

### 修法

新增 `aplus/forward.needs_forward_panel(registered_on, latest)`：

## 3.8 一条测不出区别的测试（2026-10-12 22:03）

变异体 `forward_window` 里 `>` 改成 `>=`（窗口起点从「严格晚于注册日」
放宽成「含注册日」）——**测试全绿，变异体存活**。

原因：既有的 `test_forward_window_excludes_the_registration_day`
用 `embargo_days=2`，而隔离带本身就把注册日挤掉了。
于是这条断言在两种实现下**都成立**，它测不出这两者的区别。

修法：补一条 `embargo_days=0` 的判别用例，
此时正确实现首日是 `10-13`，变异体首日是 `10-12`。

**教训：一条测试通过，不代表它测到了它声称在测的东西。**
判别标准只有一个：**把实现改坏，它会不会红**。
`embargo_days=2` 那条测试是真的在测「注册日被排除」吗？
不，它测的是「隔离带 + 排除」这个组合。这两件事被同一个断言盖住了，
其中一件从此没有覆盖。

顺带清掉一处**真冗余**：`dedupe` 里自己抄了一份 `rebalance_every ≥ 1`
校验，而它调用的 `split_weights` 二十行外就有同一份。
删掉重复实现后，那个变异体被判为「无法安放（源串未命中）」——
**不是「测试弱」，是变异体本来就没有效**。
这两种「存活」必须分清，否则会去给死代码补测试。

## 3.9 第 24 号缺陷：`mom20`/`rev5` 绕过了书要求的复牌压缩（2026-10-12 22:20）

### 缺陷本身

`aplus/panel.py` 里 `RESUME_CLAMP = 0.10` 早就存在，
但**只用在了 `vol20` 与 `ivol` 上**：

    ret_clamped = ret_real.clip(-0.10, 0.10)          # ← 只有它俩用
    mom20 = _safe_ratio(adj_close, adj_close.shift(20)) - 1   # ← 原始价比值
    rev5  = -(_safe_ratio(adj_close, adj_close.shift(5)) - 1)  # ← 原始价比值

书 3.1.2 第 2 点要求的是**复牌首日**异常值压缩。
复牌首日没有涨跌停，实测单日 +593.72%，会原样进 20 日窗口。

### 修的过程比结果重要

**第一版实现是全局 `clip(±10%)`，被既有测试当场打红**
（`test_factor_layer_still_keeps_legitimate_limit_up_moves`）：
创业板 +20% 涨停是真实、可交易、有信息的事件，
全局压缩会把它压成 +10%，**系统性削平所有信号**。

压得太宽比不压更糟——它制造的是「看起来正常的假信号」。
正确口径是三层互不替代：

    >±40%      数据不可信 → **作废**（NaN，该股退出横截面）
    复牌首日    合法但任意 → **压到 ±10%**
    普通交易日  真实涨跌停 → **不动**

### 实测影响：可忽略（这条同样重要）

400 只 / 720,587 行：

    复牌日且 |收益| > 10% 的行：**90 行（0.0125%）**，涉及 81 只
    mom20 新旧绝对值之比：中位数 **1.000**、95 分位 **1.000**
    最大 |mom20|：488% → 380%（只有极端尾部动了）

**保留这个修复**（符合书、对正常样本零影响、去掉一类尾部风险），
但**不能把它当成任何问题的答案**。

### 我推错的因果链（已撤回）

    IC 显著为负 → 书要求压缩而代码没压缩 → 「所以 IC 为负是复牌极值造成的」

前两箭头对，**第三箭头是我编的**。负 IC 是真实的短期反转效应。

**教训：「找到一个能解释现象的缺陷」≠「它就是这个现象的原因」。**
两者之间必须有一步实测，否则链条会断在听起来最顺的那一环——
而那一环恰恰是最少被人验证的。

### 一处必须说明的口径差

7.8 年 IC 引导赛马于 **22:12 启动**，本修复于 **22:19** 落地。
Python 在进程启动时导入 `aplus.panel`，**那场赛马跑的是修复前的口径**。
由于实测影响中位数是 1.000，结论不受影响——但这一点必须写明，
不能让下一���看到报告时误以为它是修复后跑的。

### 检查清单（补 1 条）

- **43.** 改了因子构造之后，**先量它到底改变了什么**（新旧比值分布），
  再决定要不要用它去解释之前观测到的现象。

## 3.10 首个过闸候选，以及它为什么没有晋级（2026-10-12 23:35）

### 结果

97 组候选（84 标准 + 13 IC 引导），训练 2019-01-02 ~ 2023-08-17、

    K=63  成本占比 4.3%

差 20 倍。在 5 万本金上，**调仓频率不是执行细节，它就是策略本身**。

### 没有晋级：这一节比结论重要

赛马说晋级，协议允许晋级，`weights.json` 却仍然不存在。理由：

    ① factor_ic_diagnostic 跑的是 2019-01 ~ 2026-10 **全窗口**
    ② 我从结果推断「符号该反过来」
    ③ **于是才去构造 ic_guided 这一族候选**
    ④ 再用 2019-01~2023-08 训练 / 2023-08~2026-10 测试去赛马

权重确实只在训练段上拟合。但**候选族的存在是被全窗口决定的**。

训练/测试切分挡住的是「用测试段挑权重」，挡不住
「我已经知道整个样本期的规律，于是只造了符合这个规律的候选」。

- **有效观测只有 11 个**（测试段 3.9 年 ÷ 63），t=+4.14 建在 11 个块上
- **广度 t=+1.09 不显著** —— 超额几乎全部来自涨腿，

  （涨腿命中率 47.4%，靠幅度赢，不靠频率）

开**第二批**前瞻注册（4 组，含该候选），与第一批共 10 组，

## 3.10 第 25 号缺陷：七道闸里**没有一道看跌腿**（2026-10-14 08:20）

### 一句话

产品承诺是每天「10 涨 10 跌」。晋级链有七道闸，
其中 `excess_t` 测涨腿、股票池闸看覆盖面、方向闸看污染——
**没有任何一道看跌腿**。`breadth_tstat` 早就写好了，
文档里还明确写着它回答「排序两端有没有真实区分度」，
却从来没有接进闸门。工具在，门没装。

### 实测的代价

7.8 年赛马 97 组，逐块分解（`scripts/candidate_block_audit.py`，
测试段 753 日）：

| | K=63（11 块） | K=21（35 块） |
|---|---|---|
| 涨腿 t | **+4.757**，正块 **11/11** | +4.358，正块 27/35 |
| 跌腿（相对大盘）t | −0.865，正块 4/11 | +0.415，正块 19/35 |
| 广度 t | **+1.005** | +2.035 |
| Bonferroni 临界（97 次） | 3.47 | 3.47 |

两个方向都够不到。而现任权重的跌腿更糟：

    现任 {mom20:1.0, rev5:0.3, vol20:0.5, vsur:0.5}
    avg_down_return = +0.126%/日

**它推的「10 只��跌」平均每天在涨。**这不是统计口径问题，
是产品承诺没有兑现，而且判决词对此一言不发。

### 两个预判都被实测推翻（同样要记）

1. **涨腿不是「一两块撑起来的」**。第一版担心 11 个观测太敏感，
   实测 K=63 是 **11/11 块全正**，去掉最好一块 t 反而**升到 5.425**
   （分母变小、标准差同步变小）。这个 t 是实的。
2. **「跌腿接近噪声」只在相对大盘的意义上成立**。跌腿命中率 52.8%，
   而 97/97 组的 `hit_rate_down` 都 > 50%（中位 52.6%）——
   **方向性对所有候选都成立，方差极小**。

### 判据为什么最后选了「绝对下跌」

第一版按「跑输大盘」设闸。**这是错的，要拦的是问错的问题**：

    down_excess_vs_market > 0 的只有 45/97 —— 约等于随机
    按它设闸会否掉 52/97 的典型候选 —— 否掉多数的闸没有判别力

5 万本金做不了空，跌腿对用户的价值是**「这 10 只别买」**，
所以要证的是「这篮子真的会跌」。最终判据：

    avg_down_return < 0

实测这条闸立刻抓得到东西——现任权重就过不了（+0.126%/日）。

### 处置

`oos_decision` 从五闸改为六闸，跌腿闸紧跟在涨腿超额闸之后；
晋级理由同步更新，并**在广度不显著时挂警告**（不否决，
但必须让人看见「本次显著性由涨腿独撑」）。

真实赛马表回放确认：判决结论不变（`{mom20:-1.0}` K=63 仍然六闸全过，
因为它的 `avg_down_return = -0.040%/日`），但**理由里第一次出现了广度警告**。

### 检查清单（补 2 条）

- **45.** 产品承诺里的**每一半**都要有对应的闸。
  「10 涨 10 跌」只给涨腿设闸，等于给半个产品发合格证。
  写闸门时对着产品承诺逐句核一遍：承诺里出现了几个名词，就该有几个闸。
- **46.** 判据必须匹配**用户实际能做的事**。
  做不了空时，「跑输大盘」不是用户需要的证据，「真的会跌」才是。
  设闸前先问：这个指标对应的是收益，还是对应「别买」？

## 3.11 第 26 号缺陷：`turnratio` 因**一天缺失**丢掉 482 只股票（2026-10-14 09:40）

### 一句话

`aplus/panel.py` 算书的 ATURN 时用 `t.rolling(252).mean()`，
`min_periods` 默认等于窗口长度——**252 根里一根都不能缺**。
于是一只上市三年、`turn` 覆盖率 96% 的老股票，中间只缺 1 天，整个因子就变 NaN。

### 实测（2025-03-20 全市场真实横截面）

    真实横截面 4904 只 → turnratio 可打分 4662、剔掉 242

第一次的假设是「剔掉的是次新股，符合书的次新 1 年过滤」，**实测否掉了**：

    242 只的上市交易日数：p50=1506（远超 252）
    其中上市不足 252 日的只有 56 只 = 23.1%
    年龄分布：<60:0  60-119:21  120-179:19  180-251:16  =252:0  253-500:6  **>500:180**

**180 只（74.4%）是上市 500 日以上的��股**。所以「因子的定义属性」这个解释不成立。

继续追一层，直接量 `turn` 列的缺失根数：

    已上市 ≥252 日的股票 5235 只 → 可算 4753、算不出 482
    这 482 只的 turn 覆盖率**中位 96.0%**
        只缺 1 根 122 只 / 缺 2~6 根 85 只 / 缺 7~20 根 122 只 / 缺 >20 根 153 只

**结论：收窄是数据完整性瑕疵，不是方法论分歧。**

### 为什么这条比看上去重要

1. **它一直是股票池闸拦下高 t 候选的理由**。`{mom20:-0.5, turnratio:-0.5}` K=63
   的 t=+5.04 是全池最高，却因为 `n_ranked` 4904→4567 被闸拦下。
   闸拦的是一个**数据瑕疵**，而它自己在注释里把理由写成了方法论问题。
2. **生产环境同样脆弱**：明天再多缺一天，就又少一只股票可打分。
   可用池会随数据源的抖动而无故变化，用户看到的榜单也会跟着变。

### 处置

`MIN_TURN_COVERAGE = 0.9`。理由是**先验的完整性判据**，不是为了让某组候选过闸
而调出来的数：无缺失样本的结果与原实现**逐位相同**（有测试钉死），
所以修复不改变任何已经算出来的数，只把「本来就有 96% 历史」的股票放回来。
短窗口（21 日）保持 pandas 默认——样本本来就小，放宽会真的改变因子值，
而那不是这次要修的东西。

### 纪律上为什么这次不构成「调到过闸为止」

- 前瞻窗口当时**仍是 0 天**（`forward_results.json` 是 `[]`），
  改因子定义**不损失任何已累积证据**
- `{mom20:-0.5, turnratio:-0.5}` 在 **2026-10-12 就已冻结注册**（K=5/21/63 共 4 条），
  不是看到修复后的结果才挑的候选
- 候选数仍是 97，Bonferroni 门槛不变

### 检查清单（补 1 条）

- **47.** 滚动窗口因子的 `min_periods` 默认值是**隐含的严格过滤**。
  pandas 的 `rolling(252).mean()` 要求窗口内一根不缺，而真实数据源有零散缺失——
  于是「96% 完整的历史」被当成「没有历史」。
  每加一个长窗口因子，都要单独量一次：**因子的可得分股票数**，
  以及被剔掉的那些**是因为历史不够长，还是因为中间缺了几根**。
