# 变异台说明：`test_growth_cashflow_arm.mut`

被测生成器：`scripts/measure_growth_cashflow_arm.py`
被测守卫：`tests/test_growth_cashflow_arm.py`

## 这 28 条在验什么

一句话：**每一条都是「这个性质一旦被摘掉，守卫会不会红」**。
变异体全部改在**源码**上（不是产物），所以它们验的是**代码**，
而产物层守卫读的是**上一次落盘**的产物 ⇒ 两者不是一回事（见下）。

| 组 | 条数 | 验的是哪条性质 | 谁杀掉它 |
|---|---|---|---|
| 负控（§5 C1） | M1–M3 | 显著性闸门是 `>=`；「显著为正」与「显著更好」两支都判作废 | 行为层：合成夹具直接问 `nc_state` |
| 交付门槛 | M4–M5 | `gross > D1/D2` 是**严格大于** | 行为层：恰好等于门槛的夹具 |
| 判决链顺序 | M6–M8 | MDE 闸**先判**；显著性线不被放宽；缺 MDE ⇒ **不报数** | 行为层：三个夹具分别落在三支 |
| 腿表（第 137 层） | M9–M11 | `ddof=1`；MDE 年化 `×244/K`；方向不取反 | 行为层：**与 arm R 的 `_leg_table` 逐位对拍** |
| PIT 断言 | M12–M13 | `lag < 0` 是违规；`lag == 0` **不是**违规；不放松到 30 天 | 行为层：合成帧（一条前视、一条当日） |
| 因子定义 | M14–M17 | 分母 ≤ 0 ⇒ 缺失；分子两项不取反；成长率就是厂商那一列；方向与预注册一致 | 行为层 + **预注册层**（拿文档当锚） |
| 逐位对拍本身 | M18–M19 | 字段清单不许漏项；「逐位相等」不许变容差 | 行为层：清单完整性 + `math.nextafter` |
| 族级标签 | M20 | 逐格**分布**，不是取极值 | 行为层：一格 LEVER + 一格 POWERLESS |
| 口径与倍数 | M21–M22 | 判决臂/交付档不许装反；倍数只取**同口径**那一列 | 行为层：`caliber_block()` / `baseline_block()` |
| 读数来源 | M23 | 头条读数来自**原臂**，不是翻号臂 | 行为层：`cell_payload()` 直接问 |
| 措辞 | M24–M25 | 「测不到」不许写成「无效」；负控的三个原始数必须**写出来** | 行为层 + 产物层 |
| 对拍自证 | M26 | 逐位对拍必须**同时**调本轮的腿表与 arm R 的腿表 | **AST 接线守卫**（否则对拍恒真） |
| **量纲**（第 182 层） | M27–M28 | 厂商成长率公式的分母**取绝对值**；产物必须声明它是**百分数** | 产物层：量纲核验块（逐行反算，匹配率 ≥ 0.999） |

## ★ 首轮实测：**26/28**，两条存活 ⇒ 查出来是**守卫漏了夹具**，不是变异体写错

首轮跑完 M2 与 M20 存活（rc=0，43 passed）。按仓内纪律，
**「变异存活」的第一解释是「它落在了没人测的那一格」**，而不是「守卫没用」或「变异体是错的」：

| 变异 | 它落在哪 | 为什么首轮全绿 | 修法 |
|---|---|---|---|
| **M2** 摘掉「负控显著更好 ⇒ 作废」那一支 | `nc_state` 的**第二支** | 我原来的三个夹具里，负控要么**为正**（第一支就触发）⇒ 摘掉第二支照样 VOID ⇒ **第二支从来没有被单独测过** | 补一格：**负控显著但为负**（`nc=−0.02, t=3.0, t_crit=2.0, orig=−0.05`）⇒ `nc_positive=False` ⇒ **只有第二支能判它作废** ⇒ 摘掉第二支 ⇒ 掉回 PASS ⇒ 变红 |
| **M20** 族级标签从 `all` 改成 `any` | `family_state` 的「全 POWERLESS 那一支」 | 该支**只在 `passed == 0` 时才可达**；而我原来那格（一格 LEVER + 一格 POWERLESS）里 `passed == 1` ⇒ 根本走不到那一支 ⇒ `all`→`any` 不可观测 | 补一格：**一格 POWERLESS + 一格 NOT_MEASURED**（`passed == 0`）⇒ 分布**不是**全 POWERLESS ⇒ 族级标签必须是 NOT_MEASURED ⇒ `any` 版本给出 POWERLESS ⇒ 变红 |

⇒ 处置是**补夹具**，**不是**改判据、**不是**把守卫改松
（失败方向最贵的正是「为了让变异变红而改本来正确的守卫」）。
⇒ 补完重跑：**28/28 逐条 `rc=1`**，基线 43 passed 验绿，
生成器**逐位还原**（章里的 `code_file_sha256` 与盘上字节相等）。

## 🚨 这批变异验不到的（明写，不藏）

**产物层守卫读的是上一次落盘的产物** ⇒ 「改了生成器没重跑」它**看不见**
（第 96 层：读快照的守卫等价于没守）。
⇒ 本文件**不假装**覆盖那一层；产物层守卫生效的前提是
**每次改了生成器都重跑并重盖章**（第 125 层的 `expect_bytes` 就是为此存在的）。

`main()` 的**编排层**（哪些块被装进产物、落盘顺序、盖章时点）同样不在行为层覆盖内：
断言它只能去读产物 ⇒ 同一条洞。

## 规格写法的两条硬限制（台子的 docstring 里也有，这里是本文件自己的提醒）

① **单行锚点**：本文件**每一条锚点都写成单行** ⇒ `dedent` 的 `pad` 就是那一行的缩进
⇒ 左移后仍是源码的子串 ⇒ `src.count(old) == 1` 成立。
⚠️ 多行锚点若**没有一行顶格**，`pad` 会取块内最小缩进 ⇒ 后续行被一起左移 ⇒ **0 处命中**
⇒ 而症状是「旧串匹配 0 处」，看起来像「规格写错」而不是「源码变了」。
② **锚点必须结束在行尾**：M21 第一次写成 `…2019-01-02→`（少一个引号）⇒
`old` 的末尾带 `\n` 而源码那一行还没到行尾 ⇒ **0 处命中**。
