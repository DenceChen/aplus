## 0. 前提核实（写明被测的量到底是哪一个）

| 项 | 值 | 来源 / 核实方式 |
|---|---|---|
| 被解释量 `y` | 生产组合的逐日**毛超额**（日频，不含任何成本） | 与 `factor_attribution.json` 同源 |
| 待测暴露 | `expo_logcap` = 持仓股 `log(close × a_shares)` 的**当日池内 z 分均值** | **定义在此处冻结**，不是从书里抄的 |
| 市值口径 | `close × a_shares`，`a_shares = volume×100/turn`，从 `turn_integrity_audit` import | **单一真相源**；不是 `float_shares`（含 B/H 股，系统性高估） |
| 现有 8 个暴露 | `expo_ivol / mom20 / rev5 / rsi / turn20 / turnratio / vol20 / vsur` | `factor_attribution.json` 的 `results.k21.full.factors` |
| **不在现有 8 个里** | **市值** | **这就是做这件事的全部理由** |

★ 三条与既有产物的关系，必须写清，否则又是一次口径混比（第 22 层）：

1. `expo_logcap` 是**第 9 个暴露**，**不是**第 8 个 —— 现有产物的 `n_factors = 8`
   与 Bonferroni 分母 `0.05/8` **都不适用于本实验**（本实验分母是 `0.05/9`，按候选数推导，不写字面量）。
2. 本实验**不改** `factor_attribution.py` 的因子集 —— 那是它自己预注册过的判决口径，
   往里加因子会让它的 `NO_LEVER` 判决**换判据后重跑**（第 91 层）。
3. 市值加权基准实验（`cap_weighted_benchmark.json`）**没有量过这个**：
   它的 `A − B = −8.04pp/年` 量的是**两个基准之间的差**（`B_c − B_e`），
   `C − B = −2.50pp/年` 量的是**给组合换加权方式的效果**（`P_c − P_e`）。
   **两者都不是「组合自身的市值暴露」** —— 那个量至今**一次也没被量过**。

## 1. 问题

**生产组合是不是在偷偷押注市值？现有「毛超额 6.78%/年（C 臂 12.49%/年）」里有多少其实是市值溢价？**

为什么值得问：目前所有关于「这个组合能赚多少」的陈述，都建立在一个
**从没被登记为因子的暴露**之上。要么它小到可以忽略（那么上面的数字是干净的），
要么它大（那么**相当一部分「选股 alpha」其实是「买小盘」**，而小盘溢价
既更难预测也更容易被成本吃掉）。

这是当前**唯一一个能改变结论方向**、而不是只改变置信度的测量。
其余待办（攒前瞻期、降 K、加因子）都不改变「20% 能不能到」这件事本身。

### 1.1 我的主张（读数据之前写死，若与结果相反则加对照臂、不改判据）

**主张**：组合是**系统性地偏小盘**的，因为生产打分器里最强的 `mom20` 与
「近期跌透的中小盘」高度相关，而池子是全市场无市值约束的。

⇒ **若数据支持**：判决 `SIZE_EXPOSURE_CONFIRMED`，并**必须**在头条数字旁
并列报告「剔除市值后的」对照数字。
⇒ **若数据不支持**（方向为大盘或不显著）：这是**反对我主张的读数**，
按规矩**加对照臂**（例如按市值中性化后的池子重测），
**不许**把判据改成「反向显著才算过」。

## 2. 方法（冻结）

与 `factor_attribution.py` **同方法、同自助次数、同分块**，
只多一列解释变量：

1. 逐调仓日取生产组合的持仓股，算 `log(float_cap)`，用**当日全池**的
   均值/sd 标准化，取持仓上的**等权均值** ⇒ `expo_logcap`；
2. 对 `y = 逐日毛超额` 做 OLS：`y ~ Σ_{k=1..9} β_k · expo_k + α`；
3. **野自助**（wild bootstrap）出 `p_i`，**每档 K 各做一次**；
4. 符号一致性要求：**5 档 K（5/10/21/42/63）全部同号**才算过线
   （与 `factor_attribution` 的三处同号同一条纪律，跨 K 是最容易被单窗口骗的那一处）；
5. `R²` **不进判决**（选股就是按因子打分，R² 高是设计的必然结果）。

### 2.1 判据（**全部由外部锚推导，不写字面量**）

| 判据 | 值 | 来源 |
|---|---|---|
| 单因子显著性 `α_family` | `0.05` | 族错误率，与 `factor_attribution` 同 |
| Bonferroni 阈值 | `α_family / 9` | **由候选数 9 推导**；9 = 现有 8 + 本次 1 |
| 符号一致性 | 5 档 K 全同号才计 `passes_bonferroni` | 外部锚：石川/Chan 的多重检验与样本外一致性纪律 |
| 分块临界 `t_crit` | `factor_attribution.T_CRIT_5PCT` | **import，不写字面量 1.96** |
| 检出力下限 | 野自助零分布 95 分位 | 授权「POWERLESS」这个标签，不是手写「n 太小」 |

## 3. 判决（**四态**，**每一条都必须可达**）

> 第 141 层的教训：**在真实数据上不可能满足的分支 = 永远红的守卫。**
> 下面三条都写了「什么数据下走这一条」。

| 判决 | 触发条件（可满足性自查已做） |
|---|---|
| `SIZE_EXPOSURE_CONFIRMED` | `expo_logcap` 在 **≥1 档 K 上过 Bonferroni 且 5 档全同号** ⇒ 组合带着可测的市值暴露。**负号 = 偏小盘**（与主张一致），**正号 = 偏大盘**（与主张相反 ⇒ 走 §1.1 的加对照臂条款） |
| `SIZE_EXPOSURE_OVERFIT` | 有档位过线但**跨 K 符号不一致** ⇒ 不得使用（照抄 `factor_attribution` 的 `OVERFIT` 语义） |
| `SIZE_EXPOSURE_POWERLESS` | **0/5 档过线** 且 **零分布 95 分位 ≥ 实测 \|β\|** ⇒ 这份样本**分不出**这个量级的暴露 |
| `NO_SIZE_EXPOSURE_MEASURED` | **0/5 档过线** 且 **零分布 95 分位 < 实测 \|β\|** ⇒ 分得出来而没分出来 ⇒ 是真的没有 |

★ 最后两态的顺序**刻意写成先 POWERLESS**：因为第 141 层的「断言不可能满足」
在那两态的顺序上出现过一次。**两态都可满足**：
前者要求 `|β_observed| < q95_null`，后者要求 `|β_observed| > q95_null`，
两条互斥且各自都有数据能走。

## 4. `what_this_cannot_prove`（预注册里先写死，不许事后补）

1. **不许把 `POWERLESS` 读成「没有市值暴露」** —— 那是检出力不足，与 `score_ranking_power`
   的 `NOT_PASSED_POWERLESS` 同一个坑（第 122 层的三态语义）。
2. **不许用本实验的数字替换头条毛超额** —— 本实验只测**暴露**，
   不测「剔除市值后还剩多少」；后者需要**市值中性化的池子重跑**，
   那是另一个实验，另行预注册。
3. `expo_logcap` 的正负只说**方向**，不说**大小是否被定价**
   （后者需要对基准池的市值溢价单独测量，`cap_weighted_benchmark` 的 `A − B`
   测的是基准之间的差，不是溢价本身）。
4. 本实验**不复核** `wf_weights_backtest.json` 的 6.78%/年 ——
   那个口径已被 `docs/TODO_cap_weighted_benchmark_2026-10-15.md` **降级**（第 143 层）。

## 补记 1（2026-10-15，**看数据之前**）：标准化口径钉死为 `robust_z`

★ **性质**：这是**读文本时发现的歧义**，不是看到结果之后的修补；
**不改动任何门槛、分支、反证臂**。写在这里是为了让 §2 与 §2.1
指向**同一个东西**，而不是两个读法。

**歧义在哪**：§2 写「与 `factor_attribution.py` **同方法**」，
§2.1 步骤 1 写「用**当日全池**的**均值/sd**标准化」。
后者若照字面实现，就是裸 `(x − x.mean()) / x.std()` ——
那**不是** `factor_attribution` 用的变换。

**钉死为**：`aplus.factor.robust_z`，与那 8 列**逐字同一段代码**。
它的内部是「**缩尾（q01/q99）后的均值/sd**」：

```python
ref = values.clip(q01, q99)          # 只缩尾「尺度」，排名仍用原值
std = ref.std()
return (values - ref.mean()) / std
```

⇒ 「均值/sd」是它的简写，**不是另一个变换**。

**为什么这条值得写死**（不是洁癖）：
| 量 | 对 `x` 缩放不变？ |
|---|---|
| 单列 `t` / `p`（一元 OLS） | ✅ 不变（β 与 SE 同比例变） |
| **联合 `F` / `R²`** | ❌ **不变性不成立** |

⇒ 缩尾与否，单列显著性**可能照样过**，而联合统计**会分家**。
市值是出了名的肥尾分布，缩尾与否差得很远
⇒ 若不钉死，会得到「主判据过、联合量不过」的自相矛盾，且**零告警**。

**对照臂（新增，登记为 §5 的一臂）**：
裸 z-score（不缩尾）作为**对照臂**并**如实报出**，**不得**当主臂。
若两臂对「组合偏大盘」给出相反方向 ⇒ 记进 `what_this_cannot_prove`，
**不改主判据**（第 5 节的纪律：读到相反结论加臂，不改判据）。

**另一个必须钉死的相邻量**：§0 已冻结「流通市值 = `close × a_shares`」，
**不是** `float_shares`（含 B/H 股，系统性高估）。
实现侧对应 `CapTable.cap_on`，**不得**改用 `a_shares_on`
（后者刻意**不**前向填充，跨停牌日会取到不同的票）。
⇒ 守卫要钉住「调的是 `cap_on` 而不是 `a_shares_on`」。

## 补记 2（2026-10-15，**看数据之前**）：§3 是四态不是三态；`n_perm` = `BOOTSTRAP_B`

★ **性质**：同样是**读文本时发现的**两处不一致，**不改动任何阈值、分支或触发条件**。

**1. §3 的标题写「三态」，表里有四行判决。**
按互斥性与穷尽性逐条核过，四条确实**互斥且穷尽**：

| 前提 | 二选一由什么决定 | 落在 |
|---|---|---|
| **任一档过线** | 5 档符号是否全同 | `CONFIRMED` / `OVERFIT` |
| **0/5 档过线** | 零分布 95 分位 与 实测 \|β\| 谁大 | `POWERLESS` / `NO_MEASURED` |

⇒ 该改的是**标题**（三 → 四），**不是砍掉一行**。
⚠️ 砍掉一行会让「有档位过线但符号随 K 变」这个真实存在的情形**无处可归**，
    而那正是 `factor_attribution` 里 `OVERFIT` 语义要管的东西。

**2. §5 写的 `n_perm` 在实现里叫 `BOOTSTRAP_B`。**
野自助（Rademacher）的次数在 `factor_attribution` 里是模块常量 `BOOTSTRAP_B`；
`n_perm` 是**置换检验**的叫法。
⇒ 对照臂条款「把 `n_perm` 提高一档」= **把 `BOOTSTRAP_B` 提到下一档**，
   并报零分布 95 分位的**收敛轨迹**。名字不统一会让这条对照臂**没人执行**。

## 补记 3（2026-10-15，**看数据之前**）：POWERLESS 那一支在 **5 档上逐档判**

★ **性质**：仍是**读文本时发现的**歧义，**不改任何阈值，只把「在几档上成立」写死**。

§3 最后两态写的是「零分布 95 分位 ≥ 实测 \|β\|」，但本实验有 **5 档 K**，
于是「实测 \|β\|」有 5 个、q95 也有 5 个 —— 原文没说是哪一档的。

**钉死为逐档判、且要求在**全部 5 档**上成立**：

```
POWERLESS          ⟺ 对**每一档** K：  q95_null(|β*|) ≥ |β̂_obs|
NO_MEASURED        ⟺ 存在**至少一档** K：q95_null(|β*|) <  |β̂_obs|
```

★ **为什么取「全部 5 档」这个方向**：`POWERLESS` 是一句**关于样本能力**的话
（「这份样本分不出这个量级」），而 `NO_MEASURED` 是一句**关于事实**的话
（「分得出来而没分出来 ⇒ 是真的没有」）。
⇒ 只要**有一档分得出来**，就不许说 `POWERLESS` —— 那会把「我们没测出来」
说成「它不存在」，正是第 122 层三态语义里最贵的那一类误读。
另一方向（任意一档成立就算 POWERLESS）会让 `POWERLESS` 变成**更容易**拿到的标签，
而它的错误方向恰恰是**掩盖真信号**，因此排除。

**逐档报，不合并**：产物里每档都要落 `beta_obs` 与 `q95_null_beta_abs` 两个字段，
判决字段只由上面的全称/存在量词算出 —— 合并成一个数会丢掉「哪一档分得出来」这个
最该被看见的事实。
