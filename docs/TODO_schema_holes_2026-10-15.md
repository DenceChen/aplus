# 整份文件只有 7 列：一条**自我维持**的数据洞（`isST` 全程失明 861 行）

**状态**：✅ **根因已修 + 数据已修 + 守卫已立**（2026-10-15）。
**发现时间**：2026-10-15，由全仓判决分支审计顺带查 `coverage.py` 时的 schema 扫描暴露。
**性质**：**真 bug**（解析层抛异常），不是停牌、不是数据正确、也不是「降级写入本身错」。

## ★ 一句话结论

> **降级写入是症状，不是病因。**
> 真正的病因在 `convert.py`：它对**停牌日的空串**用裸 `astype(float)`，
> 遇 `''` 直接抛 `ValueError` ⇒ 主源「失败」⇒ 流水线降级到腾讯 7 列
> ⇒ **下次重试撞同一个异常** ⇒ 洞**永远补不回来**。

## 1. 现象

| 文件 | 修复前行数 | 缺失列 | 影响 |
|---|---|---|---|
| `000043.SZ` | 221 | `amount/tradestatus/isST/turn/pctChg` | **221 行 `isST` 全程失明**（1994→2019 整段） |
| `300114.SZ` | 640 | 同上 | **640 行 `isST` 全程失明**（2010→2025 整段） |

⇒ 与 2026-10-14 那批（53 只 × **1 天**）相比，形态更重：**861 行的全部历史**。

🚨 **`isST` 空 ⇒ ST 过滤对这 861 行完全无效** —— 一只 ST 票会被当成正常票进入候选池。
`amount` 空只影响成交额口径；**`isST` 空影响「这只票能不能进候选池」**。

## 2. ★ 根因链（逐环实测，不是推断）

```
baostock 对停牌日返回 open/high/low/close/volume/amount/turn/pctChg 全为空串、tradestatus=0
        ↓
convert.py:96  "open": df["open"].astype(float)   ← ValueError: could not convert string to float: ''
        ↓
流水线把它当成「主源坏了」→ 降级到腾讯（只有 7 列 OHLCV）
        ↓
整份文件只剩 7 列；下一次重试撞同一个异常 ⇒ 自我维持
```

**原始样本**（`000043.SZ` 实测，2019-12-16）：

```
        date       code     open   high     low  close    volume      amount  tradestatus  isST   turn  pctChg
2019-12-13  sz.000043  19.9100 20.4900 19.7100 20.2500  7096940 142983766.5000      1     0  1.0643  1.9637
2019-12-16  sz.000043                                        0            0      0     0            ← 停牌
```

### ★ 最刺眼的地方：**同一个函数内部自相矛盾**

```python
volume = df["volume"].replace("", "0")                 # ← 知道空串有意义
amount = df["amount"].replace("", "0")                 # ← 也处理了
out["turn"] = pd.to_numeric(df["turn"], errors="coerce")  # ← 附加列也处理了
"open": df["open"].astype(float)                      # ← 唯独 OHLC 四列漏了
```

⇒ 这不是「忘了空串这回事」，是**同一件事做了三遍、漏了一遍**。
凡是这种「同一语义在同一函数里被处理 N-1 次」的代码，第 N 处几乎必然是漏的。

## 3. ★ 为什么 `repair_tail_cols.py` 修不了它

`find_broken()` 用 `tail_nan_columns(df)`，而该函数对「**列根本不存在**」返回 `[]`
（这是刻意语义：缺列归 `missing_columns` 判，不重复计入尾根 ——
有守卫 `test_coverage_tail_nan.py` 钉着）。

⇒ 这两只对 `repair_tail_cols.py` **完全隐形**。
⇒ 已新写 `scripts/repair_schema_holes.py`，两者职责不重叠：

| 形态 | 谁修 |
|---|---|
| 尾根缺 5 列（部分行） | `repair_tail_cols.py` |
| **整份文件只有 7 列** | **`repair_schema_holes.py`** |
| 正常 | — |

## 4. ★ 修法：停牌日**结转上一收盘价**

⚠️ 三种写法里**只有一种是对的**：

| 写法 | 后果 |
|---|---|
| 写 `0` | 🚨 造出 **−100% 的假跌幅** |
| 写 `NaN` | 🚨 `close.pct_change()` 从该行起**整段断链** |
| **结转上一收盘价** | ✅ 与库里既有停牌行同构 |

**「库里怎么存的」是实测的，不是推断的** —— 400 个文件样本里，
`tradestatus==0 且 volume==0` 的行一律是 `O=H=L=C=` 前收盘：

```
300137.SZ 2024-11-11   5.28  5.28  5.28  5.28   0.0  0.0  0
000416.SZ  2024-04-25   0.45  0.45  0.45  0.45   0.0  0.0  0   （连续 4 天）
```

守卫 `test_the_halt_convention_matches_what_the_real_store_already_holds`
把这条约定钉死 —— 它不是「我以为该结转」，而是「库里 1.5 万条既有行就是这么存的」。

⚠️ **首根就停牌 ⇒ 留 NaN，不编值**：没有「上一根」，且 baostock 的 `_DAILY_FIELDS`
未请求 `preclose`。要用它得改字段列表（牵动全链路）—— **宁可空着**。

## 5. ★ 差点犯的错：**放松交叉验算判据**

修完转换层再跑，**被流水线拦下**（这说明拦写机制有效）：

```
status='quarantined'
reason='cross-check failed: rows a/b=6127/640 common=640 missing_a=0 missing_b=5487'
```

第一反应是「交叉验算太严，放宽它」。🚨 **这是判据变更，必须预注册**，
而且**它根本没必要** —— 仓库里早就有专门给这个场景的模式，
`crosscheck.py:75-76` 的 docstring 原话：

> `coverage="overlap"`：只对交集日期严格比对（长窗口回填场景——备源如腾讯仅有近 640
> 交易日，窗口外的缺失是**能力边界而非数据错误**）

而默认的 `strict` 适用场景写明是「**每日增量，窗口短、双方都应全覆盖**」。

⇒ 用 `overlap` **不是放宽判据，是用它该用的地方**。
⇒ 且证据很硬：`missing_a=0`（主源严格包含备源日期）+ `mismatch_ratio=0.0000`
（640 个共同日价格逐位一致）⇒ 写入更全的历史是**严格改进**。

| 窗口 | baostock | 腾讯 | missing_a | missing_b |
|---|---|---|---|---|
| 全历史 | 6127 | 640 | **0** | 5487 |
| 2019 全年 | 233 | 221 | **0** | 12 |
| 2019-11~12 | 32 | 31 | **0** | 1 |

`missing_a` 恒为 0、`missing_b` 恒为正 ⇒ 备源系统性少行，少掉的正是**停牌日**
（腾讯不返回停牌日，baostock 返回）。
⇒ **触发拦截的条件，正是当初造成这个洞的那个条件。**

## 8. 诚实标注（未验证的部分）

### ★ 8.1 已量化：**这次失明在实际后果上是 0**

上一版这里写着「下游影响未量化」。已补测（用**修好后**的文件反查失明窗口）：

| 代码 | 失明窗口 | 窗口内行数 | 其中 `isST==1`（真 ST） |
|---|---|---|---|
| `000043.SZ` | 1994-09-28 → 2019-12-16 | 6127 | **0** |
| `300114.SZ` | 2010-08-27 → 2025-02-17 | 3511 | **0** |

⇒ **这两只在整个失明期里从来不是 ST。**
⇒ 🚨 **所以那 861 行的「ST 过滤失效」在实际结果上没有造成任何错误候选。**
本次修复的真实收益是 **`isST` / `amount` / `turn` / `pctChg` 四列从「不存在」变成「有值」**，
**不是**「修正了错误的 ST 过滤」。

> 这条必须照实写，因为**它是朝着让我自己显得更蠢的方向**：
> 我一度把这件事写成 P0 级发现，而实测的因果链末端是空的。
> **一个真实存在的缺陷，可以完全没有造成真实的后果** ——
> 缺陷的「严重度」不能由它的**形态**推定（12 列 vs 7 列、861 行的整段失明，
> 听上去都很吓人），只能由**它改没改变过任何一个判决**推定。
>
> ⚠️ **但修复本身仍然是对的**，理由与后果无关：
> ① 触发它的条件（baostock 停牌日空串）**每天都在发生**，下一次落点可以是别的票；
> ② 这次是**运气好**（恰好没撞上 ST 期），而**运气不是判据**；
> ③ `amount` 缺失会独立影响可成交性口径，不经 `isST` 这条路。
