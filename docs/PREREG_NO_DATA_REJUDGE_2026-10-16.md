## §1 三个缺陷（补记）

### 1.1 `pending_prediction_dates` 用 `any` 而非 `all`（**在犯**）

`aplus/reports.py:170`：

```
旧：judged = { pred_date : 该日**至少一行** exit_date 非空 }
```

`no_data` 那天是**部分覆盖**（实测 `pred_date=2026-10-12` 共 20 行，其中 13 行有 `exit_date`、7 行 `no_data`）
⇒ 只要那天**还有别的行判成了**，该日就进 `judged` ⇒ **那 7 条永远不会被重判**。

🚨 与该函数 docstring 自相矛盾：docstring 写「旧行缺这一列 → 视为未判定 → **重开**」
—— **意图是行级，实现是日级**。

### 1.2 `_judge_one_day` 的就绪探针取**单只**股票（**潜伏，不在犯**）

`scripts/run_daily.py:258-262`：

```
probe = _last_two_bars(store, preds["code"].iloc[0], pred_date)
data_date = store.read_daily(probe["code"])["date"].max() if probe else None
if data_date is None or data_date <= pred_date: return False
```

`probe` 为 `None` 时 `data_date` 也是 `None` ⇒ 直接 `return False`。
⇒ **一旦某天排名第 0 的票停牌，那天 20 条推荐永不判定**，日志打的是「次日数据未就绪，留待下次补判」
—— 一句听起来完全正常的话（第 158 层）。

⚠️ **实测它现在没有在犯**：600825.SH 在 `pred_2026-10-10` 名单里排**第 6 位**，不是第 0 位。
⚠️ **本文件不许把它写成已修**。它是潜伏缺陷，修它属于扩大作用域，须单独登记。

## §2 修法候选与被排除的

### 2.1 候选 A（**已否决**）：把 `any` 改成 `all`

```python
fully = ver.assign(_ok=nz).groupby("pred_date")["_ok"].all()
```

已用真实产物 + 两个现有守卫夹具 + 一个正控验过：真实 `pending` 从
`['2026-10-14','2026-10-15']` 变成 `['2026-10-10','2026-10-12','2026-10-14','2026-10-15']`；
现有两条守卫**新旧一致**；正控（旧判据在部分覆盖上返回 `[]`）抓得住。

🚨 **但它会闯祸**：`pred_date=2026-10-10` 含 **600825.SH**，实测
`data/master/daily/600825.SH.parquet` 末日期 = **2026-10-12**，而同日两只对照票
（600241.SH / 601398.SH）末日期 = **2026-10-15**，daily 抽样 40 只中 32 只 = 2026-10-15
⇒ **数据管道是当前的，是这只票停牌** ⇒ 这一天**永远不可能被完整判定**
⇒ 候选 A 会让 **2026-10-10 从此每天被重判一次，永不停歇**。

⚠️ **这就是「看起来对的修法在真实数据上制造无限重试」**（第 112 层反向形态）。

### 2.2 候选 B（**采纳**）：先分辨「该重试」与「该放弃」，再谈重试

**核心分辨**：一条 `no_data` 行是**永久**不可判定，还是**暂时**数据未就绪？

判据只用**库本身**，不依赖任何名单文件：

| 类别 | 判据（全部由程序判定） | 处置 |
|---|---|---|
| **永久** | 库对该股在所需窗口内**一根 bar 都没有**，且**库的全局末日期已越过所需退出日**（⇒ 不是库落后，是这只票没有） | 写 `result='no_data'` 且带**永久标记**，**不再阻塞该日判定** |
| **暂时** | 库的全局末日期**尚未**越过所需退出日 | 留 `no_data` 无标记，**继续阻塞** ⇒ 下轮重判 |

⇒ 修好后的 `judged(day)` 判据变成：
**该日每一行「要么有 `exit_date`，要么带永久标记」**。

⚠️ 为什么不用「读名单数行数」：`tests/test_measurement_window_identity.py:194` 把
`pred_<date>.parquet` 写成**纯文本** `"2026-10-12"`（不是真 parquet）
⇒ 任何打开名单文件的实现都会在现有守卫的夹具上抛异常。

### §5.1 🚨 补记于 2026-10-16（**动手之后**）：变异台 K5 存活 ⇒ §5 那张表里少了一条

首轮变异台 7/8，**K5 存活**（`rc=0 / 14 passed`）。六项合规证据由台子自己验过
（旧串命中 1 处 / `sha256` 真变 / `compile()` 通过 / 基线绿 / 逐位还原 / 落在 `aplus/verify.py`）
⇒ **不是空操作**，是**等价变异体**。

**机制**：`mark_unjudgeable` 的 `if res != "no_data":` 在现有夹具下**冗余** ——
`test_the_writer_marks_only_the_halted_row_of_a_mixed_day` 里 `HIT1` 确实在 `stock_max` 中，
但它的末日期 `2026-10-15` **不早于** `required_entry=2026-10-13`，
于是 `classify_no_data` 的第二道闸替写入端兜住了。而那道闸问的是
「**这只票**有没有买入窗口」，与「**这一行**判没判出结果」无关。

⇒ §5 那六条守卫钉的是「**在这个输入下**只标一行」，
不是「**无论 `stock_max` 里有什么**，只有 `no_data` 行可被标记」。
这是 [[guards-that-pin-existence-not-property]] 的形状：**契约写在 docstring 里，而守卫钉的是某个输入下的结果**。

**补的那一条**：`test_the_writer_never_marks_a_judged_row_however_full_the_date_map_is`
（含**正控**「判别器在该日期组合确实返 `halt`，否则诚实报夹具失效而非安静通过」
与**对照臂**「去掉 `no_data` 行 ⇒ 一条都不标」）。
补后 K5 以 `rc=1 / 1 failed` 被杀，**台子 8/8**，且变红的正是它自己一条、没有连坐。

⚠️ **输入是可达的，不是为造变异硬凑的**：`required_entry = max(所有行的 entry_date)`，
而停牌票的首个 bar 晚于全池会把这个 max 推高；错位一旦超过持有期，
那些**正常判出结果的行**的 `stock_max` 就落在 `required_entry` 之前 ⇒ 判别器对它们返回 `halt`。
后果**不是**改判 `pending_prediction_dates`（那里是 `anchored | settled`，判出结果的行本来就已结清），
而是**产物那一列对已判定的行说假话** —— 而按本仓规矩，产物是唯一证据。

### §7.1 §4 的预测被实测**证伪**

§4 逐字预测：「600825.SH 应当仍是 `no_data` **但带永久标记**」。

**实测**：`verification.parquet` 的 `unjudgeable_reason` 列**全表 100 行皆 NaN**
⇒ **一条永久标记都没写出来**。§4 那句预测的**后半截是错的**。

根因由程序做的反事实闭合（不是推理）：

| 实测量 | 值 |
|---|---|
| `store_max` | `2026-10-15` |
| `required_entry` | `2026-10-12` |
| `required_exit` | `2026-10-13` |
| `stock_max(600825.SH)` | `2026-10-12` |

⇒ 闸 2 的 `str(stock_max) >= str(required_entry)` **取等号成立** ⇒
`classify_no_data` 在**闸 2 就 return `None`**，闸 3 与 `halt` 分支**根本没执行**。
反事实（把闸 2 的比较对象换成 `required_exit`）⇒ 程序立刻返回 `'halt'` ⇒ 因果链闭合。

### §7.2 这是**判据不完整**，不是代码 bug

§3 的 **C4 字面**是「库里该股**全程无 bar**」。
600825.SH **有** bar（`10-08 / 10-09 / 10-12`）⇒ **代码忠实实现了预注册**。
⇒ 缺的不是实现，是 C4 没有覆盖「**有买价、无卖价**」这一格
（`verify.py:161-164`：判一笔交易要 `entry` 与 `entry+1` **两根** bar）。

⇒ 同源问题在代码里已经**被观察到并写在注释里**，但注释下的结论是反的：
`verify.py:54-55` 逐字「`stock_max >= required_entry` 时该行**本就判得出**（会有 `exit_date`）」——
在**等号上**这句为假（有买价、无卖价 ⇒ 不会有 `exit_date`）。
而 `:45-48` 的判决表**两行都写 `stock_max < required_entry`**，
`>=` 那一格**根本不在表里** ⇒ 表读起来完全正常，缺口藏在表外（第 149 层「扫错范围」的形状）。

### §7.3 🚨 修法**翻转**：不改闸 2

我动手前的待办写的是「把闸 2 的比较对象从 `required_entry` 改成 `required_exit`」。
**本节推翻它。**

| | 改后会发生什么 |
|---|---|
| 「暂时停牌」（明天复牌） | `stock_max` 停在 `required_exit` 之前 ⇒ **被判成永久** ⇒ 该行**永久退出**重判 |
| 猜错代价 | 复牌后这一行本可判定，却被永久丢掉 |

⇒ 那是在**乐观方向猜未来**（停牌可能明天就复牌），而
[[aplus-measurement-integrity]] 家族里最贵的错误方向就是乐观方向
（会让人以为「已判决、不必再攒样本」）。

**当前（不改）的代价已量**：每日常数级 —— 全表只有 **1 行** `no_data`
⇒ 1 次 parquet 读 + 20 次 `_last_two_bars`；
且 `append_verification` **幂等**、不污染产物（§3 的 C6 已钉）。
⇒ 代价可接受，收益是「不猜未来」。**不改闸 2。**

### §7.4 候选 B **继承了候选 A 的失败模式**

§2.1 否决候选 A（`any`→`all`）的理由逐字是：
「**2026-10-10 从此每天被重判一次，永不停歇**」。

**候选 B 没有消灭这个失败模式，只是把触发条件挪了位置**：

| | 触发条件 |
|---|---|
| 候选 A（被否决） | 整天**没有可标的行** |
| 候选 B（已实施） | **这一行有买价、没有卖价** |

⇒ 「每天重判永不停歇」在 B 之下**依然成立**，只是每天只有 1 行 ⇒ 从「整天不可判定」
降级成「常数级开销」。**降级不等于消除**，而 §2 的否决理由**一个字都没失效**。
⚠️ §2.2 的判据表逐字「永久 = 库对该股在所需窗口内**一根 bar 都没有**」——
**字面上就不覆盖 600825.SH**（它在窗口内有 3 根 bar）。

### §7.5 预注册（**这条是新的，写在动手之前**）：修 docstring + 补边界守卫

**本文件 §3 的 C1~C7 不动。** 下面两条是**新增**的、写在这一刻：

| 编号 | 判据 | 机械形式 |
|---|---|---|
| **C8** | `classify_no_data` 的 docstring **不得**断言 `stock_max >= required_entry` ⇒ 该行判得出 | 守卫读 docstring 文本，断言它**不含**「本就判得出」这类断言；若保留该分支的说明，必须同时写明**等号边界**的处置 |
| **C9** | `stock_max == required_entry`（**有买价、无卖价**）这一格**必须**有实测覆盖 | 守卫构造 `stock_max == required_entry` 且 `store_max >= required_exit` 的夹具，断言 `classify_no_data(...) is None` **且**断言下游 `pending_prediction_dates` **确实含**该日（正向）＋ 断言 `mark_unjudgeable` **不**写标记（对照臂） |

⚠️ **C9 的对照臂是关键**：只钉「返回 `None`」是**恒真**的（第 112 层）——
现在返回 `None` 正是缺陷的症状。必须成对钉「它返回 `None`」**与**「因此这一行继续阻塞重判」，
否则一条守卫会把**保留缺陷**当成**守住契约**。

⚠️ C8 是**文档守卫**，而本仓已登记的教训是「注释里的引用从不校验」（第 22 层）；
它必须锚在**这段 docstring 本身**（函数对象取 `__doc__`），
不许全文 `grep` —— 否则会被**别处引用同一句话的注释**满足。
