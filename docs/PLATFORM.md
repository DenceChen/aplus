# aplus 量化平台设计简报（v0 → 迭代）

> 用户目标（原话归纳）：本金 5 万，年化目标 20%；每天输出下个交易日「预测涨 10 只 +
> 预测跌 10 只」+ 策略资产配置方案；次日全自动验证对错；Web 页面看结果、可带记忆追问；
> 全部跑在本机，每天定时执行；用户先观察几天再决定是否跟随。
> 模型能力：本机 glm-failover 代理（127.0.0.1:8787，5 账号自动轮循，Anthropic 兼容协议）。

## 0. 数据泄露红线（用户 2026-10-10 深夜立的军规）

1. **新闻情绪永远不进历史回测**：搜索引擎不能时间旅行——给历史日期搜新闻，
   拿到的是当下索引的页面（含事后叙述、后续走势、当前价格），M3 训练数据也含
   后见之明。news_sentiment 只允许两种用途：
   a) 实盘前向覆盖（run_daily 当天真实搜索，预测次一交易日）——已实现
   b) 纸面验证档案的**自然累积**——每日带时间戳落盘的 sentiment 记录，
      N 个月后就是一份真正 point-in-time 的新闻数据集，届时才可回测
2. **价格因子回测只走 as_of 切片路径**（有 no_future_leak 测试钉死），
   任何新因子进回测前必须回答：「这个值在历史日 D 当天真实可得吗？」
   不可得（如复权基准、后修财务、当前搜索结果）→ 禁止入回测。

## 0.5 对目标的诚实前置（必须写给用户看）
- 沪深300 长期年化约 5-8%。**20% 年化是进取型目标**，意味着更高的波动与回撤风险，
  不是「稳定达到」的数字。平台的职责是：用可验证的预测准确率数据，让用户基于证据
  决定敞口大小，而不是承诺收益。
- 因此 v0 全部走**纸上交易（paper trading）**：真预测、真验证、真记账，但不动真钱。
  用户观察命中率与回撤后再决定。

## 1. 模块架构（全部建在 aplus 数据层之上）

```
aplus/
├── factor/     因子计算：动量/反转/波动/换手/量能（纯函数，TDD）
├── predict/    预测引擎：因子合成分 → 全市场排名 → 涨10 + 跌10
├── verify/     验证闭环：次日实涨跌 vs 预测 → 命中率滚动统计
├── alloc/      资产配置：5万本金 → 仓位规则 + 风控线 + 每日配置报告
├── web/        FastAPI + 前端：仪表盘 / 回测追踪 / 带记忆对话
├── chat/       对话记忆：SQLite 会话存储 + LLM 走 glm-failover
└── scripts/run_daily.py   每日编排：增量数据 → 验证昨日 → 预测明日 → 配置 → 报告
```

### 1.1 2026-10-11 新增的六个模块

前六个是包，后面六个是单文件模块：

| 模块 | 职责 | 为什么不能省 |
|---|---|---|
| `panel.py` | 横截面面板（可交易性 + 因子时序） | 全市场排名与回测共用**同一份**面板；对齐两处实现就是两套结论 |
| `snapshot.py` | 单日快照 / 面板窗口边界 | `panel_window_for` 是「单日窗口」那道防线的唯一实现 |
| `rebalance.py` | **回测**里的调仓频率与缓冲区 | 频率与缓冲是两个正交轴，不参数化就没法进赛马 |
| `live_rebalance.py` | **实盘**的跨日持仓状态 | `rebalance.py` 只在回测里被调用；实盘曾每天从零全换 |
| `evolve_race.py` | 样本外赛马 + 七道闸 + 分块 t 检验 | 门槛与被检验对象必须一致（见 `INCIDENTS` 第 19 号） |
| `champion_health.py` | 现任多窗口健康度 + 成本占比 + 跌腿健康度 | 判决板与每日名单用**同一份**判定，不各写一套 |
| `write_lock.py` | 主库写互斥锁 | 四个脚本写同一批 parquet；`O_CREAT\|O_EXCL` 原子拿锁，**不自动判活抢占** |
| `coverage.py` | 日线覆盖度体检 | 「列在不在」和「列有值吗」是两回事——后者漏了整整三周（`INCIDENTS_2026-10-12` 缺陷 23） |
| `factor_ic.py` | 逐因子信息系数 + 权重符号核对 | 赛马**结构上答不了**「因子有没有预测力」——它只能在候选池里排序，而候选池里可能根本没有符号正确的那个组合（缺陷 22） |
| `mutation_check.py` | 变异测试（含崩溃安全还原） | 改动源码的工具被中断后必须能自己回到干净状态——`finally` 挡不住 SIGTERM（2026-10-14 事故） |

`scripts/` 里与本轮相关的入口：

- `factor_ic_diagnostic.py`：1821 日 × 8 因子 × 4 个前瞻窗口的 IC 扫描
- `ic_guided_race.py`：**符号只在训练段定**，测试段一根不碰，再过七道闸
- `candidate_block_audit.py`：过闸候选的**逐块分解**（涨腿 / 跌腿 / 多空价差三腿）——
  低观测数该不该怕，不靠猜，去掉最好一块看 t 还剩多少
- `forward_validate.py`：前瞻验证（换窗口，复用同一套闸）
- `evolve_race_composite.py`：权重 × 频率 × 缓冲的联合赛马（84 组）
- `_verify_freq_block_t.py`：实测分块 t 的虚高倍数（诊断，不做晋级判定）
- `repair_tail_cols.py`：补末根被降级源削掉的五列；**写完逐只复验**，
  连续 15 次 `degraded` 熔断（源站会话已死，继续跑只会白填 OHLCV）
- `mutation_check.py`：变异测试工具（18 个变异体，全杀）

### 1.2 一条贯穿全项目的约定

**回测能执行的配置，实盘未必执行得了。** 每加一个回测参数，
都要回答同一个问题：「实盘路径收到它之后会做什么？」

答不上来就是执行不了——2026-10-11 之前的 `rebalance_every` 就是这样。
现在有两道护栏：

- `live_execution_status(reports_dir)`：线上在执行权重文件声明的配置吗？
- `live_rebalance.is_due(...)`：今天该不该换手？

## 2. v0 预测策略（透明、可回测、无黑盒）

- 股票池：非 ST、上市 > 60 交易日、当日成交、非北交所（数据层限制）
- 因子（全部从自建主库算，收益用「不复权价 × 复权因子」正确计算跨分红）：
  - `mom20`：20 日动量（涨势延续）
  - `rev5`：5 日反转（短期超跌反弹，负向）
  - `vol20`：20 日波动率（低波动优先，负向）
  - `turn_z`：换手率 z-score（异常放量警惕，负向）
- 合成分 = 各因子横截面 z-score 加权（v0 等权，权重可回测调优）
- **预测涨 = 合成分 Top10；预测跌 = Bottom10**。每条预测带因子快照（可解释）。

## 3. 验证闭环（迭代的核心抓手）

- T+1 收盘数据入库后自动判定：预测涨且实际涨 = 命中（含平局判定规则）
- 滚动指标：分方向命中率、预测涨组合平均收益 vs 全市场平均（超额）、连续错判告警
- **所有历史预测与验证结果永久留存**——回测调参、策略迭代的唯一依据

## 4. 资产配置 v0（保守规则型，先保护本金）

- 单票 ≤ 10%（5 千），最多持仓 5 只，权益仓位 ≤ 50%，现金 ≥ 30% 兜底
- 只买「预测涨且分数超阈值」的票；「预测跌」名单 = 回避清单
- 每票硬止损 -8%；组合回撤 -10% 强制降半仓
- 每日输出配置报告：目标持仓、与现持仓的差异、风控状态

## 5. Web 与对话

- 仪表盘：今日预测（含因子理由）、昨日验证结果、滚动命中率曲线、纸上组合净值曲线
- 对话：会话存 SQLite（带记忆、可追问）；系统提示注入平台当日状态（预测/命中率/持仓），
  模型经 glm-failover 调用——5 账号轮循由代理天然完成
- 前端：单页应用，轻依赖，本机访问

## 7.5 路线 A 作战计划：可转债 T+0（2026-10-11 凌晨立项，数据可行性已确认）

背景：日频股票选股的盘中边际（+0.14~0.34%/天）被 T+1 没收（见迭代日志终局发现），
可转债 T+0 是唯一直接保住「20% 目标」的迁移路径。

已确认：腾讯接口覆盖可转债 K 线（sz123xxx/sh11xxxx，实测 2026-10-11）。
关键难点：**债券宇宙是流动的**（实测有摘牌债返回过期数据）——名单必须动态。

工作分解（新会话执行，TDD）：
1. 可转债动态名单源（腾讯快照列表 / 交易所公告页），含摘牌标记
2. 债券日线管线（复用腾讯适配器模式；注意转债无复权、有强赎条款）
3. T+0 日内策略回测器（开盘买/收盘卖合法；h=1 曲线直接可用）
4. 债券特有因子：转股溢价率、剩余规模、双低（价格+溢价）、正股联动
5. 全链路回测 → 若盘中净超额（扣费后）> +0.1%/天 → 进入纸面验证
风险提示：转债流动性差于股票、强赎条款可造成跳空、新债供给变化快——
回测必须含手续费模型与流动性约束（涨停买不进同理：涨停债也存在）

进度（2026-10-11 二阶段收盘）：①②已交付（bond_list/bond_convert/

### 2026-10-11 凌晨 3:40 · 终局发现：真实的边际被 T+1 制度没收（全晚调查链的结论）

调查链：追高 -78% → 反转买方 -47%（改善但为负）→ 收益分段分解发现亏损全在隔夜
跳空、盘中为正 → 扣市场基准与随机对照后盘中超额 +0.29~0.34%/天真实存在 →
**持有期曲线判决**：
- h=1（当日开盘买收盘卖）净超额 +0.142%/天——**A 股 T+1 制度下违法**
- h=2（最短合法）起净超额转负（-0.21%~-0.43%/天），持有越久衰减越深
- 结论：**日频选股的信息边际真实存在，但恰好只存活在制度不允许兑现的那一天**
- 方法论意义：分段分解（隔夜/盘中）+ 随机对照 + 持有期曲线，是「收益归因三件套」，
  全部纯本地计算零成本——这套调查工具本身是今晚最有复用价值的资产

**对 20% 目标的战略含义（待与用户讨论）**：
1. 日频股票多头对 T+1 散户账户是结构性死路（证据链完整）
2. 可行转向：a) 可转债（T+0，baostock 有数据，需数据层扩展）b) 周度以上持有+
   不同因子体系（当前因子在 h≥2 直接反号，需重研究）c) 平台重定位为
   「回避清单+风控闸门+研究工作台」——跌名单 61% 命中与闸门的回撤控制仍是真价值
3. 两周观察期的看点相应调整：纸面验证重点跟踪「跌名单回避准确率」与
   「组合层回撤控制」，而非涨名单收益

### 2026-10-11 凌晨 · 跨周期终审：涨名单被判定不可投资（项目至今最重要数字）

- 2024-01~2026-03（540 日 10800 条）：**组合无闸门 -78.3%（同期市场 +52.5%）**；
  有闸门 -57.6%；涨组合日均超额 **-0.64%**

### 2026-10-11 · 生产事故：复权因子污染制造 903% 假动量（因子从不校验）

**发现方式**：接通纸面账户后重跑每日流水线，预测输出里出现 `mom20=903.72%`——
20 日动量 900% 在物理上不可能。这个数正躺在**每天推给用户的配置方案**里。

**根因**（三层）
1. `BaostockSource.fetch_adjust_factor` 取的是 baostock 的 `adjustFactor` 列。
   该列与 `backAdjustFactor` 多数行相同，但**偶发垃圾值且低一个数量级**：
   实测 `sh.601607` 的 2026-07-17 行 `foreAdjustFactor=0.993812`、
   `backAdjustFactor=10.037703`（正确）、`adjustFactor=1.020971`（垃圾）。
2. `adjust.attach_factor` 把因子表**向前填充**到日线 → 该垃圾因子污染
   2026-07-17 ~ 2026-09-17 **近两个月**的每一根 K 线。
3. `factor.momentum` 用 `close × adjust_factor` 算动量 → 跨污染窗口的
   20 日动量直接放大 10 倍。

**影响面**：5556 只中 **576 只**因子序列非单调；上海医药以 903.72% 动量霸榜
涨名单 Top1 并拿到 5000 元配置额度。原始行情完全正常（真实 mom20 = **+1.46%**），
拓维信息真实 mom20 = -7.40% 却显示 +839%。

**为什么交叉校验层没拦住**：校验层只比对 OHLCV 从不校验因子表——而因子恰恰是
**单源、无第二源、且向前填充**的那个字段。**校验矩阵的盲区比已覆盖的部分更危险**。

**修复**（TDD，4 条新测试钉死）
- 改取 `backAdjustFactor`（与 `to_hfq` 的「不复权价 × 累计因子」语义一致）
- 加单调性防护：后复权因子只增不减，源站偶发倒退伪行（实测 sz.000001 /
  sh.601607 各 1~2 处，用 `foreAdjustFactor` 与前一行相等可判定其非真实除权日）
  一律用 `cummax` 压回前值。**必须 cummax 而非丢行**——丢掉倒退行后其后正常值
  仍可能低于前值，单调性照样被破坏
- `scripts/repair_factors.py`：全量重取（约 40 分钟，串行）。**全量而非只补异常**
  ——污染检测本身不可靠，局部修补只会留下同一 bug 的不同变体

**第二轮：修复暴露出检测器自身的盲区——因子表「残缺」而非「损坏」**

第一轮修完，拓维信息仍是 +839%。查下去发现第二类损坏：本地因子表**只有 1 条
事件**，而源站实有 12 条。`attach_factor` 把首事件之前的日期按 1.0 填充（这个

**关键教训**：单行因子表完全「单调」、无 NaN、值为正——**骗过了第一轮的损坏检测**。

- 修复：`scripts/repair_factors.py --all` 全量重取（不局部修补）
- 补判据：新增**首行必须为 1.0** 的完整性不变量——baostock 必在上市日返回

  （实测 002261.SZ 首值 10.146129 = 最后一期的值，板上钉钉的残缺）
- 「空表」判为**健康**：无除权事件的股票因子恒为 1.0，填 1.0 是正确的

**第三轮：真根因——`attach_factor` 的填充语义（影响面 65.8%）**

前两轮修复后拓维信息仍是 +839.55%，而它的原始未复权动量是 **-7.40%**、因子事件


### 2026-10-11 · 转债 20% 候选的样本外复核：基准选错了，结论仍然成立

上一条记录说「低价轮动测试段 −13.18%，不泛化」。这个结论需要独立复核——**不能

**同构基准**：用完全相同的候选漏斗、相同的费用口径，等权持有当期转债池

「跑赢 22 个点」的错觉。

**正确的口径（EW-POOL 同构基准，h=5/top10/cost=0.003）**

| 段 | 策略 | 基准 | **超额（几何）** | 超额年化 |
|---|---|---|---|---|
| 训练 | +62.90% | +18.64% | **+37.30%** | +23.53% |
| 测试 | −13.13% | −7.60% | **−5.98%** | −5.86% |
| 全窗口 | +49.24% | +13.47% | **+31.52%** | +11.39% |

**但负超额 ≠ 显著跑输。** 费前选券能力测试段 vs 池均值 −0.083%/期，

**无证据支持其样本外 alpha**。这条措辞差别很重要：前者是判决，后者是诚实的未知。

### 2026-10-11 · 差点第二次自欺：`vsur` 的 inf 静默塌掉整日横截面

**发现方式**：改完 evolve_weekly 后实跑，日志里刷出上百条
`RuntimeWarning: invalid value encountered in subtract`（pandas `nanops.nanvar`
的 `(avg - values) ** 2`）。警告本身可以忽略——但它出现的位置不对。

**追查链**（每一步都排除了，而不是猜）
1. 因子表全量扫描（5556 只）：**0 零值 / 0 负值 / 0 非单调** —— 上一轮的因子修复有效
2. 日线扫描：0 个 `close == 0` —— 不是价格问题
3. 把警告升级成异常，抓到准确栈：`factor.py:58 cross_section_z` → `scores.std(ddof=0)`
4. 给 `cross_section_z` 装探针，确认入参确实含 **inf**
5. 逐个因子试：`vsur = volume / 前20日均量`。**停牌股连续 20 日零成交 → 分母为 0**

**实测影响面**：抽样 102 只股票，**6 只**的 `vsur` 出现 inf，其中 `000029.SZ`
有 **429 天**基准量为 0（长期停牌）。约 6% 的样本，远不是边角料。

**为什么这是「静默污染」而非崩溃**：inf 进加权合成分 → `cross_section_z` 的
`std()` 遇 inf 算出 inf/nan → **那一天该因子的整个横截面塌成 0**，排序信号凭空
消失。程序不崩、不报错、测试全绿，只是那一列从此没有区分度。
**这正是复权因子事故的同一种病：数据层坏了，统计层照常出数。**

**修复**：`aplus/panel.py` 引入 `_safe_ratio` —— 分母为 0 → NaN，结果非有限 → NaN。
**除以 0 的比值是「无定义」不是「无穷大」**；NaN 会被下游 `isfinite` 正常剔除，
inf 不会。同一条规则也应用到 `mom20` / `rev5`（零收盘价时同样会除零）。

**测试**（`tests/test_panel.py`，4 条）
- 停牌不得产出 inf
- 分母为 0 必须是 NaN 而非 inf
- **正常路径数值不变**（手工复核 `volume[i]/mean(volume[i-20:i])`，rel=1e-12）——
  防止「修了脏数据顺手改了对的算法」
- 四类真实脏数据（全零成交 / 长期停牌 / 零收盘价 / 交替零量）下五个因子列均无 inf

写测试时我自己犯过一次错：「长期停牌后放量」给了 55 根 K 线的成交量却配 50 根
收盘价，pandas 直接 `All arrays must be of the same length`。**测试夹具自己数据
不一致，报错比静默通过强**——但这也说明夹具得自己盯。

### 2026-10-11 · 根子上的前视：收益窗口从信号日收盘开始算

**发现方式**：核对成交口径时读 `_next_bars`，发现它返回
`close = D+1 收盘`、`prev_close = D 收盘`，于是
`actual_pct = D+1收盘 / D收盘 − 1` —— **收益窗口从 D 收盘开始**。

**为什么这是前视**：信号是用「含 D 收盘」的数据算出来的。D 收盘那一刻因子
还没出来，更不可能在 D 收盘成交。**收益窗口的起点落在信息集之内**，
整整一根 K 线。`aplus/evolve_race.py` 切了训练/测试段、加了隔离带、
把超额硬闸都做齐了，却让整个赛马跑在一个拿不到的收益上。

**它衡量的不是「策略赚不赚钱」，而是「一笔你无法执行的交易赚不赚钱」**——
而 `up_excess_vs_market` 恰恰是决定加不加仓的依据。

**除权日的极端后果**（`tests/test_execution_lag.py` 里钉死）：
收盘序列 D=140，D+1 除权跌到 10.0，D+2 收 11.0
- 旧口径：买 D 的 140、卖 D+1 的 10.0 → **−92.9% 假崩盘**
- 新口径：买 D+1 的 10.0、卖 D+2 的 11.0 → **+10.0% 真实涨幅**

同一天、同一个真实走势，两个口径天壤之别。

**修复**：`ENTRY_LAG = 1` —— D 收盘出信号 → **D+1 收盘买入 → D+2 收盘卖出**。
持有 1 个交易日，且 A 股 T+1 合法（D+1 买 D+1 卖才违法，D+1 买 D+2 卖合法）。
`entry_lag=0` 保留为旧口径，**仅供 A/B，任何判定都不得使用**。

市场基准（`_market_by_day`）走同一个函数、同一个 lag——否则超额就是拿策略的
D+1→D+2 去减市场的 D→D+1，两段不同期，超额没有意义。

**顺带的性能改动**：`df[df["date"] > after].head(1)` 换成 `searchsorted`。
市场基准那条路径要走 667 天 × 150 只 = 10 万次，原来的布尔掩码每次 O(n) 全表扫。
改后**面板从 180 秒降到 67 秒**。

**注意口径边界**：实盘 `run_daily` 的判定仍用「D 收盘 → D+1 收盘」，那是
**预测准确度**指标（明天涨没涨），与「可成交收益」是两回事，不应混为一谈。
两者都诚实，但必须分别命名——本次改的是回测里那份被用来决定交易的。

**教训**：三道护栏（训练/测试切分、隔离带、超额硬闸）全部作用在**正确的
收益口径**之上才有效。口径错了，护栏越多越自信地给出错误答案。

### 2026-10-11 · 差点第二次自欺：「两段双赢」是噪音，多重比较差点放行一次假晋级

**经过**：修好成交前视（上一条）后重跑 2 年赛马，结果**从 0/14 变成 1/14 通过**，
裁决给出「✅ 晋级：两段双赢，训练 +0.920 / 样本外 +0.405」。前视口径的 0/14
反而是错的——D→D+1 窗口被短期反转主导，系统性惩罚动量因子。

**看起来是重大突破。差点就信了。**

**打回的三步**

1. **先看量级**：赢家测试段超额 **+0.0342%/天**，命中率 **50.5%**。仍是抛硬币。
2. **t 检验**：n=266 日，标准差 0.9318%，**t = +0.60，双侧 p = 0.549**。
   Bonferroni（14 次比较）临界 \|t\| = 2.996 —— **差了一个数量级**。
3. **随机对照（决定性）**：抽 30 组同族随机权重，跑**完全相同**的切分与过闸规则：
   - 随机过闸 **1/30（3.3%）**
   - 最好的随机是 **+0.0801%**，比真赢家 +0.0342% **还高**
   - 真实过闸率 1/14 = 7.1% vs 随机 3.3%，**完全无法区分**

**判决：这是噪音。不晋级。**

**教训（比结论值钱）**

原来的三道闸——训练领先 / 超额为正 / 不劣于现任——**在多重比较面前形同虚设**：
候选池里放 14 组，总会有 1 组靠运气过关。这不是闸不严，是闸的**类型**不对：
它们全在判断「比现任强不强」，没有一条在问「**比随机权重强不强**」。
后者才是「可下注的 alpha」的定义。

**修复：给 `oos_decision` 加第四道闸（显著性）**
- 新增 `evolve_race.excess_tstat(res)`：逐日「涨篮子 − 市场基准」序列的 t 值
- 新增 `evolve_race.bonferroni_t(n)`：`n` 次比较下的双侧临界值（正态近似）
- `oos_decision` 现在要求 `test.excess_t ≥ 临界值`，且**候选数变多门槛自动收紧**
- **缺 `excess_t` 的旧记录按不显著处理**——无法证明就不能放行（宁可错杀）
- 两个赛马脚本的 `_evaluate_factory` 统一补上 `excess_t` / `excess_days`

顺带一提：如果只跑 A/B 不跑随机对照，今晚 20:00 就会把这组噪音权重
写进 `weights.json`，成为线上真实配置。**协议里少一条，防线就少一层。**

**产物**：`scripts/execution_lag_ab.py`（成交口径 A/B）、
`scripts/significance_check.py`（t 检验 + 随机对照）、
`data/reports/execution_lag_ab.json`、`data/reports/significance.json`

### 2026-10-11 · 日志系统加固：让「出问题」这件事本身可排查

**起因**：排查上述问题时被日志本身绊了三次——
1. `nohup python x.py > x.log` 后日志**空 8 分钟**（stdout 块缓冲），看着像卡死
2. `RuntimeWarning` 刷了几百行，把真正的异常埋掉
3. 日志里没有 run 概念，凌晨出事无法定位「哪次跑、哪一步炸、多久」

**已有的 `aplus/log.py` 其实早就建好了，却几乎没被用上**——
`data/logs/` 里只有几条事件。healthcheck 第一次跑出来直接是「**0 次运行**」，
这就是诊断结论本身。

**补齐的能力**
- `begin_run(module, **ctx)` → run_id + 总耗时 + 最终状态；异常时记 `run_end(status=error)`
  与 traceback 后**原样抛出**（日志绝不吞业务异常）
- `run.step(name)` → 步骤级起止与耗时
- `configure_noisy_stderr()` → **只压 4 条已知的良性数值警告**，
  其余警告全部放行（有专门测试钉死「压噪音 ≠ 藏错误」）
- `scripts/_bootstrap.py` → 无缓冲（`line_buffering`）+ 噪音隔离 + sys.path，
  长跑脚本 import 一行即可
- **`scripts/healthcheck.py`** → 排查的第一条命令，不该是 `grep`：
  一行回答「跑了吗 / 成没成 / 哪一步 / 多久 / 什么错」

**它立刻立了功**：healthcheck 捞出今天 09:07:36 的一条真实 error——
`因子表损坏 203/5556（3.7%）`。09:08~09:41 的 `repair_factors.py --all`
（全量重取 5447 只，1835 秒）正是为此跑的。**没有这条日志，这就是一个没人知道的问题。**

**顺着这条线又挖出两个真问题**
1. **`repair_factors.py` 只遍历日线代码**，而因子表比日线多 109 只
   （**孤儿因子表**，1.96%）——它们**永远修不了**，却一直被审计算成「损坏」。
   把「没在用」和「数据坏了」混为一谈，会让人为一个不影响结果的问题反复
   重跑 1835 秒的全量修复，真正的问题反而被淹没。
   → 新增 `aplus.adjust.classify_factor_files()`，审计按**可用**因子表算损坏率，
   孤儿单列 info；`repair_factors.py` 纳入孤儿范围并支持 `--codes` 定点修复
2. 定点修掉 6 只残留（非单调 5 + 真残缺 1，`600306.SH` 从 **1 事件补到 7 事件**）

**损坏率：203/5556（3.7%）→ 3/5447（0.06%）**，剩下 3 只是已记录的借壳上市误报。

**测试**：`tests/test_log.py` 11 条（含「只压良性、其余可见」「缺数据不放行」）、
`tests/test_adjust.py` 2 条（孤儿分类）。全量 341 passed。
