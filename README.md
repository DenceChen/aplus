# aplus — A 股免费多源数据层（获取 + 交叉校验 + 容灾）

> 定位：量化交易平台的数据地基。全免费数据源，架构上把「任何单一源都会挂/会错」作为第一假设。
> 方案依据：《中国 A 股量化数据源调研报告》（`../stocks/docs/A股量化数据源调研报告.md`，2026-10-09）

## 一、设计原则（来自调研的三条硬结论）

1. **只落库不复权 OHLCV + 复权因子**。前复权是动态重算的，每次除权全历史漂移，跨源天然对不齐（实测 0.58% 差异）；不复权 + 因子是唯一能跨源严格比对、且永不过期的存储形态。复权在查询时现算（`aplus.adjust`）。
2. **多源容灾是架构假设，不是优化项**。Tushare 2025-08 停运一周、akshare 接口随源站改版失效，都是已发生的事实。任何单源故障时自动降级到下一源，降级事件必须落记录。
3. **交叉校验先于入库**。成交额/成交量跨源应 100% 一致（实测结论）→ 严格比对；不复权价格理论上一致 → 小容差（0.01%）吸收浮点舍入；校验不达标的数据进隔离区（quarantine），绝不污染主库。

## 二、数据源与单位归一（最容易踩的坑）

| 源 | 角色 | 日线 | 成交量单位 | 金额单位 | 频控要点 |
|---|---|---|---|---|---|
| baostock | 主源 | 1990-12-19 起 | **股** | 元 | 日限 5 万次、**禁并发**、超限黑名单 6h 起 |
| 腾讯 ifzq kline | 备源（交叉校验） | 仅近 ~640 交易日 | **手**（×100 归一） | **无 amount 列** | 无 Referer 限制，python 直连稳定（本机实测） |
| tushare（120 积分免费档） | 可选第三源 | 全历史 | 股 | **千元**（×1000 归一） | 50 次/分、8000 次/天，需注册 token |
| akshare（东财源） | 广度补充（本机不可用） | 全历史 | 手（×100 归一） | 元 | 东财 CDN 本机掐 HTTP/1.1 且响应间歇（见已知边界） |

统一 schema：`date, code, open, high, low, close, volume(股), amount(元)`（+ 主源附带的 `tradestatus, isST, turn, pctChg` 等元数据列）。code 统一为 `600000.SH / 000001.SZ / 830001.BJ` 风格，各适配器负责转换。

## 三、架构

```
sources/  源适配层        baostock_source（主）/ tencent_source（备）/ tushare_source（可选）
   │      统一 schema + 单位归一 + code 转换
   ▼
pipeline  容灾流水线      优先级链取数 → 异常自动降级（记录 degraded_from）
   │                      双源都成功 → crosscheck
   ├─ 校验通过 ──────────► store/ 主库（parquet，不复权 + 因子表）
   └─ 校验不达标 ────────► store/ 隔离区（quarantine，带原因）
adjust    复权现算        to_hfq / to_qfq（qfq 基准=窗口末日因子，动态语义显式化）
scripts/  运维入口        bootstrap_history（全市场回填）/ daily_update（每日增量）/ live_smoke（实网验证）
```

## 四、交叉校验规则

**双源比对**（`crosscheck.compare_frames`）：
- 日期覆盖：交集行才比；缺失日期单列报告（可能是停牌/源缺失，需人工看）
- `volume / amount`：相对容差 1e-4——实测应 100% 一致，超差即 mismatch（通常是单位或数据错误）
- `open/high/low/close`：相对容差 1e-4（吸收舍入）
- 不匹配行比例 > 2%（默认阈值）→ 整批隔离

**单源合理性**（`crosscheck.sanity_check`）：
- high ≥ max(open, close)，low ≤ min(open, close)
- 价格、量、额非负
- 违反任何一条即有问题清单

**判定矩阵**：

| 情形 | status | 主库 | 说明 |
|---|---|---|---|
| 主源 OK + 备源 OK + 校验过 | `ok` | ✅ 写入 | 正常路径 |
| 主源挂，备源 OK（仅一个源成功） | `degraded` | ✅ 写入 | 可信度降级，`cross_checked=False` |
| 双源成功但校验不过 | `quarantined` | ❌ 隔离 | 数据有矛盾，宁缺毋滥 |
| 全部源失败 | 抛 `RuntimeError` | — | 上层重试/告警 |

## 七、已知边界（诚实清单）

### 本机环境坑（2026-10-09 实测记录）

- **macOS 系统代理**：本机系统代理指向 127.0.0.1:8118，对国内行情站点不可靠——
  `TencentSource` 显式 `trust_env=False` 直连；其他 requests 场景如遇 ProxyError 同样处理
- **东财 CDN 掐 HTTP/1.1**：push2his.eastmoney.com 在本机网络下对 HTTP/1.1 请求直接断连
  （curl 强制 http1.1 也空响应），对 python TLS 握手不给 h2，且直连响应间歇（时通时断）。
  因此基于 requests 的 akshare 在本机不可用，默认源链不含它
- **腾讯 kline 限制**：仅近 ~640 交易日、无成交额列（交叉校验跳过缺失字段，量价仍严格比对）

### 数据边界

- **复权因子无第二源（最大盲区）**：OHLCV 有双源交叉校验，**复权因子没有**——
  它是单源、无参照、且 `attach_factor` 会向前填充到每一根日线。2026-10-11 实测
  两类损坏：① 取错列导致因子污染（量级差 10 倍，20 日动量被放大到 +903%，该股
  直接进入用户当日配置）；② 因子表残缺（本地 1 条事件、源站实有 12 条，首事件
  之前按 1.0 填充会造出 10 倍假跳空）。**现由 `factor_audit` 每日体检
  （`aplus.adjust.is_factor_corrupt`）+ `scripts/repair_factors.py --all` 兜底**
- baostock 的后复权因子**自身也偶发倒退**（实测 sz.000001 / sh.601607 各 1~2 处，
  用 `foreAdjustFactor` 与前一行相等可判定其非真实除权日）；取数层已用 `cummax`
  压平，但无法根除——源站数据质量问题
- baostock 无北交所、无实时、分钟线仅近 5 年 5 分钟粒度
- baostock 停牌日不输出行情行（tradestatus 字段仅对交易日存在），回测层需用交易日历补齐
- 退市股在免费源可能缺失 → 幸存者偏差（bootstrap 已用 baostock 股票列表含退市股缓解）
- 商用提醒：akshare 数据声明仅学术研究；自建东财爬虫属「低频自用抓无防护公开接口」边界内（调研报告第五节），商业化前重读

### 可转债侧（路线 A）

- **volume 绝对单位无第二源钉死**：东财本机不可用，腾讯转债 kline 的张/手归属
  未经第二源证实（沪深量×收中位 548/506 万同量级，横截面一致故不影响相对比较）
- 摘牌债腾讯返回**生涯末段**过期 K 线（非空）→ 必须靠 `bond_convert.is_active`
  的 as-of 新鲜度过滤；窗口锚点必须用「仍新鲜」的满历史债，按根数锚会把窗口
  拉到 2004-2007 的古代
- 强赎/摘牌造成持仓跳空：纸面账户按**末根收盘**卖出并单独计 `n_liquidated`
  ——现实中这类债可能根本卖不掉
- 纸面账户与回测器共用候选漏斗与费用公式；唯一偏离是费用乘性扣除（二阶小量），
  由 `tests/test_bond_paper.py` 的保真用例逐期钉死

### 样本外结论（务必先读这一段再谈 20%）

- **股票侧**：2 年赛马 14 组候选，**0 组**测试段对市场超额为正。叠加 A 股 **T+1**
  的制度性阻断（当日买入不能当日卖），因子路线的边际已被制度没收。
- **成交口径**：收益窗口原先从**信号日收盘**开始算（窗口起点落在信息集内 =
  一根 K 线的前视）。修成 `ENTRY_LAG=1`（D 收盘出信号 → D+1 收盘买 → D+2 收盘卖，
  T+1 合法）后过闸数从 0/14 变成 1/14——**前视不是在美化结果，是在掩盖信号**。
  但那 1 组经检验是噪音，见下条。
- **显著性**：那 1 组的测试段超额 +0.0342%/日，**t = +0.60，p = 0.549**；
  **30 组随机权重对照里也有 1 组过同一道闸**，且最好的随机（+0.0801%）比它还高。
  真实过闸率 7.1% vs 随机 3.3%，**完全无法区分**。
- **转债侧**：低价轮动全窗口年化 +17.07%，但那**全部来自训练段**。用同构基准
  （等权持有当期转债池 EW-POOL）复核后——

  | 段 | 策略 | 基准 | 超额 |
  |---|---|---|---|
  | 训练 | +62.90% | +18.64% | **+37.30%** |
  | 测试 | −13.13% | −7.60% | **−5.98%** |

  但测试段选券能力 **t = −0.23（n=51），与 0 不可区分**。所以准确说法是
  **样本外 alpha 归零**，不是「崩盘」，也不是「彻底失效」——**统计功效不足，
  只能说无证据支持**。详见 `aplus/bond_excess.py` 与 `data/reports/bond_excess_analysis.json`。
- **基准选择的坑**：曾用 `600000.SH`（一只银行股）当转债市场基准，它测试段
  −29.85%，而转债宇宙同期只跌 −7.60%。**拿单只股票的 beta 当转债基准会凭空
  造出「跑赢 22 个点」的错觉。**

### 防泄露的工程手段（不只是自觉）

`oos_decision` 现在有**四道闸**，缺一条就可能自欺：

1. **训练段赢**——排名只看训练段（训练/测试切分 + 5 日隔离带）
2. **超额为正**——测试段对市场超额 ≤ 0 一律否决。目标函数含命中率，
   「贴大盘 + 命中率略高」会赢下目标分却毫无 alpha，对绝对收益目标只是 beta
3. **样本外不劣于现任**——训练赢、测试垮 = 过拟合特征
4. **统计显著**（2026-10-11 增补）——测试段超额的 t 值须超过 Bonferroni 临界值，
   且**候选数变多门槛自动收紧**。缺 `excess_t` 字段的旧记录按不显著处理：
   无法证明就不能放行。

> 第 4 条是血的教训：前三道闸在多重比较面前形同虚设——候选池里放 14 组，
> 总会有 1 组靠运气过关。**闸的类型不对，全在问「比现任强不强」，
> 没有一条在问「比随机权重强不强」。**

- 防泄露测试要做**变异测试**：注入真实泄露后断言必须失败。`test_bond_excess.py`
  注入全窗口标准化泄露后 3 个用例全红（9 passed → 3 passed）——不这么验就发现
  不了「断言静默失效」
