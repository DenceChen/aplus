# 概览页可读性改版（2026-10-21）

> ⚠️ **本篇只改呈现层**。所有读数来自 API 与产物 ⇒ UI 只负责**呈现**。
> 本轮**没有改任何数字**，也没有改任何口径逻辑。

## 一、读者与问题

一个用**自己 5 万块**做 A 股的普通人，每天开一次页面，只问三件事：

1. **今天看哪 10 只？**
2. **我手上这 5 只要不要动？**
3. **离年化 20% 还差多远？**

改版前的实测（1440×900，Chromium 155）：

| 量 | 实测 |
|---|---|
| 判决板高度 | **521px**（视口 900px 的 58%） |
| 第一屏能看到的名单行数 | **0** |
| 名单第一行出现在 | y = **820px**（首屏之外） |
| 「今天该动吗」（持仓降级预警）在 | y = **5015px**（第 6 屏） |
| 概览 tab 总高 | **5831px** |
| 目标进度 tab 总高 | **11234px** |

⇒ **进门先读三段「不能」，行动在第 6 屏。** 这是本轮要改的那件事。

## 二、布局概念：**「先给动作，再给证据」**

不是仪表盘（KPI 卡片行 + 图表 + 表格），是**晨报**：线性顺序，先结论后依据。

```
┌───────────────────────────────────────────────────────────────┐
│ aplus  纸面验证·不动真钱                     ● 上次已跑 10-20 │
├───────────────────────────────────────────────────────────────┤
│ 还不能下结论         命中率要攒够 10 个独立成交窗口…           │ 判决（压缩）
│ ┌────────────────┐ ┌────────────────┐                         │
│ │ 理想档 12.62%  │ │ 实盘档 +10.42% │  ← 两档并排，各带标签   │
│ │ 缺口 7.38pp    │ │ 缺口 9.5755pp  │                         │
│ └────────────────┘ └────────────────┘                         │
│ 还差 1.79×（同口径） · 来源 …                                  │
├───────────────────────────────────────────────────────────────┤
│ 概览 目标进度 历史·对比 回测 进化 转债纸面 追问 日志            │
├───────────────────────────────────────────────────────────────┤
│ ① 今日名单（看什么）  看涨 10 只 │ 看跌 10 只                  │
├───────────────────────────────────────────────────────────────┤
│ ② ★ 今天该动吗（该动吗）                                        │
│    减仓 0   观察 5   持有 0   未定（测不出）0                  │
│    001309.SZ 德明利 [观察] …                                   │
├───────────────────────────────────────────────────────────────┤
│ ③ 你现在持有 10 只 · 每 21 个交易日换仓 · 还有 N 天             │
├───────────────────────────────────────────────────────────────┤
│ ④ 依据：调仓清单 / 5 万买得起吗 / 判决配置 vs 实盘配置            │
└───────────────────────────────────────────────────────────────┘
```

**重排只动 DOM 顺序，不新增任何数据副本。**
理由：本仓第 97 层「两份副本之间没有守卫」—— 若在判决板里再读一次
`/api/holdings-alert` 的计数字段，就是第三份副本，与那一块自己的渲染
没有自动对账。⇒ 本轮**只重排 + 只改排版**。

## 三、颜色（沿用，**锁死语义**，不新增色相）

| 角色 | hex | 语义（不许越界） |
|---|---|---|
| 底 | `#0E1319` | — |
| 卡面 | `#141A23` | — |
| 正文 | `#E7EBF0` | 主要读数 |
| 支撑 | `#8D97A6` | 次要读数 |
| 口径 | `#7C8695` | 口径标签/来源（**下限**，≥4.7:1） |
| 金 `--seal` | `#C8963E` | **目标 / 判决 / 需要你看一眼** |
| 红 `--up` | `#F04A4F` | 价格正；「买得起吗」块里 = **买不起**（自带一句说明） |
| 绿 `--down` | `#1FB981` | 价格负 |
| 灰 `--void` | `#727E8C` | 无值 / **测不出** |

**纪律**：金 = 目标；红绿 = 价格方向；灰 = 测不出。
「不可判定」**不许**渲染成红色（第 16 层：「测不出」≠「没有」）。

## 四、字体

| 角色 | 族 | 理由 |
|---|---|---|
| 正文 / 表格 | `--sans`（PingFang SC / HarmonyOS Sans SC） | |
| **公司名 + L1 大读数** | `--serif`（Noto Serif SC / Songti SC） | 密排表格里的汉字，衬线笔画有粗细变化，比黑体更容易分辨（黑体 13px 汉字会糊成一团）。**这一条只对中文成立** |
| 代码 / 来源路径 | `--mono` | |

### 中文排版修正（**不是照搬西文**）

| 项 | 值 | 理由 |
|---|---|---|
| 中文正文行高 | **1.75**（表格行 1.5） | 西文 1.5 就够；中文方块字需要更多行距 |
| 中文正文字距 | **.02em** | 中文**加**字距才透气；西文那种负字距会把汉字挤在一起 |
| 数字 | 一律 `tabular-nums` | 不许同一栏里数字左右跳 |
| 断行 | 短字段 `nowrap`；长散文给 `min-width` 后照常折行 | **中文不许被压成逐字竖排** |
| 标点 | 中文引号/括号**不**手动挤压（`palt` 只在纯数字标签上开，不全局） | 全局 `palt` 会让「（」贴住前面的汉字，误读成别的词 |

## 五、字号阶梯（4 档 + 1 个例外）

| 档 | px | 用途 | 硬约束 |
|---|---|---|---|
| L1 主读数 | 26–30 | 今天要看的那个数（榜单股票名、D2 主读数、持仓计数） | 每块**最多一个** |
| L2 读数 | 16–22 | 缺口、涨跌%、综合分 | |
| L3 正文 | 12.5–14 | 说明、判据、标签 | |
| L4 口径 / 来源 | **11（硬下限）** | 口径标签、出处路径 | **不许承载需要比较的数**；对比度 ≥4.5:1 |
| 例外 | 10–10.5 | 只允许出现在 mono 的来源路径里 | 不许承载读数 |

## 六、原则（5 条，每条说清「怎么更好读」）

1. **「一屏之内先答三问」** —— 重排 + 压缩判决板，让「看什么 / 该动吗 / 离目标多远」
   在一屏内出现。 ⇒ 用户不必先读完三段「不能」才知道该干嘛。
2. **「一个数只有一个主角」** —— 每块只允许一个 L1，其余降级 ⇒ 扫视有落点，
   不会处处都想读。
3. **「口径标签双通道」** —— 理想档 / 实盘档用**文字 + 颜色 + 位置**三重区分
   （不只靠颜色）⇒ 色觉障碍与黑白打印仍可分辨。
4. **「诚实边界安静但不藏」** —— 用左边线 + 缩进表达，不上底色不加框 ⇒
   看得见，但不喧宾夺主。
5. **「不许内容被静默裁掉」** —— 窄屏下要么放得下，要么**可横滚**，
   **不许**被 `overflow:hidden` 裁掉后无法到达。

## 七、大招（一处）：**「今天该动吗」条**

「持仓降级预警」从第 4 块提到名单正下方，四个状态计数从「四个圆角 chip」
改成**一行四个读数**（账簿科目式：科目名在上、数字在下，科目之间一根竖线 ——
复用本页转债 KPI 那一套，不新发明样式）。

**「未定（测不出）」必须读成「测不出」** ⇒ 它带括号注解，且用中性灰
（`--void`），不是绿色（绿色会被读成「查过了，没问题」）。

它是全页**唯一**一处「金色左边线 + 大计数」的组合 ⇒ 与判决板同色
（都是「今天要处理的事」），但只有这一处。其余保持安静。

## 第 2 步 · 审计划：改了哪五处

| # | 一眼就是生成物的默认选择 | 换成了什么 | 为什么 |
|---|---|---|---|
| 1 | **通用仪表盘布局**（KPI 卡片行 + 图表 + 表格） | **线性顺序：先给动作，再给证据** | 读者不是分析师，是**每天要拿主意的人**。仪表盘让人「看指标」，线性顺序让人「拿决定」。而且仪表盘要求 4 个 KPI 等宽排列 —— 而本页那四个数（命中率 / 涨篮子超额 / 跌篮子超额 / 多空价差）**互不同口径**（合并 vs 单腿 vs 需空头腿），排成一行会**暗示它们可比**。⇒ 保留它们现在的「小读数带」形态，不升格。 |
| 2 | 把「今天该动吗」做成**需要点开**的交互组件（tab / 折叠） | **常驻可见的一行读数** | 折叠 = 需要动作的东西被藏起来，而本页的失败模式正是「没看到」。 |
| 3 | **新加一个「今日概览」组件**（重新组装一次数据） | **拒绝** | 第 97 层：两份副本之间没有守卫。我若在判决板里再读一次 `/api/holdings-alert` 的计数，就是第三份副本。⇒ 只重排 + 只改排版，不新增数据副本。 |
| 4 | 用 `text-overflow: ellipsis` 把宽表**截断**塞进窄屏 | **可横滚** | 被截掉的那一列是「1 手要 ¥202,070」—— 这一块的**全部结论**。而 `title` 悬停对触屏与键盘都不可达（第 96 层同族）。宽表横滚是本仓 e2e 明确认可的形态：「横向溢出本身不是罪，罪的是整个页面被撑出横向滚动条」。 |
| 5 | serif 只用在**标题** | 公司名 + L1 大读数也用 serif | 中文衬线在 13–14px 密排表格里笔画分明，黑体小字汉字容易糊。**这一条只对中文成立**，西文正文仍然全 sans。 |
| 6 | 用**一个 L1 大字**（比如「年化 10.42%」）当全页的视觉重心 | **重音给「今天该动吗」那一行四态读数** | 本页的判决已经说了「还不能下结论」⇒ 数字再大也只是「不能」。而「减 0 · 观察 5」是**唯一一个能让人今天做点什么**的读数 ⇒ 重音应该落在**行动**上，不是落在**判决**上。（判决板的判决色是既有的记忆点，本轮不抢它的戏。） |
| 7 | 把「0 只要减仓」用**警告色**画出来（红 = 危险） | 零计数**变暗**，非零才上状态色 | 「减仓 0」涂红 = 全块最扎眼的东西说的是「**没有**要减的」⇒ 把没事画成有事。这正是本页要消灭的失败模式（「不可判定」不许长得像「没变差」）。 |

### ★ 浏览器级那份为什么在 `tests/e2e/`

本仓 e2e harness 的 **session 级** playwright 会话用完之后，
**主线程上会留下一个「正在运行」的 asyncio 循环**
（playwright 的同步 API 用 greenlet 驱动事件循环，
`run_until_complete` 在 greenlet 切换点被中断 ⇒ 那个循环一直处于 running 状态）。

⇒ 后果：**同一进程里再开第二个 `sync_playwright()` 会被 playwright 自己拒绝**
（`Error: It looks like you using Playwright Sync API inside the asyncio loop`）。

⇒ 所以浏览器级守卫必须**复用** `tests/e2e/conftest.py` 的 `browser` / `live_server`
夹具（**同一份 session 级实例**），而不是自己再开一个。
放在 `tests/` 下的文件**看不到** `tests/e2e/conftest.py` 的夹具 ⇒ 自己开 ⇒ 撞上残留循环
⇒ 实测整批 14 条 **ERROR**（不是 FAILED）。

⇒ 这条是**实测出来的**，不是推理：一个探针插件在每个 e2e 用例之后检查
`asyncio.get_running_loop()`，第一处命中就是 `tests/e2e/test_chart_touch.py`。
